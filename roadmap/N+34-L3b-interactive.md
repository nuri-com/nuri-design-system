## The EFFECT set & the SoT shape (the sub-decision · surfaced)

The rule set, exactly the hand `interactive.css` (all on `.nuri-interactive` · the merged-node class):

| effect | selector (after `.nuri-interactive`) | declaration(s) | gate |
|---|---|---|---|
| affordance | (none) | `cursor: pointer` · `transition: background-color var(--nuri-duration-fast) ease, transform …` | automatic |
| focus | `:focus-visible` | `outline: 2px solid var(--nuri-focus-ring)` · `outline-offset: 2px` | automatic |
| pressScale | `[data-press-scale]:active` | `transform: scale(var(--nuri-interaction-press-scale))` | `data-press-scale` |
| disabledGuard | `[aria-disabled="true"]:active` | `transform: none` | automatic (reverts the scale) |
| disabledOpacity | `:disabled, [aria-disabled="true"]` | `opacity: var(--nuri-interaction-disabled-opacity)` | automatic |

**The SoT-vs-shell line** (the brief's named sub-decision · the analogue of palette's "SoT shape"): interactive is the **THINNEST axis** — mostly fixed STRUCTURE (5 rules) + a few token REFS. So the SoT carries the rule content **VERBATIM**: each decl is a literal `[prop, value]` pair, with the `var(--nuri-…)` interaction constants written **inline as strings**. There is **NO value transform** (unlike palette's role-NAME → `var(--nuri-<role>)`, or dimensions' `{ ref }` → `var(--nuri-px-N)`) — the interaction constants are consumed DIRECTLY ([decision 45](../decisionlog.md) · the TabBar precedent), and the shorthands MIX literal + ref in one value (`2px solid var(--nuri-focus-ring)`), so a `ref | literal` split would not fit. The **only "derivation" the emitter does is the SELECTOR ASSEMBLY** (`.nuri-interactive` + the attr gate + the pseudo-state + comma-join) — the inverse-spelling of `flattenPart`'s gate logic. So the SoT = the whole rule set; **the emitter is a structural serializer, not a value transformer**. (`SelectorPart` models the gate as an `attr` string `[data-press-scale]`/`[aria-disabled="true"]` and the pseudo as a `state` string `:active`/`:focus-visible`/`:disabled`; `disabledOpacity` carries two `on` parts — the comma list.)

## THE LOAD-BEARING ORDER (the centerpiece · the brief §5)

`transform` is set by BOTH `pressScale` (`[data-press-scale]:active`) AND `disabledGuard` (`[aria-disabled="true"]:active`) at **EQUAL specificity (0,3,0)**. A node that is `[data-press-scale][aria-disabled="true"]:active` (a disabled, press-scale control being pressed) matches BOTH, so the cascade resolves `transform` by **SOURCE ORDER**. The hand emits pressScale BEFORE disabledGuard so `transform: none` wins → **a disabled control never scales**. This is the L3.1 Guard-D order-sensitivity gap, here **LIVE, not latent** (palette had no equal-specificity same-property pair, so its Guard A structural ≡ was a complete proof; interactive's is **necessary but not sufficient** — the order guard closes the gap).

## The five guards (the L3.1 / palette pattern · the brief §5)

- **A · STRUCTURAL ≡ + the merged-node model** — generated and hand carry the same `@layer rules` (same selector set · same declaration set per selector · order-insensitive · comments excepted) AND every selector is the `.nuri-interactive` CLASS dispatch (the class PREFIX, since not every selector has a `[` — affordance is the bare class, focus is a pseudo-class). **NECESSARY, NOT sufficient** (the transform pair · see Guard D). One delta from palette: `declSig` **whitespace-normalizes** values (the hand `transition` wraps across two indented lines · CSS inter-token whitespace is insignificant · sound here — no string-literal values).
- **B · RE-EMIT FRESHNESS** — the committed `build/css-preview/interactive.css` == the emitter's current output (transfers verbatim).
- **C · RESOLVED-VALUE** — **simpler than palette** (the brief): the `--nuri-interaction-*` / `--nuri-duration-fast` refs are `:root` constants (no accent×theme cascade), so the L3.1 `buildVarMap` keep-the-last-decl is FINE (no colour-cascade walk needed — that was palette-specific). Two tests: (1) **bottoms-out** — every embedded var ref resolves to a non-var final value (the refs live INSIDE compound values — `transition`, `outline`, `scale()` — so they are EXTRACTED via a global regex, **the one structural delta from palette's pure-`var(--x)` paints**); (2) **oracle** — the scope-INVARIANT constants resolve to a RESTATED design value (`duration-fast → 120ms` · `press-scale → 0.97` · `disabled-opacity → 0.4`), each tied to the generated decl that references it. `focus-ring` is scope-dependent (light/dark) → only its bottoms-out-at-a-hex is asserted here (the exact value is the browser check's job · the palette scope-dependent posture).
- **D · ORDER-SOUNDNESS** (the centerpiece) — palette's Guard D (rest mutual-exclusivity + pressed strictly-more-specific) does NOT transfer (the transform pair is EQUAL specificity → order is genuinely load-bearing). Two legs, both structural: **(a)** for EVERY property set by >1 selector, the generated SOURCE ORDER of those selectors == the hand oracle's (so the array-order emit reproduces the hand's load-bearing precedence — `transform`: pressScale before disabledGuard; `opacity`: the comma list in order); **(b)** the transform pair specifically — exactly two rules, `scale()` FIRST + `none` SECOND (none wins by source order), both selectors **equal-specificity** (so order, not specificity, decides → the order IS load-bearing) and both co-match a `[data-press-scale][aria-disabled="true"]:active` node (the conflict is real).

(Guard C is two `test()` calls — bottoms-out + oracle — so the suite reports **5** interactive guards.)

## Judgment calls / sub-decisions (surfaced · operator-confirm if load-bearing)

- **The SoT shape** (above · the brief's named sub-decision) — `{ name, on: SelectorPart[], decls }`, `SelectorPart = { attr?, state? }`, decls as raw `[prop, value]` strings. The thinnest-axis choice: the SoT carries the rules verbatim (no value transform) because interactive's "derivation" is purely selector assembly. The multi-selector `disabledOpacity` falls out of `on` being a list; the gates (`[data-press-scale]`) and pseudo-states (`:active`) are modelled as the literal selector fragments (faithful · the emitter is the inverse of `flattenPart`).
- **The order-guard approach = BOTH** (the brief's named sub-decision · "assert-order vs computed-style cell · do at least one") — the **node order guard** (Guard D · the CI gate · airtight by CSS-cascade semantics: equal specificity + co-match + source order) AND the **browser computed-style cell** (the gold standard · the ★ order cell). The node guard is the gate (no browser in CI); the browser is the session-time confirmation.
- **The browser `:active` proxy** (a surfaced device) — getComputedStyle cannot synthesise `:active`/`:focus-visible` (no JS holds `:active`). So for those cells BOTH gen and hand CSS are rewritten by the SAME pure substitution `:active → [data-x-active]`, `:focus-visible → [data-x-focus]`. **Faithful for the order claim**: the substitution is (1) identical on gen and hand, (2) **specificity-preserving** (a pseudo-class and an attribute selector contribute equally → the pair stays equal-specificity (0,3,0)), (3) source-order-preserving (pure text edit) → the cascade resolution of `transform` is IDENTICAL to the real `:active` case. The native pass anchors the disabled/affordance effects on the EXACT generated bytes (zero rewrite). A transition-settle wait (250ms > the 120ms `transition`) lets the just-changed `transform` reach its TARGET before measuring (else mid-interpolation reads `matrix(1,…)`) — zero CSS mutation.
- **Harness helpers = COPIED, not extracted** — `layerRuleMap` + `declSig` duplicated from `palette-css.test.js`/`css-preview.test.js` (the conservative, reversible shadow choice · the L3.1/palette files stay untouched). Extraction to a shared helper is an L3c cleanup (when the namespace harnesses consolidate), deferred. NEW helpers (`orderedDecls`, `propSelectorOrder`, `specificityB`) are interactive-local (the order guard needs source order + specificity · palette did not).
- **`interactive-effects.ts` homing = in-`pipeline/`** — beside `palette-surface.ts`/`dimensions.ts`/`colours.ts` (the SoT-in-`pipeline/` convention · relocated at the carve · the [decision 68](../decisionlog.md) `rn → spec` DAG).
