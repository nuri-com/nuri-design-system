## (1) The interaction micro-SoT — generate-from-SoT (the preferred path, ratified)

`{ pressScale: 0.97, disabledOpacity: 0.4 }` are the decision-45 cross-component design constants. Until now they had
**no TS home** — they were hand-authored in `styles/tokens-primitive.css` (`--nuri-interaction-*`) and
`build/interaction.ts` was emitted by *reading the CSS back out*. That is a TS-absent → CSS → TS round-trip — the same
class N+59/N+60 killed for the colour and dimension arms. N+60 deliberately **STOPPED** here and surfaced it rather
than invent a SoT mid-slice.

The new SoT is **[`packages/spec/pipeline/interaction.ts`](../packages/spec/pipeline/interaction.ts)** — pure data,
type-strippable like `dimensions.ts` / `typography.ts`:

```ts
export const interaction = {
  pressScale: 0.97,
  disabledOpacity: 0.4,
} as const;
```

The brief offered two paths for the web CSS: **generate the `--nuri-interaction-*` block from the SoT** (true single
source), or leave the CSS hand-authored + add a drift guard `SoT ≡ CSS` (defer the CSS generation to 3c). The two lines
are **not web-entangled** — downstream consumers reference them only through `var(--nuri-interaction-*)` aliases, which
don't change — so the **generate-from-SoT path was taken** (and coordinator-ratified). After this, `0.97`/`0.4` live in
**exactly one place**.

[`scripts/parsers/interaction.js`](../scripts/parsers/interaction.js) now owns the family end-to-end from the SoT:

- `loadInteraction(tsPath)` — strip-imports the `.ts` SoT (the `loadTypography`/`loadDimensions` posture · node 20
  cannot import a `.ts`).
- `flipInteractionCss({ primitivePath, interaction })` — postcss in-place rewrite of the `--nuri-interaction-*`
  declarations from the SoT (the [`type-css.js`](../scripts/parsers/type-css.js) posture · verbatim everything else),
  with a **bidirectional drift guard**: the SoT must own exactly the `--nuri-interaction-*` leaves the CSS declares.
- `buildInteraction(interaction)` — validates + stringifies the SoT into the `{ leaf → literal }` record the emit
  consumes (`String(0.97) === '0.97'` · no CSS read).
- `emitInteractionTs(interaction)` — `build/interaction.ts` unchanged in body; only its **Source** header line now
  points at the SoT.

[`scripts/tokens-parser.js`](../scripts/tokens-parser.js): a new **Slice 0** interaction flip (alongside the
dimension/colour/type flips) writes the CSS before the primitive read; **Slice 3** now does
`buildInteraction(interactionSoT)` instead of `buildInteraction(primitiveMap)`. **One source, two readers** (the web
CSS primitives + the RN `build/interaction.ts` · the icon model · [decision 48](../decisionlog.md)); the RN factory's
`INTERACTION_BASELINE` reads `build/interaction.ts` unchanged.

## (2) The type-re-home — the real fix for the 3a schema seam

[`packages/spec/pipeline/descriptors/schema.ts`](../packages/spec/pipeline/descriptors/schema.ts) previously imported
its scale-derived contract types from `../../build/tokens`:

```ts
import type { TypeSize, Accent } from '../../build/tokens';
export type SizeLeaf = keyof typeof import('../../build/tokens').size;
```

This is the **3a seam (i)**: the schema's *emit* rewrote the import to `../tokens`, but the **source** still reached
cross-tree into `build/`. Once `build/tokens.ts` relocates to `@nuri/rn` (3b·2b·ii), `@nuri/spec` cannot import from
there — it would be a cycle. So the types are **re-homed onto the SoTs**:

```ts
export type SizeLeaf = keyof typeof import('../dimensions').size;
export type Accent   = keyof typeof import('../colours').accent;
export type TypeSize = keyof typeof import('../typography').type;
```

`keyof typeof import(...)` is type-only — no runtime import. The derived unions are **identical** to the old
`build/tokens` ones (`Accent = neutral | lilac | orange`; `TypeSize = xs | sm | md | lg | xl | 3xl`;
`SizeLeaf = xs | sm | md | lg | xl | 2xl | 3xl`); `npm run typecheck -w @nuri/rn` (which imports
`@nuri/spec/descriptors/schema`) passing at 0 confirms it. **`schema.ts` now imports nothing from `build/`** — spec has
zero `build/` dependency.

`build/tokens.ts` keeps its own `Accent`/`Theme`/`TypeSize` exports — rn still consumes them, and they relocate **with**
the tokens in 3b·2b·ii. This slice only changes where *schema* gets its types.
