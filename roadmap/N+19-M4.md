## The jest/Metro simplification — ATTEMPTED, workarounds RETAINED (the non-trivial part)

M4's premise (65.5/65.9) was that removing `@nuri/spec`'s type-only RN pins would collapse the tree to a single `react@19.1.0` + `react-native@0.81.5`, letting the M2 jest `moduleNameMapper` / Metro `resolveRequest` / `modulePathIgnorePatterns` be removed. **The premise did not hold, and the why is the finding:**

- **Conservative re-dedupe does NOT collapse the tree.** After removing the pins, `npm install` still leaves `react@19.2.6` + `react-native@0.80.3` hoisted at the root — now **orphaned** (nothing declares them), but the Expo ecosystem's `react@"*"` / `react-native@"*"` floating peers dedupe against them, so npm sees no reason to prune them. `react-test-renderer@19.1.0` hoists to root and binds the root's 19.2.6; jest-expo binds the root's 0.80.3.
- **VERIFIED the workaround is still needed.** With the pins gone, removing the jest `moduleNameMapper` reproduces `Invariant Violation: __fbBatchedBridgeConfig is not set` (jest-expo's 0.81-shaped native mock against the root's RN 0.80.3). Kept, the render-smoke is **27/27** and `expo --web` renders.
- **So the workarounds are RETAINED**, with their comments **repointed**: the "type-only pins @nuri/spec declares for the button-matrix migration test" rationale (now false) → "orphaned root hoists npm's conservative re-dedupe won't prune."
- **Two clean collapses exist as FUTURE options — neither taken** (out of M4's CI-only scope · the conservative tree is green · don't-force-it):
  - **(a) a from-scratch lockfile regen** *does* collapse to a single `19.1.0`/`0.81.5` — proving nothing genuinely needs the old versions — but it reshuffled the tree and broke `jest-expo`'s transitive `lodash` resolution in-environment (a missing/misplaced direct dep), so it is **rejected** as a CI lockfile (`npm ci` would reproduce the breakage).
  - **(b) the M2-rejected global dedupe `override` is now UNBLOCKED.** Its rejection reason ([65.9](../decisionlog.md): "the migration tsc REQUIRES the root's RN 0.80.3") is **void** with the migration tsc gone. Available if the dual-version tree ever becomes a real cost.
