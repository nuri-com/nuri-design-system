**Status**: shipped on `feat/n29-b1-descriptor-ts-sot` ([decision 69](../decisionlog.md) · Phase B · the first §9 step). The three frozen descriptors (composition-button / icon-avatar / topbar) stop being CSS-derived and become **hand-authored TS source** at `packages/spec/pipeline/descriptors/*.ts` (the SoT, beside the already-authored `schema.ts`); `build/descriptors/*` stays **byte-identical** (provenance header only); the CSS-derivation is repurposed from PRODUCER to **parity oracle**. No CSS generated (that's B2), no token inverted (decision 63 ring-fenced), no descriptor DATA changed (faithful inversion).
**Type**: **§9 step 1** — the first reversal of [decision 2](../decisionlog.md) (CSS is SoT), for the **descriptor layer only**. **REVERSIBLE by design** (the CSS is retained as the live parity oracle · two agreeing sources · irreversibility lands at B2's CSS deletion). **NON-VISUAL** (pipeline / emit / guards · no rendered surface · the proof is the gates, especially the `@nuri/rn` render-smoke). Coordinator-reviewed + approved (the load-bearing claims independently verified).

## The inversion — provenance flipped, data unchanged

| layer | before (decision 2) | after (decision 69 · B1) |
|---|---|---|
| **descriptor (Layer A)** | CSS + page → `deriveDescriptor` → `build/descriptors/*` | **`pipeline/descriptors/*.ts` (authored SoT)** → passthrough → `build/descriptors/*` |
| **token vocab (Layer B)** | `styles/tokens-*.css` (CSS SoT) | **UNCHANGED** — CSS SoT, ring-fenced (decision 63 · → B2) |
| **CSS's new role** | the producer | the **parity oracle** (Guard D · still renders web) |

The descriptor now has **two agreeing sources** — the authored TS (the producer) and the hand CSS (the oracle) — which is exactly what makes the irreversible-feeling move both *provably faithful* (byte-identity) and *reversible in practice* (revert loses nothing) until B2 deletes the CSS.

## Judgment calls (coordinator-endorsed)

- **`emitDescriptorJs(ir)` removed** as dead post-inversion (the brief said keep it · P11 wins). `emitDescriptorTs(ir)` retained as the oracle's renderer.
- **`descriptorBody` anchors on the line-start `import type … from './schema';` statement**, not a bare `indexOf('import type')` — the authored headers mention the phrase, which a naive `indexOf` would slice on (caught during the first build: a malformed twin · fixed).
- **Slice 9 / Guard G read the SoT via the browser-ESM `.js` twin** (node 20 has no `.ts` import · consistent with the codebase's string-based `.ts` handling) — so `deriveDescriptor` survives *solely* as the oracle, and the doc-gen no longer reads CSS.

## Scope reconciliation

The original `package-migration.md` B1 row read *"author the descriptor registry **+ the token vocabulary** in TS."* This session deliberately **descoped the token vocabulary** (it touches the decision-63 #4b/#6b cascade) — B1 is the audited **Layer-A** scope (descriptors only). The token-vocabulary inversion moved to **B2**, where the CSS is generated (you cannot have tokens-as-TS-SoT while `tokens-*.css` is still hand-authored — that's two sources; it is naturally coupled to CSS generation).
