# N+50 · A6 — the web factory (`defineNuriComponent`) + R1.5 defaults-in-data

> Branch `feat/n50-web-factory` · base `main` @ `4b3127d` · realizes the [§65](../decisionlog.md)/65.5
> generic-factory model on the web + closes R1.5 with data · **no new decision** (§65 + §50 + §74 cover it).

## The one-liner

Adding a merged-node component = adding **data in spec**, nothing hand-written. The web side had the
render engine (`buildComponent`) but no generic custom-element factory — each recipe hand-wrote ~80 lines
of `HTMLElement` boilerplate. RN solved this once (`createNuriComponent`); the web never got its twin.
This session built it, collapsed the 2 recipes to one-line registrations, moved the per-axis default (the
R1.5 gap) into the descriptor so **both** factories read it, and committed the factory harness (the
no-harness gap open since [N+38](./N+38-L3c-flip.md), when the factory became the sole live web renderer).

## What shipped

1. **R1.5 → the descriptor** ([`schema.ts`](../packages/spec/pipeline/descriptors/schema.ts)) — a *versioned*
   post-freeze envelope add (Guard F `FROZEN_SCHEMA.Descriptor` pin updated · [§65](../decisionlog.md) step 5):
   - `defaults?: Partial<Record<string, string>>` — the per-axis PUBLIC default. Authored on the two
     descriptors: `composition-button {variant:'soft', size:'md'}` · `icon-avatar {variant:'soft'}`.
   - `decorative?: boolean` — the [decision 50](../decisionlog.md) a11y flag (`icon-avatar: true`). Honest
     descriptor DATA the web factory reads, instead of a hand `aria-hidden` at the binding.

2. **Both factories read `defaults`** (the open question · operator-confirmed at the checkpoint):
   - web `buildComponent` fallback + RN `createNuriComponent`'s `defaultByAxis` both became
     `descriptor.defaults?.[axis] ?? Object.keys(variants[axis])[0]`.
   - This corrects RN's **latent default bug** from data: RN's `defaultByAxis` used the axis's order-first
     value, so a propless `<Button>` defaulted to `solid`/`sm`; the descriptor's public default is `soft`/`md`.
     The web↔RN parity gap the recipes patched at the binding is CLOSED — the honest 1:1 parity bar
     ([RISKS R1](../docs/RISKS.md)).
   - **RN snapshot delta = ZERO.** The brief hypothesized "the snapshot updates by exactly that default,"
     but every RN smoke test passes explicit `variant`/`size`, so `defaultByAxis` is never exercised — the
     fix lands in the code path with no snapshot churn. Cleaner than expected; the blast-radius concern was moot.

3. **`defineNuriComponent(descriptor, tagName)`** ([`factory.js`](../packages/prototype/factory/factory.js)) —
   the web twin of `createNuriComponent`, over `buildComponent` + a custom element:
   - `observedAttributes` DERIVED: the axis names ∪ `accent` ∪ `disabled` (iff the root is interactive) ∪
     `name` (iff the primary part is an `icon` leaf). Nothing component-specific enumerated.
   - a generic `HTMLElement` whose `connectedCallback`/`attributeChangedCallback` read attrs → selection +
     props, call `buildComponent`, `replaceChildren`; captures the text label for a `text` primary BEFORE the
     tree replaces it; sets `aria-hidden` from `descriptor.decorative`; passes ONLY the set attributes (an
     unset axis resolves from `descriptor.defaults` in `buildComponent` — no default hand-passed).
   - **One factory, zero per-component code** — the structural twin of the RN factory's API derivation.

4. **The 2 recipes COLLAPSED** ([`button.js`](../packages/prototype/recipes/button.js) ·
   [`icon-avatar.js`](../packages/prototype/recipes/icon-avatar.js)) — the hand `HTMLElement` classes
   DELETED (−130 lines); each is now `import { defineNuriComponent }` + the descriptor + the primitive
   self-imports the built tree upgrades into + one `defineNuriComponent(descriptor, 'nuri-…')` line.

5. **The factory harness COMMITTED** ([`factory.test.js`](../packages/prototype/factory/factory.test.js) ·
   jsdom · 7 tests) — the factory's first teeth (it has been the SOLE live web renderer since N+38 with no
   committed test). Renders Button + IconAvatar through the REAL recipes under jsdom and asserts:
   - the de-collapsed `nuri-*` tree (static `nuri-view` IS the merged node · interactive `nuri-pressable` >
     inner `button.nuri-interactive`), the namespace classes + `data-*`;
   - the **defaults-from-data** (the R1.5 assertion: variant→soft not solid · size→md not sm · the heart of
     the slice), label/glyph routing, disabled reflection, decorative aria-hidden;
   - a synthetic descriptor proving genericity: a NEW merged-node component = a descriptor + one
     `defineNuriComponent` line (its tone axis defaults to the *second* value, proving the default is read
     from data not order).
   - `jsdom@^20.0.3` added as a conservative non-RN prototype devDep (already in-tree via
     `jest-environment-jsdom` · lockfile **+1/−0** · RN tree untouched); the test glob extended to
     `pipeline/*.test.js factory/*.test.js`.

## Topbar is OUT (named, not first-bump-buried)

`topbar.js` stays the hand `apply-NS-to-host` path. The factory's open-view render model can't place
positional slots (leading / content / trailing) and the schema can't encode them — that is a real **model
extension**, not a factory refactor. It is reassessed in a **separate coordinator brainstorm** (its
pre-migration slot design predates the axes model). `buildComponent` was NOT extended for slots here.
