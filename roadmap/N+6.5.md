**Status**: closed (2026-05-29)
**Type**: main sequence (the first stateful standalone control +

## Outcome

Three cohesive deliverables land in one arc, each unlocking the
next:

1. **Box gains `background` + `radius` props**
   ([`lib/components/box/box.css`](../lib/components/box/box.css)) —
   attribute-dispatch surface vocabulary under
   [decision 42](../decisionlog.md#42-box-gains-background--radius-props--attribute-dispatch-surface-vocabulary--evidence-gated-promotion--n65).
   `background` is a 5-value enum (`canvas` / `subtle` / `strong` /
   `accent-solid` / `accent-subtle`); `radius` is a 4-value enum
   (`sm` / `md` / `lg` / `full`). Both dispatch via
   `.nuri-box[data-background="…"]` / `[data-radius="…"]` selectors in
   `@layer rules` — the `@layer tokens` block stays **empty** (Box is
   still a layout primitive · no component-token aliasing · the
   [decision 37](../decisionlog.md#37-layout-primitives-consume-semantic-vocabulary-via-prop--no-component-token-aliasing--n62)
   pattern). This **closes the N+6.2 evidence-gated Open question**:
   the surface props were deferred until a real consumer needed a
   filled, rounded container — Tabs is that consumer.

2. **Tabs** ([`lib/components/tabs/`](../lib/components/tabs/)) ships
   as the compound `<nuri-tabs value>` + `<nuri-tab value disabled>` —
   the **first multi-element component with shared state** and the
   **first Box-composition consumer**
   ([decision 43](../decisionlog.md#43-tabs--first-multi-element-compound--first-box-composition-consumer--n65)).
   The controller owns the selected `value` as a DOM attribute; each
   option reads it to decide its active styling. The tablist surface
   is a composed `<nuri-box background="strong" radius="md"
   padding="xs">` — the literal evidence that drove decision 42.

3. **Switch** ([`lib/components/switch/`](../lib/components/switch/))
   ships as the standalone `<nuri-switch checked disabled accent>` —
   the **first stateful standalone control** and a **parametric
   pill** that, unlike the layout primitives, **owns
   component-tokens**
   ([decision 44](../decisionlog.md#44-switch--standalone-parametric-pill--owns-component-tokens--button-roleswitch-not-checkbox--n65)).
   A 60×36 track with a 28×28 knob that slides on `aria-checked`.
   Built on `<button role="switch" aria-checked>` — **deliberately
   not** `<input type="checkbox">`.

A new semantic token **`--nuri-bg-inverse-muted`** (chrome family ·
neutral-11) lands to back the Switch OFF track — auto-discovered by
the classify-by-cascade pipeline (semantic count 36 → 37).

**F-ICON-RN-1 was deliberately sidestepped a second session running.**
None of the three deliverables consumes Icon, so the Icon RN renderer

## Decisions locked

- **[Decision 42](../decisionlog.md#42-box-gains-background--radius-props--attribute-dispatch-surface-vocabulary--evidence-gated-promotion--n65) ·
  Box `background` + `radius` · attribute-dispatch · evidence-gated
  promotion.** 5-value `background` + 4-value `radius` enums dispatched
  by `[data-background]` / `[data-radius]` selectors in `@layer rules`;
  `@layer tokens` stays empty (still a layout primitive · no
  aliasing). `accent-solid` is the one coupled case — it sets both
  `background: var(--nuri-accent-solid)` **and** `color:
  var(--nuri-accent-on-solid)` so text on the filled surface stays
  legible. Anti-scope: **no `max-width`** (still evidence-gated · the
  N+6.2 Open question's *other* half stays open), no `border`, no
  `box-shadow`, no per-corner radius, no component-token.

- **[Decision 43](../decisionlog.md#43-tabs--first-multi-element-compound--first-box-composition-consumer--n65) ·
  Tabs · first multi-element compound · first Box-composition
  consumer.** One directory, one IIFE defining **both** custom
  elements. Shared state lives in a **DOM attribute** (the controller's
  `value`), read by each option — no shadow DOM, no framework. The
  tablist surface is a composed `<nuri-box background="strong"
  radius="md" padding="xs">`; each option reuses the Button `sm` look
  (the active tab gets the `solid` fill). Pipeline: **only the exact
  `--nuri-tabs-` prefix emits** (the single `gap` → `space.2xs`); the
  per-option `--nuri-tab-` tokens are web-CSS-only by design (RN
  renders the option shape from the same semantic vocabulary on its
  own side). A11y: roving **baseline** only (Tab-key focus + click/
  Enter activation); arrow-key roving deferred (`F-KEYBOARD-NAV-1`).
  Anti-scope: no `outline`/`ghost` Tab variant, no tab panels, no
  arrow-key roving.

- **[Decision 44](../decisionlog.md#44-switch--standalone-parametric-pill--owns-component-tokens--button-roleswitch-not-checkbox--n65) ·
  Switch · standalone parametric pill · owns component-tokens ·
  `<button role="switch">` not checkbox.** Unlike the layout
  primitives, Switch **declares its own `--nuri-switch-*` component
  tokens** (geometry · colour · interaction) on the
  `:root, [data-accent], [data-theme]` scope-re-resolution block
  ([decision 9](../decisionlog.md#9-component-token-selector-pattern--n1)).
  The derived **knob-travel** stays in `@layer rules` as a `calc()`
  over other tokens — it is *not* a token-surface alias, so it must
  not be emitted (the pipeline reads the exact prefix; the docs Tokens
  dictionary filters it out explicitly). A11y: a native `<button
  role="switch" aria-checked>` carries the toggle semantics —
  **deliberately not** `<input type="checkbox">` (the checkbox role
  isn't the toggle role, and the styling fight isn't worth it ·
  `F-CHECKED-STATE-1`). Anti-scope: no checkbox input, no size variant,
  no new accent variant, no label slot.

## Frictions surfaced

- **Switch token dictionary leaked the derived `knob-travel` +
  `--nuri-switch-inset` typed `unknown`.** `lib/docs/tokens.js`'s
  `parseSemantics` walks **all** flat rules including `@layer rules`,
  so the derived `--nuri-switch-knob-travel` calc (declared on
  `.nuri-switch`) appeared in the dictionary with no resolvable
  reference, and `-inset` matched no `TYPE_PREFIXES` entry → `unknown`
  + a parse warning. Fixed two ways: (a) added `-inset$` → `dimension`
  to `TYPE_PREFIXES`; (b) tightened the switch.html dictionary filter
  to exclude `--nuri-switch-knob-travel` (a derived calc, not a
  token-surface alias). Verified via live DOM: 9 token rows, knob-travel
  excluded, inset typed `dimension`. Note: `preview_console_logs`
  returned a **stale persistent buffer** of the old warnings even after
  the fix — the live DOM inspection was authoritative and confirmed
  clean. Lesson: when the doc parser walks `@layer rules`, any derived
  calc var on a component class needs an explicit dictionary exclusion.

- **Both new pages injected literal `<tags>` from the `lead`
  attribute.** `lib/docs/shell.js` injects `nuri-page`'s `lead` via an
  innerHTML template literal, so literal `<input type=checkbox>` /
  `<button>` (switch lead) and `<nuri-tabs>`/`<nuri-tab>`/`<nuri-box>`
  (tabs lead) were parsed as **real elements** — a stray checkbox/
  button actually rendered inside the switch lead. Fixed by rewording
  both leads to avoid angle brackets ("a native button with
  role=switch / aria-checked", "a nuri-tabs controller wraps a set of
  nuri-tab options"). Re-screenshotted both — clean. Lesson: the
  `lead` attribute is an HTML sink, not a text sink; never put a code
  span with angle brackets in it.

## Why Switch + Tabs now (sequence position)

N+6.2 shipped the layout primitives (Stack + Box) but left Box's
surface props (`background`/`radius`/`max-width`) as an evidence-gated
Open question — promote them only when a real consumer needs a filled,
rounded container. Tabs is exactly that consumer: its tablist is a
composed `<nuri-box background="strong" radius="md" padding="xs">`, so
landing Tabs and the Box surface props in one arc is what *clears* the
gate (decision 42) rather than promoting on speculation.

Switch and Tabs together push the Behavioural-delta template past its
N+6.4 comfort zone. Button + IconButton proved the template at n=2 for
**transient** interactions (`F-PRESSED-1`/`F-FOCUS-1`/`F-DISABLED-1`).
Switch is the first control whose *primary* delta is a **persisted
boolean** (`F-CHECKED-STATE-1`); Tabs is the first with **shared
selection state across sibling elements** (`F-SELECTED-VALUE-1`) plus a
deferred focus-management delta (`F-KEYBOARD-NAV-1`). At n=4 the
template now spans transient, stateful, and compound surfaces — a
broader generalisation claim than n=2 could support.

Deferring the Icon RN renderer a second time is deliberate: Switch and
Tabs are both **non-Icon-consuming**, so they grow the component
catalog (and the RN migration evidence) without deepening the
F-ICON-RN-1 debt — and, unlike IconButton, they ship as complete RN
translations, not stubs.
