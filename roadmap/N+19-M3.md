```
BEFORE (M1/M2)                         AFTER (M3)
```

The three jobs run in parallel (no `needs:` between them):

- **`spec`** — = the pre-M3 `gates` job, workspace-scoped to `@nuri/spec`: `npm test -w @nuri/spec` (the pipeline drift guards · Guard A–F) · `npm run build -w @nuri/spec` · `git diff --exit-code packages/spec/build/` (no stale committed emit · decision 35) · `npx tsc -p docs/migration-tests/button-matrix/tsconfig.json` (the web↔RN migration mirror — **stays gating here · retires at M4**, not M3).
- **`factory`** — **THE intra-repo contract gate.** `npm test -w @nuri/factory` is the `react-test-renderer` render-smoke (27/27 · 7 snapshots): it imports `@nuri/spec`'s frozen descriptors+tokens through the `exports` map and **RENDERS** them on RN, so a `packages/spec/build/*` change that breaks the RN render **fails this job**. `npm run typecheck -w @nuri/factory` gates the `@nuri/spec → @nuri/factory` exports boundary (a contract TYPE break fails here).
- **`expo-demo`** — `npm run typecheck -w @nuri/expo-demo`: the consumable reference example must compile against `@nuri/factory`.

## The install-scoping finding (the 65.7 "RN out of the web gates" optimization · DEFERRED)

65.7 hoped per-workspace CI could keep the `spec` job RN-free. **Verified at M3: `npm ci -w @nuri/<job>` does NOT scope the install.** `npm ci` reconstructs the *whole* lockfile-defined tree by design (the `-w` flag scopes only the focus package's scripts/deps, not the install). Evidence — `react-native@0.81.5` resolves identically in both install plans:

```
$ npm ci --dry-run            2>&1 | grep -c 'react-native@0.81.5'   → 2
$ npm ci -w @nuri/spec --dry-run 2>&1 | grep -c 'react-native@0.81.5' → 2   (identical · not scoped)
```

So **each job runs full `npm ci`**, and the RN-free-spec-CI optimization is **deferred** (a future option only if CI install time becomes a real cost · P11 · e.g. a dedicated lighter lockfile / `--omit`). **The zero-build *iteration* property is unaffected** — the browser resolves `var()` natively regardless of a sibling workspace's `node_modules` (65.7's iteration claim was never about CI install).
