## The value-resolution mechanism (the agent-critical surface, generated)

The page OUTPUT is now a pure function of **(ir · palette · tokens · colors)** — all SoT-derived through ONE builder, `buildDocTokenInputs(classifiedGroups, resolved, typeScale)`, that the orchestrator (Slice 9) **and** Guard G both call, so the re-emit is byte-identical.

- **path → CSS var is DERIVED, not hand-kebabed** (the brief's load-bearing warning). `makeColorResolver` looks the semantic var up from the **classified groups** (the same leaf→cssVar map the cascade emits · the CSS SoT): `accent.solid` → `--nuri-accent-solid` (keeps its group prefix), `chrome.bgStrong` → `--nuri-bg-strong` (chrome **drops** its prefix). The swatch reads that var **live** (re-themes with scope); the hex is the **default-scope** (neutral + light · cream) literal resolved from the same `resolved` cross-product `build/tokens.ts` ships. A path that can't resolve, or dangles at the default scope, **throws** (faithfulness · decision 48).
- **The scope-anchor** ([`head_custom.html`](../website/_includes/head_custom.html)) — `state.js` defaults the web docs to the OLD preview site's brand A/B (**lilac / gray**), but the hex anchors **neutral / cream**, so the live swatch would NOT coincide with the printed hex. A 6-line script after `state.js` pins the generated SPEC docs to the build-canonical scope (**neutral · cream · light** · the scope `tokens.ts` resolves at), so **swatch == hex** at the page `:root`. The per-`<nuri-demo>` story keeps its OWN nested scope → the live examples still explore accents/themes independently. **Operator confirmed** keep-neutral-canonical at the checkpoint (the alternative — anchor the hex to the lilac brand — was declined).
- **The scales double as validation** — the size/space/radius value maps `{ leaf: 'NNpx' }` are BOTH the `assertLeaf` leaf-validation sets (Object.hasOwn) AND the px source (one map, two uses). `type` is the full typeScale.
