## What N+22 did

A thin end-to-end vertical slice for **Button only**: the descriptor becomes a build-output Markdown page, served by Jekyll/just-the-docs, with the live component embedded via the build-free `<nuri-demo>`. The fix for the old site's rot (hand-written prose + manual token/prop sync) is the **generation thesis** — docs become **build output**, regenerated from the descriptor every build, so they can't drift.

1. **Doc emitter (spec pipeline).** New [`pipeline/parsers/docs.js`](../packages/spec/pipeline/parsers/docs.js) · `emitDocPage(ir, { palette, tokens })` renders the descriptor IR as a just-the-docs Markdown page: front-matter (`title`/`layout`/`nav_order`) + **API** (axis → values) + **Anatomy** (the `el` part tree) + **Base** (the invariant composition · `structure.base` incl. the `interactive` opt-ins) + **Token map** (per axis-value → the per-part namespace composition, **resolved to token paths**: `variant`→`palette.ts` derefs · `size`→`box`/`typography` scale leaves). `tokens` is an emit-time **leaf-validation guard** (a box/typography leaf absent from its scale throws) — the OUTPUT is a pure function of `(ir · palette)`, so `tokens` never reaches the bytes. **SPEC ONLY — no prose.** One attribute per line in "Resolves to" (`<br>` + bold term + code value · operator readability request).
2. **Slice 9 in the orchestrator.** [`tokens-parser.js`](../packages/spec/pipeline/tokens-parser.js) imports/re-exports `emitDocPage`; new `DOC_COMPONENTS = ['composition-button']` (Button-only this increment) + `DOCS_OUT`; builds a `docTokens` leaf-set map from the live `classifiedGroups` + `typeScale` (one source — the same scales `tokens.ts` emits), re-derives the IR, and writes [`build/docs/button.md`](../packages/spec/build/docs/button.md) — **committed build output** (decision 35 · re-emits byte-identical).
3. **The `<nuri-demo>` story — AUTHORED, not generated.** [`website/_includes/demo/button.html`](../website/_includes/demo/button.html) holds the one `<template>` → preview+code widget (decision 10). The generated page carries only an `## Example` **include slot** (`{% include demo/button.html %}`); the story is the consumer's, not DS data (**decision 57.2** · "composing isn't DS work" · the "+" in north-star move 3's "generated data **+** stories via `<nuri-demo>`" is two sources).
4. **Jekyll/just-the-docs shell — [`website/`](../website/).** `_config.yml` (`remote_theme: just-the-docs/just-the-docs` + the plugins remote_theme doesn't auto-pull: `jekyll-remote-theme`/`jekyll-include-cache`/`jekyll-seo-tag`) · `Gemfile` (Jekyll 4) · `_includes/head_custom.html` (injects the nuri runtime so `<nuri-demo>` hydrates) · `index.md` · `.gitignore` · **`stage.mjs`** (the asset model · below).
5. **Pages deploy workflow — [`.github/workflows/pages.yml`](../.github/workflows/pages.yml).** On push-to-`main` + `workflow_dispatch` · `permissions: { pages: write, id-token: write }` · `github-pages` environment · `npm ci` → `npm run build -w @nuri/spec` (regenerate the MD) → `ruby/setup-ruby` (Ruby 3) → `node website/stage.mjs` → `configure-pages` (resolves the project baseurl) → `bundle exec jekyll build --baseurl …` → `upload-pages-artifact` → `deploy-pages`. **Separate from `gates.yml`** — it does NOT gate merges.
6. **New Guard G** ([`docs-drift.test.js`](../packages/spec/pipeline/docs-drift.test.js)) — `each build/docs/*.md re-emits identically from its descriptor`: re-emit identity via live `emitDocPage` `assert.equal` vs the committed file (the §35 stale-build / hand-edit teeth, Guard D/E posture) + the arc-#1 page-contract pins (front-matter · the `## Example` include slot · the five section headings · two token-map cell strings). docs-drift **5→6**.

## The kramdown path used

**Default kramdown block-HTML passthrough via the `_includes/` partial — NO fallback needed** (`{::nomarkdown}` not required). The `_includes` partial is itself one of north-star move 3's two recommended fallbacks; combined with kramdown's default `parse_block_html: false`, the `<nuri-demo>`/`<template>` block passes through intact. Proven by a Ruby-2.6 kramdown run on the staged page (the include expanded · the Liquid-then-kramdown order mirrored).

## The asset-serving approach — `stage.mjs` (the SoT-copy model)

GitHub Pages deploys only `website/_site`, so the nuri runtime must live inside the site. [`stage.mjs`](../website/stage.mjs) copies, at build time, `build/docs/*.md` → `website/components/` and the runtime assets (token CSS · `state.js`/`scope.js`/`button.{css,js}` · `control.*` · `demo.*`) → `website/assets/nuri/`. **The staged copies are gitignored** — only the `website/` SOURCE is committed (the Jekyll shell + the authored demo + `stage.mjs`). The generation thesis applied to assets: build output, copied fresh, never hand-synced → **no drift, no committed duplication**. (`shell.css`'s two base rules `nuri-scope{display:contents}` + `nuri-demo{display:block}` are inlined in `head_custom.html` — stable platform glue — rather than staging the 53KB docs shell, which would fight just-the-docs.)

## Gap in the derivable spec (found this increment)

The descriptor is a faithful **composition** spec but not the full element prop surface — two gaps a future increment must decide how to fill (no prose · derivable only):
- **No default-per-axis.** The descriptor carries axes' VALUES but not which is the default (`variant=soft` · `size=md`), so the API table can't mark defaults. This is exactly the **R1.5 "no default-per-axis in the frozen contract" finding** (the Digital-cash first-bump agenda) surfacing again from the docs side.
- **Axes ⊂ props.** The descriptor's axes are the composition axes (`variant`/`size`); the element's `accent` (scope override) + `disabled` (interaction state) props are NOT axes, so they're absent from the generated API. Faithful to the descriptor, but narrower than the old hand-written props table.
