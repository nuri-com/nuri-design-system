## What N+28·A2 did

S1 (N+25) made the RN resolver data-driven; S2 (N+26) shipped `nuri-pressable`; S3 (N+27) built the browser factory and de-collapsed Button (`view+interactive` + `text` arms). S3 left the static-`view` and `icon` arms as explicit `S4` throws. A2 fills them in — one generic engine, no per-component code — and un-gates the `.js` descriptor emit.

1. **`nuri-view` — the static merged-node host** ([`lib/components/view/view.js`](../packages/spec/lib/components/view/view.js) + [`view.css`](../packages/spec/lib/components/view/view.css) · new). The web mirror of RN's static `<View>` (the `el:'view'` non-interactive case). Unlike `<nuri-box>`/`<nuri-stack>`/`<nuri-pressable>` (display:contents wrappers around an inner painting node), **the `<nuri-view>` element IS the painting node**: the factory applies the merged `box ⊕ stack ⊕ palette` classes + data-* directly onto it — no inner element, no interactive, no MutationObserver (simpler than the pressable). `view.js` is a **bare registration** (no observed attrs, no `connectedCallback` work). `view.css` is the host's default box only — **RN `<View>`'s Yoga defaults: `display:flex; flex-direction:column; flex-shrink:0`** — plus an empty `@layer tokens` (the skip-emit convention). DEDICATED · ≠ `nuri-box` (the N+26 lock).
2. **The factory generalized** ([`lib/runtime/factory.js`](../packages/spec/lib/runtime/factory.js)). `renderPart` is now a **switch** over `el`: `view`+interactive → `<nuri-pressable>` (S3, unchanged), static `view` → `renderStaticView` (`<nuri-view>`), `text` → `<nuri-typography>` (S3), `icon` → `renderIcon` (`<nuri-icon name=X>`), and a **default throw** — the web analogue of the RN factory's `assertNever` (the consumability backstop · R7). The two `S4` throws are gone. `buildComponent` routes `props.name` to an `icon` primary part (IconAvatar's `name` API), alongside the existing `children`→primary-part routing. `open` needs **no branch** — the RN oracle's `renderPart` doesn't branch on it either (a view renders own-content + child parts regardless; `open` only marks that the host accepts positional children, which the own-content append already serves). Merge semantics are MIRRORED from the RN factory, not imported.
3. **The `.js` emit un-gated** ([`pipeline/tokens-parser.js`](../packages/spec/pipeline/tokens-parser.js)). `BROWSER_DESCRIPTOR_COMPONENTS` widened from `['composition-button']` to all three. The emit machinery (`emitDescriptorJs`) was already generic from S3 — a pure P11 un-gate, no new code. Rebuild → [`build/descriptors/icon-avatar.js`](../packages/spec/build/descriptors/icon-avatar.js) + [`topbar.js`](../packages/spec/build/descriptors/topbar.js) (additive · committed · **data byte-identical** to the `.ts`, the S3 contract).

```
  </nuri-view>
```

## The two checkpoint course-corrections (operator-directed)

Visual-feedback-first surfaced two recipe-vs-frozen-descriptor differences; the operator directed each:

1. **`flex-shrink` → FIXED at the primitive level (the gap is closed).** The icon-avatar recipe pins `.nuri-icon-avatar { flex-shrink: 0 }` (the circle never squishes); the stack `fill` vocab (`grow | grow-shrink`) can't express shrink:0, so a fill-less factory `<nuri-view>` initially got web's default `1`. The fix is **RN-faithful, not a paper-over**: RN `<View>`/Yoga defaults `flexShrink: 0` (web flexbox defaults `1`), so `nuri-view`'s base box gains `flex-shrink: 0` — completing the "`nuri-view` = RN `<View>`'s Yoga defaults" identity (the same rationale as `display:flex; flex-direction:column`). **Verified live** that the RN "explicit fill beats the default" model holds via existing `@layer` specificity: `.nuri-stack[data-fill]` (0,2,0) outranks the `nuri-view` element rule (0,0,1) in the same layer, so the Topbar grow-shrink content pivot still grows/shrinks (`flex-shrink:1`) while the IconAvatar circle + the Topbar chrome row stay rigid (`flex-shrink:0`) — matching RN.
2. **Topbar title-type → SURFACED accurately (a descriptor-fidelity gap · NOT fixed · NOT "A6 plumbing").** The topbar title typography (lg-em) is **not in the SoT** — the descriptor's `content` part carries no typography. It is hand-duplicated in **two** places: the web recipe ([`topbar.js`](../packages/spec/lib/components/topbar/topbar.js) · the bare-string `.nuri-type-lg--em` auto-type · decision 64) AND the RN consumer ([`packages/expo-demo/src/screens/Demo.tsx:31`](../packages/expo-demo/src/screens/Demo.tsx) · `TopbarTitle` → `typeStyle('lgEm')`). **Neither factory (web nor RN) can generate it** — the RN factory is not buggy, it faithfully renders an incomplete descriptor (the RN render-smoke passes the title as an explicit `<Text>` element; the web factory renders a typed title identically — verified 22px/600 — and only the recipe's bare-string *auto-typing* differs). The clean fix is a **topbar-descriptor DESIGN decision** — a typed `title` part vs the bare-string-conditional convenience (runtime child-inspection, not static descriptor data) — **DEFERRED**. It **joins the descriptor-fidelity / first-bump backlog** alongside R1.5's no-default-per-axis, the stringly-typed boolean axes, and the `subtle` fg-only variant. Surfaced, not fixed (the S3 / R1.5 precedent · the schema is frozen · Guard F).
