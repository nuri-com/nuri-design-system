# Session N+53 · Phase 4·3 — relocate the codegen out of `@nuri/spec` (`spec` → no-deps / no-scripts)

**Status**: shipped on `feat/n53-codegen-relocation` ([decision 79](../decisionlog.md) · base `main` @ `376e646` · the structural EXIT-path step of [decision 68](../decisionlog.md)'s Phase 4). The `postcss`-using token codegen moved OUT of `@nuri/spec` into a root `scripts/` directory; the spec package now has **no `devDependencies` and no `build`/`test` scripts** — pure data its consumers import, regenerated by an external tool.
**Type**: ORGANIZATIONAL — the generator's *location* moved, its *output* did not. **[decision 2](../decisionlog.md) UNTOUCHED** (no SoT moved, no CSS authored/generated). `build/*` + `styles/*` + `lib/components/icon/icons.js` re-emit **byte-identical** from the new home.

**Stayed in `packages/spec/pipeline/`** (untouched): the 8 `.ts` token SoTs (`colours` · `dimensions` · `typography` · `typography-axis` · `palette-surface` · `interactive-effects` · `resolve-map` · `property-spelling`) + `descriptors/*.ts` + the 2 browser computed-check `.html`. The `./resolve-map`, `./dimensions`, … subpath exports keep resolving (the `.ts` targets didn't move) → **no consumer-path churn**.

## The mechanical trick — one re-anchored line

Verified against the tree first (the brief was a hypothesis): the codegen has **zero `import … from '*.ts'`** — every SoT read goes through a `REPO_ROOT`-relative path constant + a data-URL `stripTypes` load (`loadDimensions`/`loadColours`/`loadTypography`/…). And every output path (`styles/` · `build/` · `lib/` · `icons/`) is `REPO_ROOT`-relative too. So the entire relocation is one line per file:

```
const REPO_ROOT = resolve(__dirname, '..')            // was: packages/spec from pipeline/
const REPO_ROOT = resolve(__dirname, '../packages/spec')  // now: packages/spec from scripts/
```

(the new home is one level shallower than `pipeline/`). `docs-drift.test.js`'s `MONOREPO_ROOT = resolve(REPO_ROOT, '..', '..')` stays correct (still the repo root). The `git mv` preserved the `parsers/` subdir, so the inter-emitter relative imports (`./parsers/foo.js`, `./semantic.js`) are **pure renames** — `git status` shows the 12 `parsers/*` as `R` (rename, no content change), the 7 re-anchored files as `RM`.

## The cross-package coupling (the one thing the brief's anti-goal didn't anticipate)

Two `@nuri/prototype` namespace-CSS freshness tests reach across the package boundary into the colour-cascade resolver as Guard C's value oracle:

```
// palette-css.test.js · typography-css.test.js
import { readSemanticRules, buildPrimitiveMap, resolveSemanticCrossProduct }
  from '../../spec/pipeline/parsers/semantic.js'   // ← that file MOVED
```

`semantic.js` is a core emitter (6 importers inside the codegen — `tokens-parser` + 5 sibling parsers), so it had to move with the codegen; leaving a copy/shim in spec would keep a codegen file in spec and defeat the goal. The two imports were repointed to `../../../scripts/parsers/semantic.js` (the only `@nuri/prototype` touch · **test-import-only**, no build-logic change). `css-preview.js` (prototype's live build) reads only its own `./parsers/*` + spec's exported SoTs + the generated `tokens-semantic.css` — all unaffected. **This coupling is recorded in [decision 79](../decisionlog.md)** so a future codegen move knows the dependency exists. The "don't touch prototype's codegen" anti-goal meant don't rework `css-preview.js`/its `postcss` — a forced relative-import repoint is not that (it's the same informal reach the prototype already used, pointed at the new home · operator-approved at the checkpoint).

## The build-order fix (the deferred N+41 footgun, discharged)

Root `package.json`:
- `"build": "node scripts/tokens-parser.js && npm run build --workspaces --if-present"` — the codegen runs **FIRST** (it writes `spec`'s `styles/tokens-semantic.css`), THEN the workspaces (`prototype`'s `css-preview.js` reads that generated CSS cross-package · DAG `prototype → spec`). The N+41 "make the root build run `@nuri/spec` before `@nuri/prototype`; fix when it bites" invariant is now satisfied.
- `"test": "node --test scripts/*.test.js && npm test --workspaces --if-present"`.
- `"type": "module"` added (root now owns ESM codegen · kills the `Reparsing as ES module` perf warning) + `postcss` as the root devDep.

`@nuri/spec/package.json` lost its `scripts` and `devDependencies` keys entirely (`--if-present` makes the workspace fan-out skip it cleanly).

## CI — the `spec` job re-pointed, the required-check name preserved

The `spec` job is a branch-protection required check, so the **name stays** (the [N+28](./N+28-A2.5.md) A1 `factory`→`rn` precedent). What it runs changed: `node --test scripts/*.test.js` (the relocated guards · folded into the existing job — the open-question call, confirmed: one token-pipeline gate, minimal churn) + `node scripts/tokens-parser.js` + `git diff --exit-code packages/spec/build/ packages/spec/styles/` (`styles/` **added** to the diff — the codegen regenerates it in place). The other 4 jobs (`prototype`/`rn`/`expo-demo`/`doc`) are untouched + self-sufficient against the committed tree.

## Judgment calls

- **Move `semantic.js`, repoint the 2 prototype tests (option A) — not a shim in spec (option B).** B keeps a codegen file in spec and defeats the no-deps/no-scripts goal; `semantic.js` has 6 in-codegen importers so it belongs with the codegen. The repoint is the minimal forced consequence (operator-approved · coupling recorded in the ledger).
- **Fold the relocated guards into the existing `spec` job, not a new job/step** (the open question). One token-pipeline gate, the required-check name unchanged, the clean Install→Test→Build→Diff shape preserved. They also run in the root `npm test` aggregate.
- **`type:module` at the root** — the root now owns ESM codegen; without it node reparse-detects ESM (a perf warning) on every `node scripts/*` invocation. The root has no other `.js`, so it only affects `scripts/`.
- **`styles/` added to the CI diff** — the codegen regenerates `styles/tokens-*.css` in place (the [§71](../decisionlog.md)/N+31 in-place hybrid), so the byte-identical gate must cover it, not just `build/`.
