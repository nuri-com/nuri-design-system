# Session N+7 · List family assembly · List + ListItem

**Status**: closed (2026-05-30)
**Type**: component-surface session (the List family **capstone** ·
assembles the N+6.9 building blocks into the row primitive · zero new
tokens · both skip-emit)

## Outcome

Shipped the **List family capstone** — `<nuri-list>` and
`<nuri-list-item>` — the row primitive the N+6.9 building blocks
(Separator · IconAvatar) and N+6.7's TypographyStack were minted for.
The family composes those four existing components **as-is** (none
modified) into ONE slotted row shape.

**List** ([`lib/components/list/`](../lib/components/list/)) is
`<nuri-list [density]>`: a `role="list"` flex column with **no `gap`
prop** (inter-row rhythm is each row's own min-height plus author-placed
`<nuri-separator>`s — a container gutter would double-space the
separators and fight the row min-height) and a single `density` enum
(sm · md default · lg). Density is a **container decision projected onto
its rows**: it dispatches as a host attribute and resolves to a child
`min-block-size` — sm→`size-xl` (60px) · md→`size-2xl` (72px) ·
lg→`size-3xl` (90px) — through a rule in `list.css` that targets
`nuri-list-item` **only**, so the 1px Separators between rows keep their
height across every density
([decision 51](../decisionlog.md#51-list--listitem--family-capstone--one-row-shape-slots-not-use-case-variants--density-owns-row-rhythm--interactive-press-overlay--skip-emit--n7)).

**ListItem** ([`lib/components/list-item/`](../lib/components/list-item/))
is `<nuri-list-item [interactive]>` plus the named book-ends
`<nuri-list-item-leading>` / `<nuri-list-item-trailing>` — **ONE slotted
row shape** `[leading?] · content · [trailing?]` laid out in **document
order** (no reparenting · contrast Topbar's 3-region routing ·
[decision 46](../decisionlog.md#46-topbar--first-compositional-chrome-shell--child-reparenting-compound--slots-not-use-case-variants--n66)).
It is **not** a set of use-case variants: the same shape carries a
disclosure row, a transaction row, and a summary row purely by swapping
slot content (an IconAvatar in `leading`, a TypographyStack in `content`,
an amount stack or caret `<nuri-icon>` in `trailing`). When the
`interactive` attribute is set, `list-item.js` appends a **full-row press
overlay** — an absolutely-positioned `<div role="button" tabindex="0">`
that paints the `bg-pressed` wash behind the row's content. The row is
**dual-role** (`listitem` on the host · `button` on the overlay) and
**nav-agnostic**: no `href`, no native `<button>`, no `disabled`, no
hover — it only fires a bubbling click and leaves routing to the
consumer.

Both components have an **empty `@layer tokens`** block → the pipeline's
skip-emit path detects 0 declarations and writes **no**
`build/components/{list,list-item}.ts` (decisions 37 · 47 · 49 · 50
pattern). **Zero new tokens** — both consume the semantic
size / surface / focus vocabulary directly in `@layer rules`.

## Why ONE slotted shape, not use-case variants

The external-project source carried distinct `faq` / `transaction` / `fee`
list-item shapes. Each is really the **same row geometry** — a leading
book-end, a flexing content column, a trailing book-end — differing only
in *what* sits in each slot. Modelling them as variants would fork the
layout three ways and force a new variant prop for every future row kind
(a settings row, a notification row…). ONE shape composed via slots
(`leading` · content · `trailing`) carries all of them by swapping
content: an IconAvatar + a two-line TypographyStack + an amount stack
*is* a transaction row; a TypographyStack + a caret *is* a disclosure
row; a label + a value *is* a summary row. This is the Topbar
slots-not-variants precedent (decision 46) applied to rows, and it keeps
ListItem's surface to a single `interactive` boolean.

## Why the press overlay (and not `:has()` / a native button)

The full-row press wash needs the **whole row** to react to a press on
**any** part of it. Three approaches were weighed:
- A native `<button>` wrapping the row would swallow the row's semantics
  (everything becomes button content) and forbid nesting interactive
  trailing controls later.
- An ancestor `:has(:active)` selector would let the row react to a
  descendant's state — but `:has()` is used **nowhere** in the codebase,
  and introducing it for one component is a disproportionate new
  dependency on selector support.
- **The chosen overlay**: an absolutely-positioned `<div role="button">`
  at `z-index:0; inset:0`, with the row's real content lifted to
  `z-index:1; pointer-events:none`. The wash paints the full row
  **behind** the content; clicks pass *through* the content to the
  overlay. No `:has()`, no semantic capture, and the row keeps its
  `listitem` role while the overlay carries `button` — a clean dual role.
The `<div>` gets no keyboard contract for free, so Enter (keydown) and
Space (keyup, preventing scroll) are wired by hand, and the nameless
button is given an accessible name from the row's visible text.

## Frictions

- **F-LISTITEM-ROLE-1 (new · documented, not a blocker)** · React
  Native's `AccessibilityRole` type has `list` but **no** `listitem`.
  The web row carries `role="listitem"`; the RN row cannot. Resolution:
  the RN interactive row is a single `Pressable
  accessibilityRole="button"` and the non-interactive row is a plain
  `<View>` with **no** role — the list-membership semantics that web gets
  from `listitem` are simply unavailable on RN, an honest platform gap
  rather than a renderer bug. Captured in the index.tsx comment and
  decision 51.
- **F-FOCUS-1 stays open (RN omits the focus ring)** · the web overlay
  shows a `:focus-visible` outline; RN `Pressable` has no
  focus-ring analogue in this spec. Behavioural, not structural —
  the press wash ports, the keyboard-focus ring does not.
- **R1 (web↔RN parity is behavioural, not structural)** · the web
  `leading`/`trailing` wrappers are custom elements; RN passes
  `leading`/`trailing` as render props. Same prop *names*, different
  mechanism — the family is a parity-by-behaviour case, not
  parity-by-DOM.

## Why N+7 closes the List family

N+6.9 minted the two leaf building blocks (Separator · IconAvatar) but
explicitly built **neither** List nor ListItem; N+6.7 minted
TypographyStack as the line-hierarchy primitive the family composes.
N+7 is the assembly step: it wires those three plus Icon into the row
primitive itself, reusing the now-four-times-proven light-DOM compound
mechanism (Tabs · Topbar · TypographyStack · ListItem). With the row
landed, the List family is complete — the next operator brief turns to
the first icon-consuming display component (SegmentedControl · TabBar ·
Tag), the higher-value validation that decision 48's glyph path
generalises beyond IconButton.
