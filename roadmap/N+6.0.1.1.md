## Outcome

Downstream-cascade governance lock for N+6.0.1. The previous
session landed
[decision 33](../decisionlog.md#33-semantic-token-docs--format-b-verbose-dual-mode-for-context-dependent-tokens--n601)
(Format B verbose dual-mode for context-dependent semantic tokens)
and applied the convention across `styles/tokens-semantic.css`, but
did not propagate the rule to the spec-authoring surfaces where
future agents will encounter the convention. This session closes
that gap with a **3-surface skill-routed cascade**:

1. [`skills/modify-tokens.md`](../skills/modify-tokens.md) — the
   direct surface for any semantic-token edit; Semantic bullet now
   names the dependency-driven trigger + canonical-block + terse
   cross-ref pattern.
2. [`skills/add-accent.md`](../skills/add-accent.md) — the surface
   that generates 6 new accent-* tokens (varying across
   accent × theme) on every new accent; per-family cascade step
   now names Format B canonical at the accent block + terse
   cross-ref at the dark block, with the bright-accent
   partial-redeclare note per
   [P4](../pages/principles.html#p4-mode-accent-composition).
3. [`skills/close-out-session.md`](../skills/close-out-session.md) —
   closes the loop at audit time; audit-asks now include the
   Format B coverage check for any session that modified
   `tokens-semantic.css`.

The cascade is **surface-localized**, not trans-surface, because
decision 33's trigger fires only when modifying
`styles/tokens-semantic.css`. The N+5.7.1 cascade for
[decision 30](../decisionlog.md#30-primitive-parsimony--no-speculative-additions--n571)
went 5 layers wide (AGENTS hard-rule + FIXED-defaults +
5 skill files + close-out audit + CI guardrail at
`build/tokens-parser.test.js` test 15) because parsimony is a
trans-surface meta-rule any session can violate; decision 33 is
not. Explicitly NOT extended this session:
[AGENTS.md](../AGENTS.md) hard-rules (would be meta-rule theater),
[`prompts/working-session.md`](../prompts/working-session.md) FIXED
defaults (would be false-positive in semantic-untouched sessions),
[`skills/add-component.md`](../skills/add-component.md) (component
tokens live in component CSS files, not `tokens-semantic.css`), and
[`skills/add-foundation.md`](../skills/add-foundation.md)
(foundations document existing tokens; the rare adding-tokens case
goes through `modify-tokens.md` which already carries the cross-ref).

[Decision 33](../decisionlog.md#33-semantic-token-docs--format-b-verbose-dual-mode-for-context-dependent-tokens--n601)
itself gains a **Procedural enforcement** section (mirroring
[decision 30](../decisionlog.md#30-primitive-parsimony--no-speculative-additions--n571)
lines 254-266) naming the 3 surfaces with their one-line roles and
the contrast against decision 30's trans-surface 5-layer cascade.
This makes the cascade visible from the decision itself, not just
from the surfaces back. No amendments to the original body — the
N+6.0.1 lock stays verbatim per the decisionlog convention.

No new tokens; no new files beyond this retrospective. `npm test`
