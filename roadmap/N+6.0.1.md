# Session N+6.0.1 · Semantic docs · Format B verbose dual-mode for context-dependent tokens + decision 33 lock

**Status**: closed (2026-05-28)
**Type**: bridge (docs convention · doc-only)

## Outcome

`styles/tokens-semantic.css` is now self-documenting at every
context-dependent semantic token. Each of the 18 tokens that
ship (12 chrome + 6 accent) carries either a **Format B canonical
comment** showing the full resolution matrix at its canonical
declaration block, OR a **terse 1-line cross-ref** at any
non-canonical block — never a duplicate matrix, never a "current
mode only" view that forces the reader to traverse 4+ blocks.

The convention is locked by
[decision 33](../decisionlog.md#33-semantic-token-docs--format-b-verbose-dual-mode-for-context-dependent-tokens--n601)
and is **dependency-driven**, not type-driven: a token gets Format
B only when its value varies across the active cascade dimensions
({theme, scope, accent, …}). The N+6.1 semantic spacing + sizing
layers will be mode/scope-invariant — they get terse role
descriptions instead. A future change that makes spacing
density-dependent would promote those declarations to Format B
mechanically.

Canonical-declaration assignment follows the cascade structure:

| Token category | Canonical block | Reason |
|---|---|---|
| Chrome (bg / text / border / focus) | Block 1 (`:root`) | Block 1 declares the chrome default; block 2 is the only override |
| Accent · neutral family | Block 1 (`:root`) | Block 1 declares the neutral default; blocks 2/3/4 are mode/scope variants |
| Accent · lilac family | Block 5 (`[data-accent="lilac"]`) | Block 5 declares the lilac default; block 6 holds partial-dark overrides per [P4](../pages/principles.html#p4-mode-accent-composition) |

The narrative comments the coordinator added in Point 1 (post-N+6.0
fix that established the neutral-accent INVERSE pattern) are
retrofitted to canonical Format B — the inverse-pattern insight is
preserved, just distributed across per-declaration comments instead
of concentrated in a paragraph.

Inherits the N+5.7.1 parsimony lock — the FIXED anti-goal default
in [`prompts/working-session.md`](../prompts/working-session.md)
fired automatically; no new tokens, no value changes. `npm test`
stays 15/15; `npm run build` continues emitting 216 colour
primitives + 18 semantic × 2 accents × 2 themes (counts unchanged
— this session touched only inline comments and the doc-cross-link
surface).

during the convention application itself. The single observation

when the cascade structure has a clear canonical-block assignment
(here: defaults block + accent-family-specific default block).
A future cascade that introduces a third dimension (density / font
/ neutral-scale) would need to revisit the canonical-block
assignment table — the convention itself stays dependency-driven
and applies the same way, but the canonical block for each new
dimension's interactions needs an explicit pick.

## Why N+6.0.1 not bundled with N+6.1

Two reasons:

1. **Cognitive mode separation.** N+6.1 is technical work — new
   semantic spacing + sizing scales, button.css full refactor,
   emitter extension, two foundation pages — ~10 ship items in
   the "code change" mode. N+6.0.1 is docs convention — one
   decision lock + applying the convention across an existing
   file — in the "writing surface" mode. Bundling mixes mental
   models inside a single audit.
2. **Sequence value.** Locking the Format B convention BEFORE
   N+6.1 lands means the N+6.1 agent inherits the rule via
   [decision 33](../decisionlog.md#33-semantic-token-docs--format-b-verbose-dual-mode-for-context-dependent-tokens--n601):
   spacing / sizing semantic tokens (mode/scope-invariant in the
   N+6.1 roadmap) get terse 1-line role descriptions, not Format
   B. Without the convention in place, the N+6.1 agent might
   either skip the inline matrix doc entirely (regression vs
   today's chrome / accent) or pre-apply Format B to invariant
   tokens (drift from the dependency-driven rule). Sequencing
   solves both by construction.

X.Y.Z numbering: N+6.0.1 is a derivative of N+6.0's primitive
direct-pixel migration (which surfaced the gap operator articulated
in the N+6.0 retrospective thread). Mirrors the
[N+5.7.1 precedent](./N+5.7.1.md) (downstream governance lock
after N+5.7's cleanup evidence).
