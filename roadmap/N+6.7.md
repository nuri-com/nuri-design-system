# Session N+6.7 · TypographyStack family

**Status**: closed (2026-05-29)
**Type**: main sequence (the text-hierarchy primitive · a two-element
light-DOM compound for stacking typographic lines at a contextual
level · the line-hierarchy primitive that List / ListItem / Separator
will compose in future sessions · reuses the Tabs/Topbar
child-element compound mechanism at a third consumer)

## Outcome

One cohesive deliverable — the **TypographyStack family**, a
two-element light-DOM compound
([`lib/components/typography-stack/`](../lib/components/typography-stack/)):

- **`<nuri-typography-stack>`** is the flex container. Layout is
  **pure CSS** reading the `direction` attribute — `column` (default ·
  `gap: var(--nuri-space-2xs)`) or `row` (`align-items: baseline` ·
  `gap: var(--nuri-space-xs)`). The element only needs *defining* (no
  JS layout).
- **`<nuri-typography-stack-element level="1..5">`** is the styled
  text line. `#sync()` resolves `level` → the existing `.nuri-type-*`
  utility class (size + emphasis · SSOT in
  [`styles/typography.css`](../styles/typography.css)) and sets
  `data-level` so [`typography-stack.css`](../lib/components/typography-stack/typography-stack.css)
  can dispatch the chrome text colour. Unknown / missing `level` warns
  and falls back to level 4 (the plain `sm` primary line · mirrors
  `<nuri-typography>`'s unknown-size warn).

Each line declares a **contextual `level` (1..5)**, not an absolute
size — "the most prominent line in *this* stack", which the stack
renders at a concrete size + colour. The level carries on the
*-element*, deliberately **not** on `<nuri-typography>` (it would
collide with `size` and leak contextual hierarchy into a context-free
primitive). [Decision 47](../decisionlog.md#47-typographystack-family--contextual-text-hierarchy-primitive--level-carried-by-the-element--n67)
locks the family.

As a **layout primitive** its `@layer tokens` block is **empty** (no
`--nuri-typography-stack-*` tokens · the
[decision 37](../decisionlog.md#37-layout-primitives-consume-semantic-vocabulary-via-prop--no-component-token-aliasing--n62)
pattern); colour dispatches off `data-level` in `@layer rules`
([decision 42](../decisionlog.md#42-box-gains-background--radius-props--attribute-dispatch-surface-vocabulary--evidence-gated-promotion--n65)
attribute-dispatch — JS reports state, CSS owns appearance). The
pipeline skips its per-component emit (no
`build/components/typography-stack.ts`).

**Typography was NOT touched** — no `level`, no `tone` prop; the stack
*composes* the existing `.nuri-type-*` utilities rather than extending
the primitive. **Zero new tokens.**

| 2     | `nuri-type-md--em`  | md   | 600      | `--nuri-text-primary`   |
| 3     | `nuri-type-sm--em`  | sm   | 600      | `--nuri-text-primary`   |
| 4     | `nuri-type-sm`      | sm   | 400      | `--nuri-text-primary`   |
| 5     | `nuri-type-sm`      | sm   | 400      | `--nuri-text-muted`     |

## API · operator-locked at session open

```
<nuri-typography-stack [direction]>          direction: column (default) | row
  <nuri-typography-stack-element level="1..5"> … </nuri-typography-stack-element>
  …
</nuri-typography-stack>
        column → flex-direction:column · gap space.2xs
        row    → flex-direction:row · align-items:baseline · gap space.xs
                 NO gap prop (rhythm owned by the primitive), NO Shadow DOM / <slot>,
                 light-DOM only · the host IS the styled text node (no inner span)

<nuri-typography-stack-element level="1..5">  level: 1 (lg em) … 5 (sm muted) · default 4
                 level lives HERE, not on <nuri-typography> (would collide with size)
```

## Why a new primitive and not reuse `<nuri-stack>`

`<nuri-stack>` is a *generic* flex/gap primitive — it knows nothing
about typographic rhythm. The space between a title and its caption is
**inter-level text rhythm**, a property of the type system, not the
same authoring decision as the gap between two cards. Folding it into
the generic stack would either force every caller to re-derive the gap
(drift surface) or teach the generic stack about type levels
(use-case knowledge it has no business holding · the
speculative-generality refusal of decision 30 / P11). A dedicated
primitive keeps the rhythm in one place and `<nuri-stack>` generic.

## Why level on `-element`, not Typography

`<nuri-typography>`'s `size` is an **absolute** scale (xs..xl), a
context-free global choice. A stack `level` is **contextual** —
relative prominence inside *this* stack. Putting `level` on Typography
would collide with `size` (two competing scales) and leak the stack's
contextual hierarchy into a context-free primitive. Carrying it on a
stack-scoped element keeps the two scales orthogonal.

## Frictions surfaced

- **RN font metrics can't be dereferenced from tokens.** The primitive
  `type` set is **pipelineInline**
  ([decision 34](../decisionlog.md#34-per-component-files--tokenpath-union--set-policy--pipeline-emit-shape--n603)),
  so `build/tokens.ts` exposes no runtime font-size/weight namespace.
  RN therefore hand-declares `TYPOGRAPHY_STACK_LEVELS` from the
  `--nuri-type-*` primitive values (lg=22 / md=17 / sm=15 · em 600 /
  regular 400 · line-heights 1.27/1.29/1.33), while **colour** resolves
  from the runtime `chrome[theme]` slice exactly as the web
  `data-level` dispatch does. One declared mapping, read identically
  both sides — but the metric half is a hand-maintained parity guard
  (R1), not pipeline-derived. (No new friction code minted · parsimony
  · the RN-spec-home Open question already tracks the home.)

## Why TypographyStack now (sequence position)

N+6.5 shipped Tabs (first compound) and N+6.6 shipped Topbar (first
chrome shell) — both light-DOM child-element compounds. TypographyStack
reuses that mechanism at a third consumer and lays the **text-hierarchy
primitive** that List / ListItem / Separator (future sessions) will
compose for transaction rows, fee summaries, and Cancel/Save bars. It
is a non-Icon-consuming interlude — F-ICON-RN-1 carried forward
unchanged (the renderer debt was neither advanced nor deepened) since
the stack composes only text utilities and chrome colour, no glyph.
