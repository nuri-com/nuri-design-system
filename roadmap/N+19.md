### The model in one screen (detail → `resolver-model.md`)
- **Transversal baseline** (theme/factory · §1): four *small, fixed* vocabularies — colour (surface
  roles, each rest+pressed) · type (steps) · geometry (space/size/radius) · interaction
  (press-scale/disabled-opacity). Does **not** grow per-consumer.
- **Three kinds** (§3): leaf (Icon) · primitive (open · consumes a subset · *exposes the substrate's
  interface, never remaps*) · recipe (closed · *may remap a subset to a semantic vocabulary*).
- **surface** = shared colour *data*, reused via the engine (§4). **Interaction decomposes** (§5):
  pressed-colour lives in the surface vocab; press-scale / disabled = independent opt-ins.
- **Format** (§7): Unistyles-compatible `variants`/`compoundVariants` — *compatible, not a dependency*;
  baseline = the `theme`; engine = a *bounded* custom build on `NuriThemeContext`/`resolveToken`/`typeStyle`.
- **Two scopes** (§12): theme/accent (`ScopedTheme`-style · dec 27/63) vs the surface
  foreground/label-type context (propless typography/icon inherit). Don't conflate.
