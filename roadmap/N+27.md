### The merged node (the faithful web analogue of RN's single `<View style>`)

The descriptor's root part carries `box ⊕ stack ⊕ palette ⊕ interactive` on ONE node. The factory emits `<nuri-pressable>`; the pressable owns the inner `<button class="nuri-interactive">` (created lazily in its `connectedCallback`). The factory MERGES `nuri-box nuri-stack nuri-palette` + the geometry/colour `data-*` onto that **same** button — proven live as:

```
<nuri-pressable press-scale press-color>                          ← interactive opt-in → gate attrs
  <button type="button"
          class="nuri-interactive nuri-stack nuri-box nuri-palette"
          data-direction=row data-align=center data-justify=center  ← stack
          data-min-height=lg data-padding-x=lg data-radius=sm        ← box
          data-variant=solid                                         ← palette (fg rides along · F-BOX-FG-1)
          data-press-scale data-press-color>                         ← pressable's gates
    <nuri-typography size=md emphasis>Pay</nuri-typography>          ← text → typeStep 'mdEm' expanded
  </button>
</nuri-pressable>
```

The pressable sets the button's `className` ONCE and never rewrites it (the N+26 contract), so the merge never clobbers. Because the button is created on connect, the merge is **DEFERRED** — a one-shot `MutationObserver` on the host applies it the moment the inner button appears (microtask · before first paint). `pressColor`/`pressScale` → the host's `press-color`/`press-scale` attrs (pressable maps them to `data-press-*` gates); `disabledOpacity` is automatic. Foreground flows by SCOPE — palette sets BOTH `background` AND `color`; the `<nuri-typography>` label INHERITS `color` (the type utility sets none). The factory threads no fg.

## The checkpoint course-correction — `reset.css` (operator-directed)

Visual-feedback-first earned its keep: the 14/14 computed-style report (rest/disabled/accent) was green, but the **screenshot** showed the factory buttons wearing the native `<button>`'s UA chrome — a `2px outset` border, the bezel (`appearance: auto`), an intrinsic `1px 6px` padding-block — because `.nuri-interactive` never normalized its host the way `.nuri-button`'s base does ([`button.css:188`](../packages/spec/lib/components/button/button.css) · `border:0` · `appearance:none` · `padding:0` · `user-select:none` · `font:inherit`). The de-collapse styles the same button from box⊕stack⊕palette, so the host needs that normalization too.

First pass folded the reset into `interactive.css`'s affordance block. **The operator vetoed that** (2026-06-22): the namespace CSS (`box/stack/palette/interactive.css`) is the **§9 generation target** — those rules are TOKEN-DERIVED data a build-time resolver will EMIT; a hand-authored UA reset must NOT be mixed into a to-be-generated file. Reverted `interactive.css` to `origin/main`; moved the reset to its own hand-written [`lib/runtime/reset.css`](../packages/spec/lib/runtime/reset.css) (the "thin hand-written primitive layer whose mechanism is hand-written" · decision 67). It targets `.nuri-interactive` in **`@layer rules`** so specificity (not layer priority) decides — `padding:0` is outranked by `box`'s `.nuri-box[data-padding-x]` (0,2,0 vs 0,1,0) for the inline axis, so box supplies the inset while the reset only zeroes the UA `padding-block`. (An unlayered reset would beat the layered box rule and wipe the inline padding too.) Also fixes the latent S2 bare-`<nuri-pressable>` bezel.

**The split is now principled**: generated namespace CSS = token-derived · `reset.css` = hand-written browser-normalization. §9's CSS generator must preserve this boundary.
