## What N+26 did

S3 will de-collapse Button into an `el`-named `<nuri-*>` tree styled from the descriptor. That needs the interactive el-host as a standalone primitive — today it is hard-coded inline in the Button recipe (`button.js` creates a native `<button>` with the `.nuri-button` recipe class). N+26 ships the generic extraction.

**P11 / rule 20 / decision 30 — shipped ahead of its consumer, sequence-authorized (the explicit one-line justification).** `nuri-pressable` ships at S2 but its first consumer is **S3** (the Button de-collapse into `<nuri-pressable>`). This is decision 30's "explicitly reserved with a one-line justification" path, **not speculation**: the decision-67 build sequence ([`factory-rewrite.md`](./factory-rewrite.md) §3 · the S2 row) requires the interactive el-host as a standalone primitive *before* S3 can emit it — S3 cannot de-collapse Button into `<nuri-pressable>` if `<nuri-pressable>` does not yet exist. (`nuri-view`, the other half of the el→primitive lock, is correctly **not** built — its consumer is S4, so only its shape is locked · P11.)

1. **`nuri-pressable` — the generic interactive el-host** ([`packages/spec/lib/components/pressable/pressable.js`](../packages/spec/lib/components/pressable/pressable.js), new). The web mirror of RN `<Pressable>` ([`createNuriComponent.tsx:104`](../packages/factory/factory/createNuriComponent.tsx) — the `el:'view'` + `interactive` case). It does what `button.js` does inline — create a native `<button type="button">`, move authored children inside it, never tear it down on re-sync (so consumer click listeners survive an attribute change) — but applies the **generic `.nuri-interactive` namespace** ([`interactive.css`](../packages/spec/lib/components/interactive/interactive.css) · decision 65.3 §6 / 65.4), **not** the `.nuri-button` recipe. The interactive vocabulary is exposed as `data-*` gates (the box/stack pattern). `className` is set ONCE in `connectedCallback` and `#sync()` never rewrites it — so S3 can merge `nuri-box nuri-stack nuri-palette` onto the same host with no clobber (the merged-node model · the opposite of `typography.js`'s wholesale-className rewrite).
2. **`pressable.css`** ([new](../packages/spec/lib/components/pressable/pressable.css)) — one rule `nuri-pressable { display: contents }` (the wrapper is layout-invisible; the inner `<button>` paints · the [`button.css:134`](../packages/spec/lib/components/button/button.css) precedent) + an empty `@layer tokens` (the `interactive.css` / decision-37 skip-emit convention).

### The attribute surface (1:1 RN `<Pressable>` · decision 21 / 67)

| `<nuri-pressable>` attr | → inner `<button>` | RN `<Pressable>` |
|---|---|---|
| `press-scale` (boolean) | `data-press-scale` | the `interactive` channel (factory's pressed render-prop) |
| `press-color` (boolean) | `data-press-color` | the `interactive` channel (factory's pressed render-prop) |
| `disabled` | native `disabled` | `disabled` + `accessibilityState={{disabled}}` |
| `accent` | `data-accent` (Tier-2 self-scope · decision 27/62) | `accent` base prop |
| `accessibility-label` | `aria-label` | `accessibilityLabel` |
| (native click bubbles · no `onpress` attr) | — | `onPress` |

`press-scale` / `press-color` are the web realization of the descriptor's `interactive` namespace (a structured per-part opt-in · decision 65.4) — each its own `:active` gate so a static surface never reacts. `interactive.css` realizes `press-scale` (the `:active` scale) + the disabled dim; `palette.css` realizes `press-color` (the `:active` bg swap, gated `[data-press-color]`) once a palette merges onto the node at S3. The inner host stays `<button>` only — no `as`/role escape hatch (no current consumer · P11 · decision 30).

## The el → web-primitive mapping (as-built · decision 67 scope · no new decision)

The lock S2 records — for each anatomy `el` the S3/S4 web-factory walks, which web primitive renders it:

| anatomy `el` | web primitive | status | RN mirror |
|---|---|---|---|
| `view` + `interactive` | **`nuri-pressable`** | **BUILT (N+26)** | `<Pressable>` ([createNuriComponent.tsx:104](../packages/factory/factory/createNuriComponent.tsx)) |
| `view` (non-interactive) | **`nuri-view`** | **DECIDED — dedicated, NOT `nuri-box`** · built at **S4** when IconAvatar/Topbar consume it (P11 · only its shape is locked here) | `<View>` |
| `text` | **`nuri-typography`** | **REUSE existing** — text parts are single-namespace (typography) | `<Text>` |
| `icon` | `nuri-icon` | exists | glyph leaf |
| — (bench layout) | `nuri-screen` / `nuri-scroll` | exist (decision 58) — leave them | `<View flex:1>` / `<ScrollView>` |

**Why `nuri-view` ≠ `nuri-box`** (locked, built at S4): a `view` part carries `box ⊕ stack ⊕ palette ⊕ interactive` on ONE node (the Button root · `composition-button.ts`); `nuri-box` is geometry-only. A dedicated `nuri-view` is the clean 1:1 with RN `<View>`. Its first consumer is S4 (IconAvatar/Topbar de-collapse), so only its shape is locked here — **not built** (P11 · rule 20).

**Scope was narrower than the roadmap S2 row** (verified first-hand): of the four primitives that row listed (`nuri-pressable`/`nuri-text`/`nuri-screen`/`nuri-scroll`), only `nuri-pressable` was missing. `nuri-screen`/`nuri-scroll` already exist (decision 58); the `text` part reuses the existing `nuri-typography` (no `nuri-text` built); the `view`-vs-`nuri-view` question resolved to a dedicated `nuri-view` deferred to S4.

## Byte-identical `build/` — the mechanism

The pipeline's `COMPONENTS` walk-list ([`tokens-parser.js:187`](../packages/spec/pipeline/tokens-parser.js)) is **hardcoded, not a glob**, and contains neither `interactive` nor `pressable`. So `pressable.css` is **never read** by the build → `packages/spec/build/` stays byte-identical by construction (the same reason `interactive.css` emits nothing). The empty `@layer tokens` is the documented convention (belt-and-suspenders for the day a consumer adds `pressable` to the list).

## What N+26 did NOT do (deliberate · anti-goals)

- **No RN / factory changes** — `packages/factory/**` untouched; `createNuriComponent` already wires `<Pressable>` (decision 65). The RN "primitive" is the native; nothing to build there.
- **No descriptor / schema / `resolve-map.ts` / `build/` changes** — dec 2 untouched · NOT §9.
- **No other primitive builds** — no `nuri-view` (→ S4), no `nuri-text` (→ reuse typography), no `nuri-screen`/`nuri-scroll` (exist · decision 58).
- **No Button de-collapse / descriptor wiring** (that is S3); `pressable.js`/`.css` reference **no** recipe CSS (`button.css` untouched, uncited as a dependency).
- **No new tokens, no hex, no component-token aliasing** (decision 37 · rules 1–2) — `.nuri-interactive` consumes `--nuri-interaction-*` / `--nuri-focus-ring` directly (already done in `interactive.css`).
- **No committed page** — no `pages/components/pressable.html` (a hand page cuts against the website doc-gen arc · decision 66); the proof was a throwaway preview smoke.
- **No `as`/role escape hatch, no `onpress` attr** — native click bubbles; inner host is `<button>` only (P11).
