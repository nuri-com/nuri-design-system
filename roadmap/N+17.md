### 1 · ListItem — content-pivot open primitive (web)

- **`lib/components/list-item/list-item.css`** — introduced `<nuri-list-item-content>` as the
  layout pivot (`flex: 1 1 auto; min-inline-size: 0`). **Deleted** the
  `nuri-list-item-leading` / `nuri-list-item-trailing` book-end rules, the trailing
  `margin-inline-start: auto` patch, and the `> :not(leading):not(trailing)` content selector.
  Leading/trailing are now **positional siblings** — anything before the pivot is leading,
  anything after is trailing — auto-width, self-styling, centred by the row's
  `align-items: center`. The pivot's `flex:1` pushes any trailing to the row end **by
  construction** (no margin-auto). `@layer tokens` (`paddingBlock` / `gap`) **unchanged**.
- **`lib/components/list-item/list-item.js`** — replaced the two book-end marker classes with a
  single `NuriListItemContent` marker; `NuriListItem` (role="listitem") unchanged.
- This aligns web to the **already-validated RN shape** (`list.tsx` already used a `flex:1` View
  pivot · decision 64), and the pivot maps to a `<View>`, never a `<Text>` — structurally
  avoiding the R-EXPO-2c native-`<Text>`-child invalidity class.

### 2 · NavItem — closed scalar recipe (web)

- **`lib/components/nav-item/nav-item.js`** — rewrote from the children-distribution hybrid to a
  **scalar** contract: `text` (required) · `icon?` (→ a leading `<nuri-icon-avatar name>`) ·
  `variant?` / `accent?` (forwarded to that avatar · **no-op without `icon`**) · `onpress`
  (required). **Deleted** the `while`-loop / `localName` type-routing. Template now composes
  `list-interactive-item ∘ list-item ∘ [icon-avatar] ∘ <nuri-list-item-content><nuri-typography
  size="md" emphasis>{text}</nuri-typography></…> ∘ <nuri-icon caret-right>`. Because the source
  of truth is now attributes (not moved children), re-composition is idempotent.
- **`lib/components/nav-item/nav-item.css`** — the always-present caret is muted via
  `nuri-nav-item .nuri-nav-item__caret { color: var(--nuri-border-strong) }` (the icon inherits
  via `currentColor` · decision 38 · no `muted` prop on Icon). The class out-specificities
  `.nuri-icon { color: currentColor }` and scopes the mute to the caret alone (a leading
  icon-avatar's glyph keeps its colour). `icon.js`'s additive `classList.add('nuri-icon')`
  preserves the hook. Skip-emit (empty `@layer tokens`) **unchanged**.
- Arbitrary leading / rich content is **not** a NavItem concern — drop to the `<nuri-list-item>`
  primitive (the escalation rule · decision 64).

## The `flex:1` STOP — operator/coordinator decision (recorded, not actioned)

At the visual checkpoint the operator asked about the *real* ListItem migration gap: the
content-pivot's **flexbox layout values** (`flex:1` / `min-inline-size:0`) live only in
`list-item.css` `@layer rules` and are **hand-mirrored** in `list.tsx` (`<View {flex:1,
minWidth:0}>`) — not machine-checked, so they can drift. The proposed resolution was to emit
them as component design tokens. **Per the brief's wall** ("no new decision · no emit-shape
change · if forced, STOP and surface"), this was raised, not implemented.

**Coordinator decision: do NOT emit** `flex:1` / `min-inline-size:0`. They are **structural
invariants** of the content-pivot pattern (same category as `flex-direction:row` /
`align-items:center`) — definitional, identical for every content-pivot, captured in decision 64
— not the tunable baked decisions the EMIT line is for (`paddingBlock=space.md`, density, wash,
radius · values a designer tunes at a checkpoint). Two decisive reasons: (1) **Topbar's**
content-pivot has the same `flex:1` but is **skip-emit** (decisions 46/37) — a `contentFlex`
token would force an incoherent asymmetry or break Topbar's skip-emit; (2) the flex drift is a
symptom of the **systemic R-EXPO-6 / F-DEMO-5** ("build emits token *values* but not the curated
prop-vocab / structure → RN hand-types"), a separate foundational decision (roadmap Open Question
#2), not an N+17 one-off. The structural values stay **hand-mirrored** in `list.tsx` (correct,
not debt), exactly like `flex-direction:row`. Recorded as **known-deferred to R-EXPO-6**.

The behavioural-delta sections cover only the **irreconcilable** gaps (`F-LISTITEM-ROLE-1`,
`F-FOCUS-1` · RN literally has no `listitem` role / no DOM focus model); the flex is a
**reconcilable pattern invariant**, identical on both platforms, so it is **not** documented as a
delta.
