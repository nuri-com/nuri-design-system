# N+45 · typography — de-fuse `size`×`emphasis` (orthogonal axis + the data-attr type scale)

**Status**: SHIPPED on `feat/n45-typography-defuse` (base `main` @ `b321690` · N+44 / #72).
De-fuses the typography axis: the fused `TypeKey` (`mdEm` = `md` + a weight flip · a 12-value enum) →
`{ size, emphasis }` as two orthogonal inputs, realized on web as `[data-type-style="{size}"]` (6 rules)
+ one source-order-last `[data-type-emphasis]` rule, and on RN as `typeStyle(size, emphasis)`. **NOT
byte-identical — computed-equivalent**: emphasis is a uniform `400→600` weight override, so the shape
de-fuses but no value moves. Records [decision 77](../decisionlog.md).

## Why this session

`TypeKey = TypeSize | ${TypeSize}Em` is a 6×2 Cartesian product flattened into a 12-value enum — it fuses
two orthogonal dimensions into one key, violating the DS's core orthogonality property ([P11](../packages/spec/pages/principles.html#p11-parsimony)).
It was the *cause* of the web/RN realization split the [N+43](./N+43.md) axis doc surfaced: web un-fused
`mdEm` via `expandTypeStep`, RN carried it fused. [Decision 76](../decisionlog.md) (N+44) reclassified the
typography axis as `size`; this completes it into orthogonal `size`+`emphasis`. Proven clean: emphasis is
**uniformly** semibold across all 6 sizes (size/line-height/letter-spacing identical), so the de-fusion
changes the *shape*, never the *values* — the rendered output is unchanged (computed-equivalence · the
N+30/N+31 flip pattern).

## The gate — computed-equivalence (NOT byte-identical), three independent legs

This is a deliberate API + CSS change, so byte-identity does NOT hold (the descriptors, `tokens.ts`,
`typography.css`, the RN `resolve` snapshot, and `button.md` all change on purpose). The proof is that
every `(size, emphasis)` renders the same computed style before/after:

- **Node harness** (`typography-cascade.test.js`, the dimension-cascade pattern): Guard A (the shape is 6
  `[data-type-style]` + 1 `[data-type-emphasis]` · the classes retired), B (the emphasis rule is
  source-order-LAST + equal-specificity · both declare `font-weight`), C (the de-fused rules, resolved
  through the live `var()` chain, reproduce the OLD 12-key fused composites EXACTLY · an
  **independently-restated oracle**), D (the per-size `--em-weight` primitives retired · emphasis is the
  uniform semibold). **Non-tautological** — reproduced both mutations: emphasis→regular weight fails C+D;
  a size-value drift fails C.
- **Real browser** (`typography-defuse-computed-check.html` · `getComputedStyle` via the real
  `<nuri-typography>` element path): **12/12 cells PASS** (6 sizes × {regular, emphasis}) — the cascade
  source-order tiebreak is real-engine-verified, not modeled. End-to-end on `demo.html`: 21 labels dispatch
  the data-attrs; the md emphasis label computes `17 / 21.93 / 600 / -0.34` — **byte-identical to the RN
  render-smoke snapshot** (web↔RN parity).
- **RN** — `render-smoke.test.tsx.snap` is **UNTOUCHED** (the resolved `Text` style didn't move); only
  `resolve.test.ts.snap`'s `typeStep` intermediate changed (`"mdEm"` → `{size:"md", emphasis:true}` · a
  deliberate `-u`). Plus an explicit oracle test: `typeStyle(size, true)` reproduces the old
  `typeStyle('{size}Em')` composite exactly (`resolve.test.ts`).

## Decision

[**decision 77**](../decisionlog.md) — typography `size`×`emphasis` de-fused; `{ size, emphasis }` orthogonal
inputs realized on web as `[data-type-style]` + one `[data-type-emphasis]` rule (source-order-last) and on
RN as `typeStyle(size, emphasis)`; behaviour-preserving (computed-equivalent · the values frozen); a
versioned post-freeze schema change (Guard F pin updated · §65); the type-scale **value** flip stays phase-4.
