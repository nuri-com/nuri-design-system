# Session N+5.5 · Orthogonal theme provider + classify-by-cascade emitter

**Status**: closed
**Type**: bridge

## Outcome

Bridge session between N+5 close and N+6 open. Two interlocking
architectural locks landed together — both expressions of the same
orthogonality principle decisions 1, 6, 9 and P5 already commit to,
at two layers:

1. **Consumer side · RN theme provider stays orthogonal**
   ([decision 27](../decisionlog.md#27-theme-provider--custom-orthogonal-not-cross-product-registry--n55),
   spec-only). A single `NuriThemeContext` with merge-on-override
   semantics; one entry per dimension; pre-computed (∏ dims) theme
   tuples rejected (672 themes at roadmap dimensions). The composite
   `NuriScope` mirrors web `<nuri-scope>` 1:1. Spec'd at
   [`lib/components/scope/README.md`](../lib/components/scope/README.md);
   working RN file deferred to the first multi-dim migration test
   (N+6 or later).
2. **Producer side · emitter shape derives from cascade**
   ([decision 28](../decisionlog.md#28-emitter-shape-derives-from-cascade-structure-not-from-a-hardcoded-list--n55)).
   `build/parsers/semantic.js` discovers each semantic var's
   dimensionality from which `[data-<dim>=…]` blocks declare it. The
   two hardcoded export lists are gone; future dimensions (font /
   density / neutral) auto-discover when their CSS blocks land;
   unmapped signatures fail the build with the offending signature
   in the message. Six flat accent exports collapse into a single
   nested `accent` keyed by
   `Record<Accent, Record<Theme, {...}>>`.
