### 1 · impl-guide density/neutral "Optional" → reserved/absent (self-contradiction)

- **`pages/implementation-guide.html`** · the cascade-mapping table cell for
  `data-density` / `data-neutral` said *"Optional in `NuriThemeValue` today."* —
  contradicting the page's OWN shipped-shape block and `scope.html:322-323`, which
  say density/neutral are **reserved · not entries**. `_shared.tsx`
  `NuriThemeValue = { mode, accent }` carries no density/neutral field. Cell now
  reads *"Reserved — not `NuriThemeValue` fields today; they join when their web
  tokens exist (P11)."* The only other "optional" on the page refers to the Button
  `accent` prop (correct · untouched).

### 2 · impl-guide Tier-2 skeleton stale (pre-decision-41)

- **`pages/implementation-guide.html`** · the Tier-2 self-scope "positive control"
  skeleton referenced `styles.label` (which does NOT exist in `button.tsx` — the
  label uses `typeStyle(LABEL_KEY[size])`) and omitted the per-size geometry. The
  skeleton now mirrors the live `button.tsx`: `GEOMETRY` / `LABEL_KEY` constants,
  the `size: sizeProp = 'md'` prop, inline `resolveToken` geometry
  (minHeight / paddingHorizontal / borderRadius), and `typeStyle(LABEL_KEY[sizeProp])`
  for the label (decisions 41 size matrix · 55 size-coupled label type). It stays a
  skeleton (illustrative · links to the real file) but is no longer contradicted by it.

### 3 · `DensityContext` name collision → `RowDensityContext`

- **`list.tsx`** · the list-local ROW-density context (`createContext<Density>('md')`,
  the `<nuri-list density>` projection onto rows) shared a name with the reserved
  scope theming `density` dimension — a latent trap when scope `density` lands.
  Renamed `DensityContext` → `RowDensityContext` (declaration + `List` Provider +
  `ListItem` `useContext`), with a comment stating it is row-density, NOT the scope
  dimension. RN-only context; web unaffected. grep confirms zero stale refs and no
  external importer.

### 4 · IconAvatar geometry sourcing (operator-decided · NOT an amendment to decision 50)

- **`icon-avatar.tsx`** · geometry was the lone hardcode (`size.lg` / `radius.full`
  literals) while `IconButton` dereferences emitted `iconButton.size` / `.radius`.
  At the checkpoint the operator chose **neither** leave-as-is **nor** couple to
  `iconButton.*` — instead dereference the **shared semantic scale**:
  `resolveToken(geomTokens, 'size.lg')` / `resolveToken(geomTokens, 'radius.full')`.
  This mirrors the web `.nuri-icon-avatar`, which consumes
  `var(--nuri-size-lg)` / `var(--nuri-radius-full)` DIRECTLY and deliberately does
  NOT alias icon-button's tokens (`icon-avatar.css:37-40,46-50,67-69,98-100`).
  IconAvatar skip-emits (0 decls · decision 50), so it has no component token of its
  own; sourcing from the shared scale removes the RN literal hardcode without coupling
  to IconButton (coupling would contradict the web and break R1 parity). Values
  unchanged (48 / 9999). **Decision 50 NOT amended** — IconAvatar stays a direct
  semantic consumer, exactly as the web CSS already documents.
