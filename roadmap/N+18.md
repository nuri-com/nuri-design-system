## Outcome

Topbar drops JS region-reparenting and becomes an **OPEN primitive on the content-pivot
anatomy** ([decision 64](../decisionlog.md) · [amendment 46.4](../decisionlog.md)): a named
`<nuri-topbar-content>` **layout pivot** (`flex:1; min-inline-size:0`) wraps ONLY the content;
**leading / trailing are plain positional siblings** around it — anything before the pivot is
leading, anything after is trailing. The pivot's `flex:1` absorbs the slack and pushes any
trailing to the row end **by construction**, so an empty side simply contributes nothing.
Identical web↔RN shape (the validated ListItem content-pivot · `list.tsx`), so it closes the
structural gap decision 64 names (R1).

This **resolves the R-EXPO-2 a/b/c cluster** (SPEC-FEEDBACK `F-DEMO-6`) **structurally**, not by
patching the old reparenting mirror:

- **(a) no phantom gap** — a positional empty side is absent; there is no empty side `<View>`
  to reserve a `gap` slot (the violation of amendment 46.3's RN-parity note).
- **(b) no collapsed trailing** — leading / trailing are self-sized positional controls, never a
  `flex:0` (basis-0) region that measured 0px and let icons overflow.
- **(c) non-text centre not `<Text>`-wrapped** — the lg-em title type applies to **bare text
  only**; a non-text centre (a segmented control) passes through (was: one `<Text>` wrapping all
  centre nodes · native-invalid for a non-text child).

### 1 · Web — `topbar.css` / `topbar.js`

- **Deleted**: the `connectedCallback` reparenting (`querySelector` + `createElement` +
  `appendChild` of `__start/__center/__end`), the `data-leading/-trailing` occupancy detection,
  the `display:none` empty-side collapse, and the `<nuri-topbar-start>` / `<nuri-topbar-end>`
  element defs + their `display:contents` rules.
- **Kept**: `center` → `data-center` and the `inset` / `inset-start` / `inset-end` →
  `data-inset-start/-end` reflection (declarative inset · [decision 46.1](../decisionlog.md#461-amendment--n66--inset-edge-padding-override)).
- **Pivot**: `nuri-topbar-content { flex:1 1 auto; min-inline-size:0 }`. The host is the flex row
  (`display:flex; align-items:center; gap:space-sm; height:size-lg; bg-canvas; text-primary`).
  Layout is pure CSS on BOTH `:defined` and `:not(:defined)` (no FOUC reflow · the List pattern).
- **center**: `nuri-topbar[data-center] > nuri-topbar-content { display:flex; align-items:center;
  justify-content:center; text-align:center }` — the content centres in the pivot.
- **inset**: base `lg` on the host; per-edge `[data-inset-start|end="xs|sm|lg"]` overrides at
  equal specificity. **Removed** the occupancy (`filled`→sm) and `center`→xs auto-resolution —
  both needed child-type inspection (dropped at 46.4; per-shape defaults move to recipes).
- **Title type**: topbar.js's `<nuri-topbar-content>` applies the `.nuri-type-lg--em` utility
  (the Typography SSOT · `styles/typography.css`) to a **bare-text** pivot only (element children
  → untyped passthrough · mirrors the RN `typeof children === 'string'` check). **Never** a
  hand-applied `--nuri-type-*` block ([decision 64](../decisionlog.md) · 53 · supersedes the
  font-bearing `.nuri-topbar__center` of [46.2](../decisionlog.md#462-amendment--n84--topbar-is-now-font-bearing-for-its-title)).
  `@layer tokens` stays **empty** (skip-emit intact).

### 2 · RN mirror — `topbar.tsx`

- `TopbarContent` = `<View {flex:1, minWidth:0}>`; bare strings → `<Typography size="lg"
  emphasis>` (REUSES the single text-style owner), else passthrough (R-EXPO-2c). `Topbar` renders
  positional `children` in a row `<View>`; `center` reaches the pivot via a `TopbarContext` (the
  RN analogue of the web `[data-center]` descendant selector · the `RowDensityContext` pattern).
- `TopbarStart` / `TopbarEnd` + the child-routing + the blanket `<Text>`-wrap are **gone**.
- `inset` is purely declarative (`space[insetStart ?? inset ?? 'lg']`) — base `lg`, no occupancy /
  center auto.
- **Height drift corrected**: `size.xl` (60px) → `size.lg` (48px) to match the web
  `var(--nuri-size-lg)` (operator-noted at the checkpoint · the mirror must mirror web · R1).
- **center mechanism (operator-approved · ship as-is)**: `center` centres the content WITHIN the
  pivot. With **symmetric** side controls (a segmented switch flanked by equal 48px icon buttons ·
  the common centred shape per 46.1) it reads **optically centred** (measured 0px offset on web).
  With **asymmetric** sides (the Cancel/Edit/Save action bar · Cancel 72px vs Save 58px) the title
  lands ~7px off true centre — 46.4's positional model removed the equal-flex side WRAPPERS that
  balanced asymmetric sides. The operator chose to **ship as-is** (the segmented case is perfect;
  true optical centre for asymmetric action bars becomes a future `screen-header` / `action-bar`
  recipe concern · P11), keeping web↔RN identical with no grid/side-region mechanism split.
