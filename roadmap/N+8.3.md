# Session N+8.3 · Type scale EMITTED as a directly-accessed namespace · one source, two readers

**Status**: closed (2026-05-31)
**Type**: pipeline emit + RN migration (reverses the `type`-pipelineInline
clause of [decision 34](../decisionlog.md#34-per-component-files--tokenpath-union--set-policy--pipeline-emit-shape--n603) ·
no new component surface · web UNCHANGED · one new emitted namespace)

## Outcome

[Decision 34](../decisionlog.md#34-per-component-files--tokenpath-union--set-policy--pipeline-emit-shape--n603)
classed the `type` primitive set as **`pipelineInline`** — present in the
CSS the web reads directly, but with **no `tokens.ts` namespace** for RN
to dereference. RN therefore **hand-declared** the metrics (the
`TYPOGRAPHY_SIZES` px map · xs 13 · sm 15 · md 17 · …), a parallel copy
that could silently drift from the `--nuri-type-*` source. N+8.2 left this
gap explicitly open and named its closure N+8.3.

N+8.3 closes it: the type scale becomes a **first-class emitted namespace**
in `build/tokens.ts` that RN **dereferences**, machine-checked against the
source primitives — exactly the *one source, two readers* model the icon
registry set ([decision 48](../decisionlog.md#48-typed-buildiconsts-emit--svgxml-over-the-shared-registry--one-registry-two-readers--n68)).
The web is **unchanged**: `.nuri-type-*` utility classes keep consuming the
`--nuri-type-*` primitives directly (zero-build · CSS is NOT regenerated
from the emit).

1. **`pipeline/parsers/type.js` emits a `type` namespace** from the
   `--nuri-type-*` primitives in
   [`styles/tokens-primitive.css`](../styles/tokens-primitive.css). It is a
   **directly-accessed, context-invariant** composite (like `icons`), NOT a
   cascade-resolved runtime/TokenPath set — no `(accent × theme)`
   cross-product. Per step `xs · sm · md · lg · xl · 3xl` (`2xl` reserved
   gap), emits `type.{size}` (regular) and `type.{size}Em` (the `--em`
   weight), each `{ fontSize, lineHeight, fontWeight, letterSpacing }`.

2. **Emit shape is DTCG typography composite** · `fontSize` → **px number**
   (rem × 16 · `1.0625rem → 17`); `lineHeight` → **unitless ratio,
   verbatim** (e.g. `1.29`); `letterSpacing` → **em number, verbatim**
   (e.g. `-0.02`; `xs = 0`); `fontWeight` → quoted weight literal (`'400'`
   regular · `'600'` em).

3. **lineHeight + letterSpacing stay RELATIVE — a11y rationale.** RN's
   `lineHeight` / `letterSpacing` are absolute dp that do NOT scale with
   `fontSize` or the OS `fontScale`; baking either to absolute in the emit
   would clip/cramp at large accessibility text sizes and break web↔RN
   *spacing-that-scales* parity (the web scales both natively). The single
   relative→absolute conversion lives in the consumer-side `typeStyle(key)`
   helper — also the future `* fontScale` point when Dynamic Type lands
   (P11 · not now).

4. **Drift guard** (`pipeline/tokens-parser.test.js`) re-derives every
   value from the `--nuri-type-*` source with its OWN conversion helpers
   (not the emitter's), asserts full coverage (every size × {regular, em}),
   per-step `deepEqual`, and that on-disk `build/tokens.ts` `.includes()`
   the freshly-emitted block. A renamed/dropped primitive throws at build.

5. **RN `Typography` dereferences the emit.** The hand-declared
   `TYPOGRAPHY_SIZES` map is **removed**; `Typography` reads
   `typeStyle(key)` over the emitted `type` namespace. `TypographyStack`
   composes `Typography` children unchanged. The `muted`/`emphasis`/`size`
   surface from N+8.2 is untouched.

  readers. Records (a) the **element-vs-values rule** — *the
  `<nuri-typography>` element is for author content; component-owned labels

## Anti-scope (held)

- **Web is UNCHANGED.** `.nuri-type-*` classes keep consuming
  `--nuri-type-*` directly (zero-build). CSS is **not** regenerated from
  the emit.
- **The SET_POLICY set is NOT removed.** `'primitive.type'` keeps its
  component-token-reference role; only the *no-runtime-namespace*
  implication reverses.
- **NOT a cascade/runtime set** — `type` is directly-accessed like `icons`;
  no `(accent × theme)` resolution, no TokenPath union entry.
- **lineHeight / letterSpacing are NOT baked absolute** in the emit — the
  conversion lives only in `typeStyle`.
- **Button + Tab font-token consolidation is NOT done here** — it is the
  N+8.4 follow-up (see below).

## Follow-up → N+8.4

**Button and Tab still carry their own duplicated font tokens** — Button's
`--nuri-button-{lg,md,sm}-font-size` + `--nuri-button-font-weight` and Tab's
`--nuri-tab-font-size` + `--nuri-tab-font-weight`, each aliasing a
`--nuri-type-*` primitive through a per-component token rather than reading
the shared scale directly. Consolidating those two onto the emitted scale —
per the element-vs-values rule in [decision 54](../decisionlog.md#54-type-scale-emitted-as-a-directly-accessed-namespace--one-source-two-readers--n83) —
is **N+8.4**. (**Topbar is NOT in scope**: it owns no font tokens — a
layout shell that expects a slotted `<nuri-typography>` title · decision 46.)
This session lands the scale and migrates the `Typography` primitive only.

> **Reversed in N+8.4** ([amendment 46.2](../decisionlog.md#462-amendment--n84--topbar-is-now-font-bearing-for-its-title) ·
> [decision 55](../decisionlog.md#55-component-owned-labels-source-type-from-the-shared-scale--button--tab--topbar--n84)):
> Topbar WAS brought into scope — it gained a default lg-em title type on its
> centre region. It still owns no `--nuri-topbar-*` tokens, but is now
> font-BEARING for its title (the slotted-`<nuri-typography>` stance is gone).
