## What N+25 did

The RN resolver was a mapping-table-written-as-code. S1 makes the mapping DATA and the dispatch a registry, under the snapshot/parity oracle that makes it provably byte-identical.

1. **Extracted the agnostic namespace→style mapping into DATA** ([`packages/factory/factory/resolve-map.ts`](../packages/factory/factory/resolve-map.ts), new). The old `resolveBox`/`resolveStack` walls of `if (ns.x) s.y = scale[ns.x]` become `STACK_FIELDS` / `BOX_FIELDS` — `Record<keyof StackNS|keyof BoxNS, Field>` tables (the `Record<keyof …>` makes the table **total over the namespace** — a new field is a compile error). `Field` is a tagged union: `scale` (value from a named scale) · `keyword` (a shared flexbox-keyword map) · `literal` (passthrough) · `flag` (boolean→keyword) · `expand` (one input → a multi-prop set · the `fill` tri-state). `ALIGN`/`JUSTIFY`/the `fill` expansion moved here as the `keyword`/`expand` data.
2. **A generic RN applier** ([`resolve.ts`](../packages/factory/factory/resolve.ts) `applyFields`) walks a table and emits a `ViewStyle` — the per-target EMIT. ⚠ It iterates the **table's** keys (fixed declaration order), not the input's, so the prop order reproduces the old if-walls byte-for-byte (pretty-format keeps key order). A `default → assertNever(f, 'field')` gives field-kind exhaustiveness (a new `Field` arm without a case is a compile error).
3. **Restructured `resolveNS` into a per-target resolver registry** (target §6.1 · roadmap §1). `RN_RESOLVERS: TargetResolvers` is one resolver per namespace; `stack`/`box` delegate to `applyFields`, `typography`/`palette`/`interactive` are bespoke. `RESOLVERS = { rn: RN_RESOLVERS } satisfies Partial<Record<'rn'|'web'|'css', TargetResolvers>>` — **shaped for the S2/S3/§9 columns, RN-only populated** (no speculative emit). `resolveNS` dispatches `RESOLVERS.rn[key]` over the present (authored-order) keys; the runtime `assertNever` backstop is retained for a non-schema key.
4. **Generalized `mergeNS`** over a canonical `NS_ORDER` tuple (was 5 hardcoded merges), with a type-level completeness check (`Exclude<keyof NS, NS_ORDER[number]> extends never`). Order is load-bearing (it fixes `node.view`'s key order downstream).
5. **`palette` + `interactive` + `typography` moved into the registry shape with logic VERBATIM** — bespoke mechanism, not data (decision 65: behaviour is the factory's). `resolvePalette` (theme matrix · `accent` self-scope · fg-by-scope) untouched.

`flattenPart` · `buildPartRecipe` · `toUnistylesRecipe` · `resolveAnatomy` · `recipeFor` · `ResolvedNode` · all public exports — **unchanged** (signature-preserving refactor; the parity oracle stays an INDEPENDENT second reader — not fused).

## The design choice — the table's neutrality (operator-confirmed at checkpoint)

The judgment S1 had to land + flag (it shapes S3): **the value-sources are the shared contract; the property SPELLING is the per-target emit's business.** The table's value-side is platform-neutral — scales referenced by NAME (the applier binds the tag to its scale repr), the flexbox keywords RN+CSS share verbatim (`flex-start`, `space-between`, `row`), the `1/0` flex values. The `prop`/`cases` identities are **RN-spelled** (`flexDirection`, `paddingHorizontal`, `borderRadius`). So at S3 the web resolver **ADDS a web emit that consumes THIS same table** (key → property-concept → value-source) + supplies its own spelling (camelCase→kebab + the logical-pad remap `paddingHorizontal`→`padding-inline`) — **it does not fork the table**. The alternative (canonical identities now, RN translating back) was declined: it front-loads a rename map with zero S1 benefit and no oracle to validate it (the snapshots exercise only the RN emit) → deferred to S3 as not-yet-consumed (P11).

## Exhaustiveness — demonstrated it bites (+ a real defect caught)

Pulling the `box` resolver and typechecking surfaced that the mapped type `{ [K in keyof NS]: … }` is **homomorphic** — it inherited NS's optional `?`, so every resolver was optional and the totality did **NOT** bite (typecheck passed with a resolver missing). Fixed with `-?` (`{ [K in keyof NS]-?: NSResolver<K> }`); re-verified: with `box` removed, `error TS2741: Property 'box' is missing … required in type 'TargetResolvers'`. Restored. The exhaustiveness now bites **per target** (the `assertNever` of old, now structural). Three compile guards in total: the registry totality (`-?`), the field-kind `assertNever`, and the `NS_ORDER` completeness check; plus the runtime `assertNever` backstop.
