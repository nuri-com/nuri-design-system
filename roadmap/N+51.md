## The one-liner

Adding an icon = **dropping a `.svg` in `packages/spec/icons/`**. The folder is the source of truth; the web
registry (`lib/components/icon/icons.js`), the `IconName` type, and the RN reader (`build/icons.ts`) are all
GENERATED from it — the A6 "add a thing = add data" ethos, applied to glyphs. This replaces the hand-curated
phosphor registry (17 glyphs × 3 weights) with a simpler model from the operator's new sources: **one drawing
per glyph · no weights · `currentColor` · md=24 / sm=18**, and drops the stale `@phosphor-icons/core` devDep
(Phase 4's "spec → no deps" · the icon half). The icon RENDER changes by design — this is NOT a byte-identical
session.

## What shipped

1. **The SoT folder** ([`packages/spec/icons/*.svg`](../packages/spec/icons)) — `apple` · `bitcoin` · `card` ·
   `euro` (the operator's seed sources · `viewBox="0 0 32 32"` · one or more `<path>` · `fill-rule`/`clip-rule`
   present on `card`/`bitcoin`/`euro`). The filename is the icon name. **This is the only hand-touched icon
   surface** — the catalog grows by dropping files, no session.

2. **The generator** ([`pipeline/parsers/icons.js`](../packages/spec/pipeline/parsers/icons.js) · rewritten ·
   still in spec's pipeline · NO postcss · SVG-text processing):
   - `readIcons(dir)` → reads each `.svg` (sorted · deterministic emit), `extractIconMarkup` pulls the inner
     `<path>`(s) verbatim (preserving `fill-rule`/`clip-rule`), **normalizes every `fill` → `currentColor`**
     (the `fill-rule`/`clip-rule` attrs are NOT matched — the `=` must follow `fill`), and **asserts the
     `viewBox` is `0 0 32 32`** (assert-uniform · a non-32 source fails LOUD). Builds `ICONS = { name: '<path…/>…' }`
     — one markup per glyph, NO weights (`ICON_WEIGHTS` retired).
   - `emitIconsJs` + `emitIconsTs` emit BOTH readers from it: the web reader
     [`lib/components/icon/icons.js`](../packages/spec/lib/components/icon/icons.js) (zero-build inline · now
     GENERATED) + the RN reader [`build/icons.ts`](../packages/spec/build/icons.ts) (`IconName` union +
     `Record<IconName, string>` — reshaped · no weight inner-map · `IconWeight` gone). One registry, two readers
     ([decision 48](../decisionlog.md)), both committed + byte-identical-guarded.
   - [`tokens-parser.js`](../packages/spec/pipeline/tokens-parser.js) Slice 6 now READS the folder → emits both
     (was: imported the hand registry).

3. **The web element** ([`prototype/primitives/icon.js`](../packages/prototype/primitives/icon.js)) —
   weight-coupling dropped (the `fill` attr REMOVED · resolves the deferred icon-arc `fill` first-bump gap ·

4. **The size, closed into the SHARED box axis** (the coordinator's re-checkpoint ask · NOT a bespoke icon
   rule): the glyph sizes through `box` width/height (the `size` scale), not the retired `.nuri-icon[data-size]`

## Three durable facts (don't lose these)

- **`size.sm` = 24** (was 28) — a scale refinement on the shared `size` leaf. `px-28` stays a primitive
  (`shell.css` consumes it directly).
- **The icon sizes via the box axis** — `<nuri-icon>` is now a `nuri-box` consumer (it carries the box
  namespace · the operator-ENDORSED call: "an icon is a box of a size" · box is the foundational web styling
  layer every real Nuri page links · the pre-upgrade skeleton covers the no-JS reserve · the only edge — token
  CSS linked but box.css absent → post-upgrade icon unsized — is the same dependency class the factory
  components carry). No bespoke `[data-size]` residue remains.
- **The naming OFFSET**: the icon's public `md` ↔ the `sm` size leaf (24) · icon `sm` ↔ the `xs` leaf (18).
  Anchors below element heights by design; documented in `icon.js`/`icon.css`/the descriptor.
