## The model (why the shapes differ)

Colour is **layered substitution**: accent fills the accent-portion of the palette UPSTREAM of mode; mode resolves
light/dark DOWNSTREAM. The runtime composes `chrome[mode] ⊕ accent[accent][mode]` — there is no `(accent × theme)`
cross-product. So:

- **chrome** stays `Record<Theme, {…}>` theme-major, **byte-identical** to the CSS-walked emit (chrome is
  accent-invariant). Re-sourced from `colours.ts` but routed through the SAME generic emit, so only the VALUES'
  provenance changed (the spelling is unchanged).
- **accent** becomes `Record<Accent, { role: hex | {light,dark} }>`: a FLAT SoT role (a single bare ref · the
  P4-frozen brand fill) → one `hex` string; a PAIR SoT role (`{light,dark}`) → `{light: hex, dark: hex}`. The
  flat-vs-pair distinction is read STRAIGHT from `colours.ts`'s authored shape (string vs object), never re-derived
  from CSS. This kills the duplication the cross-product carried (solid/solid-pressed/on-solid were byte-copied across
  light & dark).

The composed `(accent, mode)` slice `runtimeTokens` returns is **byte-identical** to today — only the accent SHAPE +
how `tokens.ts` is GENERATED change.

## The sweep correction — a CI-gated consumer the grounding (+ the sub-agent sweep) both missed

The brief's grounding said *"the only accent-shape consumer is `runtimeTokens` + the `RuntimeTokens` type."* The
sub-agent sweep added `resolve.test.ts` (an expected rn test oracle) but ALSO certified `@nuri/doc` as safe. **The
`doc` gate refuted that.** `@nuri/doc`'s [`makeColorResolver`](../packages/doc/pipeline/docs.js) (`docs.js:154`)
resolved a colour `TokenPath` at the default scope by indexing the accent **cross-product**
(`specTokens.accent[DEFAULT_ACCENT][DEFAULT_THEME][leaf]`) — it broke hard ("`accent.solid` dangled at the default
scope"), failing the doc build + all three Guard-G drift tests. Folded in: the accent branch now collapses the
two-layer role (`typeof role === 'string' ? role : role[DEFAULT_THEME]`), the same composition the runtime does. The
resolved hex is unchanged, so **`packages/doc/generated/` re-emits byte-identical**. (`foundations-ir.js` was already
SoT-shape-aware — it reads `def.light` off the `colours.ts` pair, not the build cross-product.) The only residual
cross-product reference is an illustrative snippet in `packages/doc/archive/*.html` (frozen historical material · left
untouched). **Lesson: the grep-sweep is necessary but not sufficient — running all 5 gates is what caught it.**
