## Decisions locked

- **Decision 58** · Screen + Scroll · the per-screen scaffold. Navigator owns the
  safe-area (frame / React Navigation), so the TabBar is a SIBLING of Screen, not
  a child, and the primitives stay inset-agnostic. Scrolling is a COMPONENT in RN
  (`ScrollView`), never a `View` style — which is *why* Scroll is its own
  primitive and `overflow` is never a Box prop (R1). No `<nuri-app-shell>` (it
  would BE the navigator = a framework, no clean RN home). Both skip-emit.
- **Decision 59** · Spacer (grow / fixed `size`) + Typography `align`. Spacer
  chosen over a general `grow` prop "for now, see what emerges" (the general grow
  prop stays deferred · P11). `align` → `text-align`, host flips to `display:block`.
- **Decision 60** · Box + Stack `fill` → `flex: 1 0 auto` (not `1 1 0`, which
  would clip when content exceeds the viewport). The web analogue of RN's
  `contentContainerStyle={{ flexGrow: 1 }}`; Scroll becomes a flex column to host it.
- **Decision 61** · Spacer `grow` (1–4) → proportional `flex-grow` (renamed from
  `weight` · 2026-06-01 · font-weight collision). A positive RN `flex` IS
  proportional `flexGrow`, so it maps 1:1.
- **Amendment 46.3** · Topbar collapses an empty side region in non-center layout
  (it no longer eats the host `gap` slot · the phantom leading inset).
- **Amendment 57.1** · Playground pins all THREE chrome dimensions
  (theme+neutral+**accent**), and the shell chrome renders on neutral GRAY while
  the device mockup stays cream.

## The scaffold (decision 58)

`<nuri-screen>` = `display:contents` host over an inner `flex:1` column.
`<nuri-scroll>` = `flex:1; min-block-size:0; overflow-y:auto` (a flex column as
of decision 60). Padding for the scrolled content goes on a `<nuri-box>` INSIDE
the scroll (the `contentContainerStyle` analogue), never the scroll box itself.
Safe-area is owned ONCE upstream (the device frame's structural inset rows in the
playground; `SafeAreaProvider` + React Navigation in RN) — no CSS var, no inset
props on the primitives.

## fill (decision 60) · the chain

`Scroll(flex col) > Box[fill](flex:1 0 auto · becomes a flex column) >
Stack[fill](flex:1 0 auto) > … <Spacer> … buttons`. The Spacer then has slack to
push trailing content to the bottom. `1 0 auto` (grow 1, shrink 0, basis auto)
fills when content is short AND keeps content height when tall, so the Scroll
scrolls instead of clipping.

## Spacer (decisions 59 / 61)

Behaviour-free, host-sized (Separator's shape). Grow (no `size`) → `flex:1`;
fixed (`size`) → a definite inline/block extent per `direction`; `grow` 1–4 →
proportional `flex-grow` (scoped `:not([size])`). In the vault a `grow="1"`
spacer above the total + a `grow="2"` spacer above the fund actions split the
free space 1:2.

## Frictions

- **F-TEXTALIGN-RTL** (candidate) · Web `align` is logical `text-align: start|end`
  (RTL-aware); RN `textAlign` has no logical start/end (auto|left|right|center|
  justify), so the RN mirror maps to PHYSICAL left/right (LTR). True RTL would
  flip via `I18nManager.isRTL` / `writingDirection` — logged, not solved (P11).
- **Box `fill` web↔RN delta** · on web Box is `display:block` so `fill` must also
  switch it to a flex column; an RN `<View>` is already a column, so the RN
  mirror only needs the grow part. Same props, different mechanism (R1 budgeted).
- No new friction *codes* minted beyond the textAlign-RTL candidate; the rest is
  props-1:1 with budgeted mechanism deltas, which R1 already covers.
