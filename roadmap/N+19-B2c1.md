## The channels (coordinator-agreed design · schema = decisionlog 65.4, authored in B2c·2)

`interactive` is a **structured per-part opt-in, not a boolean**. Interaction decomposes (65.3 §6 ·
resolver-model §5) into independent effects, each its own gate. **`interactive` owns the effect-set**;
box stays purely geometric (42.1/60.1), palette purely colour (65.3 §6) — `pressColor` is the one
effect palette *realizes* (colour is palette's by contract). Affordances are automatic with
interactivity; only the state effects are opt-ins.

| channel          | gate (web)             | effect                          | realized in    | witness (live · on main)        |
|------------------|------------------------|---------------------------------|----------------|---------------------------------|
| pressScale       | `data-press-scale`     | `:active transform: scale()`    | interactive.css | Button · TabBar                 |
| pressColor       | `data-press-color`     | `:active` bg swap               | **palette.css** | Button · list-interactive-item  |
| disabledOpacity  | (automatic)            | `:disabled`/`[aria-disabled]` opacity | interactive.css | Button                    |
| affordance       | (automatic)            | cursor · transition · focus-ring | interactive.css | every interactive surface       |

WHY a per-part opt-in: the effects are **proven independent on main** — Button = scale + colour ·
TabBar = scale only (no bg swap · decision 56) · list-interactive-item = colour only (no scale ·
decision 52). A **static surface carries no marker** (no `.nuri-interactive` class, no gate), so it
never matches `:active` — non-reactive is the default (Tabs / Topbar chrome stay inert).

Every value mirrors the live **Button** (button.css = the SoT witness · decision 48): press-scale
`--nuri-interaction-press-scale` (0.97) · disabled-opacity `--nuri-interaction-disabled-opacity`
(0.4) · focus `--nuri-focus-ring`. Consumed as **bare interaction constants directly** (decision-45
carve-out · the TabBar precedent), not aliased into `--nuri-interactive-*`. **No new tokens.**

## What shipped

### 1 · The namespace — `lib/components/interactive/interactive.css` (new · zero-build · skip-emit)
Class + `data-*` dispatch **on the painting node** — the merged-node model (B1.5 §4.2 · the
palette/box precedent): NO `<nuri-interactive>` element, NO interactive.js; the `.nuri-interactive`

`:disabled`/`[aria-disabled]` opacity (button.css:274).

## The proof (visual checkpoint · preview MCP · operator-approved)
The merged node `class="nuri-box nuri-stack nuri-palette nuri-interactive" data-variant="solid"
data-press-scale data-press-color` presses **pixel-identical** to a live `<nuri-button variant="solid">`,
verified by computed style **and** CSSOM rule resolution: resting bg `rgb(190,170,255)` · fg
`rgb(56,27,106)` · radius 6px · min-height 48px all identical; both `:active` paths resolve to scale
`0.97` + pressed-bg `#b39ff3` + focus-ring `#ae91ff`; **parity holds in light AND dark** (same token
refs · the lilac brand triple is theme-frozen by design). The only visible difference is the label
font weight (merged = body, Button = semibold) — *expected*: font is typography's namespace, not one
of interactive's channels. Static inertness confirmed: no ungated `.nuri-palette:active` rule exists,
and the live Tabs tablist carries no interactive marker → no `:active` swap. Console clean.

## Handoff to B2c·2 (re-emit) → B2c·3 (factory)
The interactive namespace is real on web: the press effects merge onto one node, gated, and a static
surface stays inert. **B2c·2** authors decisionlog **65.4** (the `interactive` schema — the channel
set above) and re-emits the descriptor speaking `interactive.{pressScale,pressColor,disabledOpacity}`
+ the affordance flag; it also decides `interactive`'s pipeline registration (the COMPONENTS entry left
open here). **B2c·3** builds the factory (one merged painting node per anatomy node · wires
Pressable/native-button + `cursor`/`transition`/`:active`/disabled/focus) and rewires the RN mirrors —
`resolvePalette(state)` already returns `pressedBg`; the factory feeds it the `pressed` flag the
`data-press-color` gate models on web.
