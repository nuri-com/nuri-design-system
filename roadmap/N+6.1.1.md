## Why N+6.1.1 not N+6.2

Foundation surface completeness before the layout primitives
that consume the dimension vocabulary land. N+6.2's
Stack/HStack/VStack will reference `space.md` / `size.xl` /
potentially `radius.md` via their `gap` / `height` / `radius`
props; the documentation surface a composing agent reads when
wiring those primitives should be present (and discoverable via
NAV) before the consumers arrive.

The reorg (4 pages nested under `dimension/`) and the radius
vocabulary both fit cleanly into the same session — both are
follow-ups to the N+6.1 mechanics (SET_POLICY auto-promotion ·
classifier array-entry · consumer-side static-vs-dynamic split ·
foundation page template). Bundling them avoids a third bridge
session for the same domain.

X.Y.Z numbering: N+6.1.1 is the first derivative of the N+6.1
semantic dimension thread (N+6.0 → N+6.0.x ran 5 derivatives ·
N+5.6 → N+5.8 ran 3). The decimal-derivative pattern stays
elastic to follow-ups that don't yet warrant a fresh major
session.

## Continuation-agent pattern note

**This is the first non-fresh-agent continuation since N+5.5.**
The same agent that closed N+6.1 picked up N+6.1.1 to save
onboarding cost on a tight same-domain follow-up. Operator
justification: the foundation template + SET_POLICY mechanism +
classifier extension + consumer-side split — all four mechanics
N+6.1.1 leans on — were the agent's own work three turns
earlier. A fresh agent would have re-read all four pattern
surfaces (the SET_POLICY registry · the classifier array-entry
extension · the per-leaf TS-type emit · the migration-pair
consumer split) before adding the radius leaf to each. The
continuation skipped that re-reading and went straight to
extension.

**Outcome**: clean ship, no broken patterns. Two minor
in-pass-fixed drifts:

1. P9 dimension row was missing `--nuri-space-*` + `--nuri-size-*`
   (latent from N+6.1 — fresh-agent N+6.1 audit missed it too).
   Caught by R13's cross-ref sweep, not by continuation-agent
   memory.
2. `--nuri-radius-full: 9999px` primitive declaration left
   shadowed by the new semantic `100%` (faithful-to-brief
   interpretation · documented as a friction · could be cleaned
   up in a future session if parsimony spirit becomes
   pressing). Not a drift the audit would have caught either
   way.

**Generalised conclusion**: the continuation-agent pattern is
viable for tight same-domain follow-ups where the agent itself
authored the patterns being extended. The risks (skipped
audit-style re-reading) are mitigated by the closeout-audit
subagent, which runs against the diff regardless of who
authored it. A future coordinator may use this signal: fresh
agent for new directions (the n=9 N+5.5 → N+6.1 streak); same
agent for tight extensions of the prior session's patterns. The
extension window probably closes once the prior session's
patterns become foundational — at that point the
continuation-agent overhead (re-pulling stale context) starts to
exceed the savings.

## Post-close coordinator polish

After close, operator observed a visual bug on `.nuri-tag` (the
draft/planned/exploratory chips): rectangular tag boxes rendered
as **ellipses** instead of pill shapes. Root cause: `border-radius:
100%` interprets relative to box dimensions — for a rectangular
box wider than tall, 100% on the horizontal axis equals the full
width and on the vertical axis equals the full height, producing
an ellipse. The legacy primitive `--nuri-radius-full: 9999px`
worked because the browser clamps oversized border-radius to
`min(width/2, height/2)`, saturating to a pill for any box shape.
