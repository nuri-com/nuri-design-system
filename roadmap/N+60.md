## The design call — the round-trip is REMOVED, not masked (coordinator-ratified)

3b·1 re-sourced colour by **Object.assign-over**: walk the CSS cross-product (`resolveSemanticCrossProduct`), then
overwrite the colour groups with the TS-flattened values. That leaves the CSS walk running (its dimension output is
discarded). For dimensions the literal mirror would do the same — but then the cascade walk still *reads* the
dimension cells, so a "no longer reads `semanticRules`" claim is cosmetic.

Instead, `resolveSemanticCrossProduct` is **dropped from the RN value path entirely**. The orchestrator assembles

```js
const resolved = { ...colourTokens.chrome, ...dimensionTokens };
```

from the two TS resolvers — chrome (theme-major cross-product node · 3b·1) + dimensions (singletons · new) — and
hands `accent` to `emitTokensTs` as the two-layer table. After this the RN value arm reads **no CSS**: the dimension
arm genuinely never touches `semanticRules`, so **Guard D is honest, not a coat of paint**. `classifyAll(semanticRules)`
stays ONLY for the GROUP STRUCTURE (chrome/accent/dims leaf names + order · the cascade classifier) + the web
`token-vars` emit — both relocate with the web projection in **3c** (the brief scope line). The `type` composite still
resolves its weight against the primitive map (its own SoT · out of this slice).

## How the dimension arm flattens

`resolveDimensionTokens(dims)` resolves each `space`/`size`/`radius` leaf to the final CSS literal the live var()
chain bottoms out at — the value RN sees:

- `{ ref: N }` → `${px[N]}px` (the px primitive · value == name · [decision 32](../decisionlog.md)).
- `{ value: 0, unit: 'px' }` → `'0'` (the collapsed-gutter sentinel · unitless · decision 32).
- `{ value: 9999, unit: 'px' }` → `'9999px'` (the pill sentinel · amendment 36.1).

Dimensions are context-invariant, so each leaf is returned in `resolveSemanticCrossProduct`'s node shape with the
IDENTICAL literal in every `(accent, theme)` cell; the generic singleton emit collapses the redundant cells back to
one value per leaf — byte-identical to the old cascade walk. The TokenPath union is enumerated the same way: chrome +
accent role names (camelCased) from `colours.ts`, then `space`/`size`/`radius` keys from `dimensions.ts`, in the
tokens.ts emit order — no `classifyAll`.

## interaction.ts — STOPPED + surfaced (no SoT invented)

Per the brief: `pressScale 0.97` / `disabledOpacity 0.4` have **no TS home**. They live ONLY in
`styles/tokens-primitive.css` (`--nuri-interaction-*`); `interactive-effects.ts` holds the token PATHS
(`token: 'interaction.pressScale'`) + the gate names (`press-scale` / `disabled-opacity`), never the numeric values.
Inventing a SoT here is a separate decision (P11) — so `build/interaction.ts` is **untouched** (still CSS-sourced).
**Its TS-sourcing is the FIRST STEP of 3b·2b** — a 2-constant micro-SoT in `pipeline/` → re-source byte-identical →
then the relocation rides on top. NOT a separate micro-slice.
