# Session N+9 · TabBar · icon-only bottom destination switcher

**Status**: closed (2026-05-31)
**Type**: new component surface (compound · two light-DOM custom elements ·
navigation chrome · EMITs one baked structural token · DISTINCT from
[Tabs](../decisionlog.md#43-tabs--first-multi-element-compound--first-box-composition-consumer--n65) ·
[decision 56](../decisionlog.md#56-tabbar--icon-only-bottom-destination-switcher--distinct-from-tabs--emit-bar-height--direct-semantic-items--n9))

## Outcome

TabBar is the icon-only **BOTTOM** navigation bar — the app-level destination
switcher behind the My-vault / Coin / Activity screens. It is a compound of two
light-DOM custom elements sharing one piece of state (the selected `value`):

- **`<nuri-tab-bar value="…">`** — the controller. Owns the selected value,
  builds the `<nav class="nuri-tab-bar">`, reparents the authored items into it,
  defaults `value` to the first item, and toggles each item's `active` attribute
  on click.
- **`<nuri-tab-bar-item value=… name=… [label]>`** — one destination. Builds an
  inner `<button class="nuri-tab-bar__item">` wrapping a `<nuri-icon size="md">`,
  sets `data-active`/`aria-current="page"` + the icon `fill` when active, and
  derives an accessible name (`label || name.replace(/-/g, ' ')`).

Both are `display: contents` (invisible in layout) and defer-loaded; one IIFE
registers the item then the bar. The compound mirrors
[Tabs](../decisionlog.md#43-tabs--first-multi-element-compound--first-box-composition-consumer--n65)'
value/active **mechanics** but shares **none** of its semantics — see the a11y
section.

## EMIT · one baked structural token (decision 52)

Unlike the skip-emit chrome primitives (Topbar / IconAvatar own zero component
tokens), TabBar bakes **one** fixed structural decision worth
machine-checking: its height. `--nuri-tab-bar-height: var(--nuri-size-xl)`
mirrors Topbar's chrome row so top and bottom chrome share one rhythm, and is
EMITted to [`build/components/tab-bar.ts`](../build/components/tab-bar.ts) as
`tabBar.height: 'size.xl' as const satisfies TokenPath`. The RN bar reads it via
`resolveToken(tokens, tabBarTokens.height)`. No prefix collision —
`--nuri-tab-bar-` is distinct from Tabs' `--nuri-tabs-`. The first chrome
primitive to EMIT a single structural token rather than skip-emit.

## Direct-semantic items · zero per-item tokens

The per-item treatment reads the shared chrome + interaction vocabulary directly
in `@layer rules` (the IconAvatar / Topbar precedent ·
[decision 50](../decisionlog.md#50-iconavatar--static-decorative-twin-of-iconbutton--composes-icon-directly--skip-emit--avatar-name-reserved--n69)),
NOT via per-item component-token aliasing — so the bar emits exactly **one**
declaration. Operator-locked visual spec (zero new tokens):

| state               | icon weight | color                | scale       |
|---------------------|-------------|----------------------|-------------|
| selected (active)   | fill        | `--nuri-text-primary`| —           |
| not selected        | regular     | `--nuri-border-strong`| —          |
| pressed (transient) | unchanged   | `--nuri-text-muted`  | press-scale |

Icon weight flips via the `fill` attribute tab-bar.js sets on the selected
item's `<nuri-icon>` (md → regular at rest, md+fill → fill when selected ·
[decision 38](../decisionlog.md#38-icon-component--phosphor-source--nuri-icon-name-nuri-facade--2-size--fill--registry-based-js-dispatch--n63)).
**Pressed has NO background change** — only the shared Button press-scale
(`--nuri-interaction-press-scale` · 0.97) plus a colour shift to text-muted; the
weight is untouched. Pressed is transient and applies to whichever item is held
regardless of selection, overriding the resting colour by source order (equal
0-2-0 specificity to the active rule). Reuses Button's press-scale directly
under the bare-constant carve-out
([decision 45](../decisionlog.md#45-interaction-family-primitives--cross-component-design-constants----nuri-interaction---n65-post-close-coordinator-polish)) —
no tab-bar press token.

## A11y · F-TABBAR-ROLE-1 (operator-confirmed at checkpoint)

Web: `<nav aria-label>` + native `<button>` per destination + `aria-current=
"page"` on the selected one — **router-agnostic** (the bar emits selection, it
does not navigate), and distinct from a `role="tablist"`. RN has no peer for
"current page in a nav landmark," so the mirror approximates with
`accessibilityRole="tab"` + `accessibilityState={{ selected }}` — the same
honest-platform-gap pattern as F-LISTITEM-ROLE-1. The icon-only target reuses
**F-ARIA-LABEL-1** and the shared **F-SELECTED-VALUE-1** controlled-selection
contract. The operator confirmed this model "as shipped" at the visual
checkpoint. Recorded in [`docs/RISKS.md`](../docs/RISKS.md) under R1.

## Full-width decision (operator-confirmed at checkpoint)

Because the host is `display: contents`, the built `<nav>` shrink-wrapped to its
icons (~120px) inside the centred preview stage. Both options were surfaced; the
operator chose **`inline-size: 100%`** so the bar spans its container
edge-to-edge (a bottom navigation bar fills the screen width). After the change
the bar spans the full stage with its items at equal `flex: 1` widths. **No**
`position: fixed` / safe-area inset and **no** top border — routing + viewport
pinning + dividers belong to the consuming app, not the primitive (P11 ·
[decision 49](../decisionlog.md#49-separator--standalone-generic-1px-display-primitive--author-placed--horizontal-only--n69)).

## Anti-scope (held)

- **No speculative additions** — no badge / label / tone / max-width / new
  glyphs. Icon-only, three-to-four destinations, one active.
- **No `position: fixed` / safe-area inset** — viewport pinning belongs to the
  consuming app, not the primitive.
- **No router assumption** — the bar emits selection via `value`; it does not
  navigate (F-TABBAR-ROLE-1).
- **Did not touch `<nuri-tabs>`** — TabBar is a separate surface with separate
  semantics; the in-page segmented control is untouched.
- **No top border** — dividers are author-placed Separators (decision 49).
- **No per-item component tokens** — items are direct-semantic; the only emitted
  token is the bar height.

## Frictions

- **F-TABBAR-ROLE-1 (new)** · web↔RN a11y gap: web's `<nav>` +
  `aria-current="page"` destination-switcher role has no RN
  `accessibilityRole` peer; RN approximates with `tab` + `selected`. Honest
  platform gap, modeled on F-LISTITEM-ROLE-1. Recorded under R1 (frictions 15
  → 16).
- **R1 (web↔RN parity)** · the bar height crosses the boundary as a TokenPath
  (`tabBar.height`); the per-item direct-semantic colours + press-scale are
  re-expressed faithfully on both readers.
- No other new friction codes minted.
