# Session N+15 · Accent×theme self-scope cascade clobber · descendant-combinator dark blocks (#4b/#6b)

**Status**: open (PR in review · 2026-06-01)
**Type**: fix (web CSS cascade · `styles/tokens-semantic.css` + ledgers · no `lib/` / `build/` token change · byte-identical emit)
**Branch**: `fix/accent-theme-cascade` (based on `origin/main`)

## Outcome

A pre-existing **accent×theme cascade bug**: a Tier-2 component that
**self-scopes its accent** (sets `data-accent` on its inner element, NOT
`data-theme`) showed the **LIGHT** accent value even inside a **dark** ancestor
scope. In the playground My-vault **dark** device frame the swap IconButton
(`variant="solid" accent="neutral"`) and the IconAvatars went **dark-on-dark
(invisible)**.

### The bug

Accent×theme lives in `styles/tokens-semantic.css` as an attribute-only cascade
(decision 57 dropped `:root` so nested scopes re-match). The dark-theme accent
overrides were **compound** selectors — `[data-accent="X"][data-theme="dark"]`
(block 4/6) — requiring **both** attributes on the **same element**. A Tier-2
self-scope only sets `data-accent` on its inner element; `data-theme` lives on a
themed **ancestor**. So:

- The **light** base accent block (3/5) re-declares the accent custom props at
  the **element** level → clobbers the dark values the element would otherwise
  **inherit** from the ancestor.
- The **dark** compound block (4/6) **doesn't match** the element (no
  `data-theme` on it) → the dark values never re-apply.

Result: a self-scoped accent inside a dark scope resolves to the **light** cell.

### The fix · approach A (descendant-combinator dark blocks)

Two **descendant-combinator** blocks added — `[data-theme="dark"]
[data-accent="X"]` — so an ancestor's dark theme re-applies the dark accent
values to a self-scoped descendant:

- **`#4b`** (after block 4 · `neutral`) — all 6 adapting tokens (`fg` · `solid` ·
  `solid-pressed` · `on-solid` · `bg-subtle` · `bg-subtle-pressed`).
- **`#6b`** (after block 6 · `lilac`) — the **3 adapting** tokens (`fg` ·
  `bg-subtle` · `bg-subtle-pressed`); the P4 **FROZEN brand** triple
  (`solid` / `solid-pressed` / `on-solid` — identical light+dark) is
  intentionally **omitted** so the frozen invariant is never re-asserted.

### Why A over B (candidate B rejected)

- **B** (accent-as-pointer + theme-resolves indirection) **breaks
  classify-by-cascade** in `pipeline/parsers/semantic.js` — `--nuri-accent-*` must
  classify to signature `accent,theme`; a semantic→semantic pointer that the
  resolver (primitives-only) can't chase would throw at build. **The emit
  (`build/tokens.ts`) is the RN deliverable — non-negotiable.**
- **A is parser-transparent**: `selectorMatches` counts `[`=2 and resolves
  #4b/#6b to the **same (accent, dark) cell** as #4/#6 with **identical values** →
  `build/tokens.ts` **byte-identical**, zero emit change.
- A fits the N+10 attribute-only model (decision 57 dropped `:root`; it did **not**
  ban combinators · #4b/#6b add no new dimension).

### Known limitation (revisit-trigger)

A descendant combinator matches **ANY** dark ancestor, not the **NEAREST** theme.
A self-scoped accent inside a **light** scope nested inside a **dark** scope
resolves **dark** (wrong — nearest is light). CSS can't express "nearest scope"
without a per-element theme. **No current consumer nests opposite themes around a
self-scoped accent** (the playground scopes ONE theme per device frame), so
accepted per **P11** and documented as a revisit-trigger
([RISKS F-SCOPE-3](../docs/RISKS.md)). The clean answer when it lands is the
per-element-theme · RN single-context model (decisions 27/62) — which is **immune**
to this bug (positive control · validates the model).
