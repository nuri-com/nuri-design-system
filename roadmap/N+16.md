Per-fix conformance (web SoT ↔ mirror ↔ consumer resolution):

### 1 · Button — drop base `flex: 1` (R-EXPO-3 · F-DEMO-2)

- **Web SoT**: `button.css` styles `.nuri-button` as `display: inline-flex` with a
  `min-height` and **no flex-grow** — a content-sized leaf control.
- **Mirror (was)**: `styles.base` baked `flex: 1` (over-fit to the matrix's
  `direction="row"` equal-width demo). In a COLUMN that grows the button on the MAIN
  (vertical) axis — nothing like the web, and it would fight a `grow` spacer.
- **Now**: `flex: 1` removed; `styles.base` is alignment/direction only
  (`alignItems` / `justifyContent` / `flexDirection`). Full width in a column comes
  from the parent Stack's default `alignItems: 'stretch'` (exactly the web inline-flex
  behaviour: natural width in a row, full width in a column). An inline comment
  documents the deliberate absence so a future agent doesn't re-add it.
- **Consumer resolution (F-DEMO-2)**: "ported `Button` **without** `flex: 1` —
  content-sized, relying on the parent column's default `alignItems: 'stretch'`."

### 2 · Scroll — default `contentContainerStyle={{ flexGrow: 1 }}` (R-EXPO-4 · F-DEMO-3)

- **Web SoT**: `scroll.css` `.nuri-scroll` is `flex:1` (definite height) +
  `display:flex; flex-direction:column`, so a `flex:1 0 auto` box fills it; the file's
  own comment names `contentContainerStyle={{ flexGrow: 1 }}` as the RN analogue
  ([decision 60](../decisionlog.md#60-box--stack-fill--grow-to-fill-a-flex-parent--the-scrollview-contentcontainer-pattern--n11)).
- **Mirror (was)**: a bare `<ScrollView style={{ flex: 1 }}>` whose header claimed the
  `Box fill` CHILD was "the contentContainerStyle analogue (Box fill == {flexGrow:1})".
  A `ScrollView` lays children in a SEPARATE content container that is content-sized by
  default, so a `Box fill` (`flexGrow:1`) child had no free space to grow into and
  collapsed to content height — the render disproved the header's claim.
- **Now**: `Scroll` adds a `contentContainerStyle?: StyleProp<ViewStyle>` prop and
  applies `contentContainerStyle={[{ flexGrow: 1 }, contentContainerStyle]}` (default,
  overridable · mirrors the existing `style` pattern). This grows the content container
  itself (the faithful RN realization of the web's definite-height flex-column scroll);
  the grow stays OPT-IN per child — a child still only fills if it carries `fill`, but
  now it has the viewport height to grow into. The header was rewritten and explicitly
  annotates the old "Box fill == {flexGrow:1}" claim as disproven by the render.
- **Consumer resolution (F-DEMO-3)**: "`Scroll` sets `contentContainerStyle={{ flexGrow: 1 }}`
  by default (overridable) — the faithful RN realization of the web's definite-height
  scroll + filling box."

### 3 · Separator — axis-absolute `width:'100%'` + `flexShrink:1` (R-EXPO-5 · F-DEMO-4)

- **Web SoT**: `separator.css` is `inline-size: 100%` (axis-ABSOLUTE) + `block-size: 1px`,
  so the hairline flanks correctly in a column AND a row.
- **Mirror (was)**: `height:1` + `alignSelf:'stretch'`. `alignSelf:'stretch'` is
  axis-RELATIVE (fills the CROSS axis): full-width in a column, but **0 width in a ROW**
  (cross axis is vertical there, so the explicit `height:1` wins) — so a horizontal
  hairline in a row container (e.g. the My-vault swap affordance) vanished.
- **Now**: `alignSelf:'stretch'` replaced with `width:'100%'` + `flexShrink:1` — the
  faithful translation of `inline-size:100%`: full width in a column, shrinks-to-share
  alongside a sibling in a row, keeps the 1px height. The header's "stretched on the
  cross axis" line was corrected to axis-absolute width; an inline comment records why
  `width:'100%'` (not `alignSelf:'stretch'`).
- **Consumer resolution (F-DEMO-4)**: "`width: '100%'` + `flexShrink: 1` — the faithful
  translation of `inline-size:100%`."
