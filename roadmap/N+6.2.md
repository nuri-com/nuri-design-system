**Status**: closed (2026-05-28)

## Outcome

The single highest-friction missing surface since N+4 closes
structurally. **Stack** ([`lib/components/stack/`](../lib/components/stack/))
and **Box** ([`lib/components/box/`](../lib/components/box/)) ship
as the first two layout primitives under
[decision 37](../decisionlog.md#37-layout-primitives-consume-semantic-vocabulary-via-prop--no-component-token-aliasing--n62).

API · operator-locked at session open:

```
Stack:
  direction?: 'column' | 'row'                            (default 'column')
  gap?:       'xs' | 'sm' | 'md' | 'lg' | 'xl'            (5-leaf subset of space)
  align?:     'start' | 'center' | 'end' | 'stretch' | 'baseline'
  justify?:   'start' | 'center' | 'end' | 'between' | 'around'
  wrap?:      boolean
  as?:        string                                      (host-resolved)

Box:
  padding?   / paddingX?  / paddingY?:                    'xs' | 'sm' | 'md' | 'lg' | 'xl'
  paddingStart? / paddingEnd?:                            'xs' | 'sm' | 'md' | 'lg' | 'xl'
  paddingTop? / paddingBottom?:                           'xs' | 'sm' | 'md' | 'lg' | 'xl'
  center?:    boolean                                     (margin-inline: auto)
  as?:        string                                      (host-resolved)
```

Pure layout — NO `background`, NO `border`, NO `radius` props on
either. Color / border / radius derive from consumer components
(Card / Field / Button-pattern with `accent` prop + variant →
resolved bg), not from layout primitives. The deferred props live
in the [`roadmap/index.md`](./index.md) Open questions list,
evidence-gated on the first real consumer.

## Decisions locked

- **[Decision 37](../decisionlog.md#37-layout-primitives-consume-semantic-vocabulary-via-prop--no-component-token-aliasing--n62) ·
  Layout primitives consume semantic vocabulary via prop · no
  component-token aliasing.** The pattern: empty `@layer tokens`
  block; attribute-selector CSS in `@layer rules` dispatches the
  prop value directly to a `var(--nuri-space-*)` reference. The
  per-component pipeline emitter extends with a third branch
  (empty `@layer tokens` → skip emit), so `build/components/stack.ts`
  and `build/components/box.ts` deliberately don't ship. Component
  page template adapts decision 24 by skipping
  Variants / States / Theming sections (layout primitives have
  none of those axes) per decision 19's template-flexibility
  precedent.

## Frictions surfaced

- **Pipeline empty-emit case · resolved in-pass**. The
  per-component emitter at
  [`pipeline/parsers/components.js`](../pipeline/parsers/components.js)
  was written for the n=1 (Button) case in N+6.0.3 with an
  implicit assumption of ≥1 declaration per component. The
  empty-case handling lives at the orchestrator level
  ([`pipeline/tokens-parser.js`](../pipeline/tokens-parser.js))
  rather than inside the emitter — the emitter never sees empty
  input. Trade-off: orchestrator-level handling means the
  emit-vs-skip decision sits outside the emitter's contract,
  which is arguably less clean. Alternative would be `emitComponentTs`
  returning `{ source: null }` for empty input; both shapes are
  defensible. The orchestrator-level handling won because it
  surfaces the skip in the build log (where the operator looks)
  without changing the emitter's stable signature.

- **Button-stretching across rows in the migration test ·
  consumer-side stretch policy**. Pre-N+6.2 the `.playground-row
  nuri-button { flex: 1 1 0 }` rule stretched buttons across each
  row. Stack itself doesn't impose a child stretch policy — Stack
  stays opt-in on what its children do, matching CSS flex
  semantics. Considered: (a) add a `stretch` prop on Stack that
  sets `flex: 1` on its children · rejected as speculative without
  a real second consumer; (b) keep the row-stretch pattern as a
  page-local CSS rule on the migration test (one-line rule that
  the consumer owns, not the primitive) · **accepted**; (c) drop
  the stretch and let buttons size to content · rejected because
  the matrix's visual contract is "two equal-width buttons per
  row". The accepted rule lives at
  [`docs/migration-tests/button-matrix/index.html`](../docs/migration-tests/button-matrix/index.html)
  page-local `<style>` block:
  `nuri-stack[direction="row"] > div > nuri-button { flex: 1 1 0; }`.
  The principle holds: Stack ships layout primitive · stretch
  policy is consumer-owned · one line of CSS at the call site is
  cheaper than a `stretch` prop without n≥2 consumers asking for
  it.

- **RN spec home for layout primitives · deferred Open question**.
  Today Stack + Box RN definitions live inline in the migration-
  test pair. n=1 (one consumer with two co-located primitives) is
  too thin to decide the long-term home (peer
  `lib/components/<name>/<name>.tsx`? separate `lib/spec/`
  namespace? inline TS in `<name>.css` via a future parser-
  extracted code-block?). Logged in
  [`roadmap/index.md`](./index.md) Open questions. Re-evaluate
  post-N+6.2 when n≥2 RN-component-spec consumers exist.

- **F-LAYOUT-1 web-side scope larger than `index.tsx`**. The
  session brief named the RN side as the consumer refactor target
  (R7 framed around `index.tsx` styles). The web side
  ([`index.html`](../docs/migration-tests/button-matrix/index.html))
  had identical hand-rolled layout styles
  (`.playground-row-group` + `.playground-row`) — both sides
  needed the retirement for the structural close to feel
  complete. Web-side refactor folded into R7 in-pass.

## Why N+6.2 not N+6.3

N+6.3 (the next component page · likely Tag or IconButton) almost
certainly composes Stack/Box for its internal layout: Tag has a
label + optional close affordance (HStack-shaped); IconButton has
icon-only content (Box-shaped center). Without layout primitives
first, N+6.3 would either hand-roll layout (returning to
F-LAYOUT-1 friction) or wait. Sequencing is structural — Stack/Box
are the **prerequisite for any composition-heavy component**, and
that's what makes N+6.2 the right sequence position rather than a
bridge after N+6.3.

After N+6.2 closes, N+6.3 lands against:

- Working Stack + Box web custom elements + RN component sketches
- The decision 37 layout-primitive pattern (Tag may or may not
  follow it · Tag has internal anatomy with a label + close
  button so it's more anatomy-driven than parametrized · likely
  follows the Button-pattern with component-tokens, but Stack/Box
  available for its internal composition)
- The retired F-LAYOUT-1 friction (consumer composition is now
  ergonomic in both web + RN)
- The opportunity to add a Behavioural-delta section to the
  component template (R1 mitigation · F-PRESSED-1 + F-FOCUS-1 +
  F-DISABLED-1's cursor as the n=1 content) — the second
  component is the n=2 confirmation point for whether the
  template section is the right surface.

## Pattern note · continuation-agent vs fresh-agent

This session shipped under a fresh-agent pattern. The
N+6.1.1 retrospective documented the continuation-agent pattern
(same agent across N+6.1 → N+6.1.1) as a tight-extension play; the
operator picked fresh-agent for N+6.2 on the reasoning that
N+6.2 introduces NEW patterns (layout-primitive class · empty-emit
case · adapted component-page template · RN spec home Open
question · F-LAYOUT-1 retirement) where fresh-agent eyes might
catch blind spots a continuation-agent misses. Outcome: clean
ship; the layout-primitive pattern lands without rediscovering
any of N+6.1's mechanics (auto-promotion via SET_POLICY is NOT
applicable here — Stack/Box have no component-tokens to promote)
and without claiming new ground in semantic vocabulary (the
5-leaf subset is a prop-surface decision, not a vocabulary
decision; the underlying space scale is unchanged).
