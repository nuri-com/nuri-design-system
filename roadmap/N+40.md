## The problem this closes

After the N+38 flip, Slice 8 (`derivePalette` → `build/palette.ts`, a `@nuri/spec` export the RN
runtime consumes) asserted its contract against the GENERATED `lib/components/{palette,typography}.css`
(§74 moved the witness there when the recipe-CSS cross-checks retired). But the A3 carve (N+41) moves
that namespace CSS into `@nuri/prototype` — and `spec`'s build still reading it would invert the DAG
(`spec → prototype`). This session re-points the assertion one step further UP the cascade: at the **TS
SoTs the namespace CSS is itself generated from** (`palette-surface.ts` + `typography-axis.ts`), so
`spec`'s build stops reaching into the soon-to-move namespace CSS.

## What shipped

the cells STILL come from `PALETTE_CONTRACT`; the CSS reads were always pure ASSERTIONS, now repointed
to the true SoT. That is strictly BETTER — it catches contract-vs-true-SoT drift where before it only
caught contract-vs-generated-artifact.

1. **`derivePalette` re-sourced** ([`pipeline/parsers/palette.js`](../packages/spec/pipeline/parsers/palette.js)).
   Signature `derivePalette({ surface, typographyAxis }, { classifiedGroups })`.
