# N+44 · interactive — single-source the opt-in axis (one SoT, two projections)

**Status**: SHIPPED on `feat/n44-interactive-single-source` (base `main` @ `72270f4` · N+43 / #71).
Reshapes the **interactive** axis SoT so the web CSS, the web factory gate, and the RN applier all
PROJECT from one source — restoring the one-SoT-two-projections invariant ([decision 70](../decisionlog.md))
for interactive, the one axis that was genuinely multi-sourced. **Behaviour-preserving** — `interactive.css`
re-emits byte-identical, the RN snapshots stay byte-identical; only the *source* of the mapping moved.
Records [decision 76](../decisionlog.md) (the §73 taxonomy refinement · single-source ≠ shape).

## Why this session — the axis-doc critique

The N+43 axis docs read as a "CSS guide" because two axes (interactive · typography) presented their
*web CSS* as their source. interactive genuinely WAS multi-sourced: the opt-in → (gate · property ·
trigger · realization) mapping was hand-written in THREE readers that could drift —
`pipeline/parsers/interactive-css.js` (web CSS), `factory/factory.js` (the web gate attrs), and
`packages/rn/factory/resolve.ts` (the RN state patches). This session makes interactive obey the same
invariant box/stack do (one agnostic table, both targets project). It must land before the doc redesign
so the doc can render interactive agnostically from one source. (typography turned out already
single-sourced — see the taxonomy note; its doc reclassification + the uniform doc redesign follow.)

## What shipped

1. **The SoT reshaped** ([`packages/spec/pipeline/interactive-effects.ts`](../packages/spec/pipeline/interactive-effects.ts)) —
   from `effects[]` (CSS-rules-as-data) into:
   - **`opts`** — the 3 agnostic opt-ins (`pressColor` · `pressScale` · `disabledOpacity`), each
     `{ trigger, gate, rn, web }`. `rn` is **pure data** the appliers interpret (no closures):
     `{ prop, from }` reads the resolved node (pressColor → `node.pressedBg`), `{ prop, token, shape? }`
     reads the theme baseline (`shape:'scale'` → RN's `[{ scale }]`). `web` is the opt's CSS rule, or
     `null` where it lives in another axis (pressColor's `:active` bg-swap is **palette's**).
   - **`webChrome`** — the web-only realization with no agnostic input / no RN analog (affordance ·
     focus · disabledGuard).
   - **`webOrder`** — the interleaved web emit order. **LOAD-BEARING**: pressScale before disabledGuard
     (the equal-specificity `transform` pair · source-order decides → a disabled control never scales).
   - **`effects`** — a DERIVED projection of the above (the transient @nuri/doc bridge · see below).
2. **The web CSS emitter** ([`interactive-css.js`](../packages/prototype/pipeline/parsers/interactive-css.js)) —
   `loadInteractive` reads `{ opts, webChrome, webOrder }`; `emitInteractiveCss` walks `webOrder`,
   pulling each rule from `webChrome[name]` or `opts[name].web`, assembling the selector from the
   structured `on` parts. **`interactive.css` re-emits byte-identical** (the generated header held to
   the committed bytes · the SoT-name refresh rides a future re-emit, per the byte-identity gate).
3. **The RN applier** ([`resolve.ts`](../packages/rn/factory/resolve.ts)) — imports `opts`; `flattenPart`
   replaces the 3 hardcoded `if`s with a generic walk over `opts` (trigger-gated · realize from
   node/theme); `buildPartRecipe`'s compoundVariants walk `opts` too, **preserving pressColor's
   per-palette-variant `pressedBg` loop** (the `from`-arm · node-derived). The RN snapshots are the
   oracle — **byte-identical**. A compile-time `_OptKeysMatchSchema` pins `keyof opts` to `InteractiveNS`
   (drift → a type error, not a silent gap).
4. **The web factory** ([`factory.js`](../packages/prototype/factory/factory.js)) — replaces the
   hardcoded `setAttribute('press-scale')` / `press-color` with a derivation: for each gated opt that is
   on, set `camelToKebab(key)` (= `opts[key].gate`). No attr string is hardcoded. The factory is
   browser-runtime (can't import the `.ts` SoT), so the gated set is `INTERACTIVE_GATES` (exported),
   **pinned to the SoT by Guard E**.
5. **Guard E** ([`interactive-css.test.js`](../packages/prototype/pipeline/interactive-css.test.js)) —
   asserts the factory's `INTERACTIVE_GATES` equals the SoT's gated opts (`gate !== 'auto'`) both ways,
   `camelToKebab(key) === opts[key].gate` for each, and every other opt is `'auto'`. The one seam the
   browser-runtime factory can't close by import is closed by the guard. (Guards A–D unchanged — they
   pass against the byte-identical CSS.)

## The doc-consumer conflict (the brief vs the live tree)

The brief said reshape `effects` away AND make "no doc-gen changes." But `@nuri/doc` (merged to `main`
hours earlier · N+43) consumes `effects` in `axis-ir.js#interactiveAxisIr` / `build.js` /
`docs-drift.test.js`, and it is a **CI-gated job with a byte-identical Markdown gate**. The brief's DoD
omitted that gate — the freshly-merged consumer wasn't accounted for. Surfaced to the operator, who
chose: **keep `effects` as a DERIVED projection**
(`webRules = { ...webChrome, pressScale: opts.pressScale.web, disabledOpacity: opts.disabledOpacity.web };
effects = webOrder.map(name => ({ name, ...webRules[name] }))`). `opts` stays THE single source; `effects`
is its web projection in the legacy shape, kept so @nuri/doc re-emits byte-identical with **zero
doc-gen change**. The web rules stay STRUCTURED (`on:[{attr,state}]`, not flat selector strings) so the
projection is faithful (the doc's `gateOf` reads `p.attr`). Proven **deep-equal to the original `effects`
array** before building. **Tracked for deletion** when the doc redesign re-sources the interactive page
onto `opts` (the next arc).

## The dual-stripper constraint (documented in the SoT header)

`interactive-effects.ts` is strip-loaded by BOTH @nuri/prototype's line-oriented `stripTypes` AND
@nuri/doc's brace-aware `stripTsData`. To strip cleanly under both: every `type` alias is single-line;
NO `const NAME: T =` annotations (use `as const satisfies <NamedType>`); the `satisfies` target is
**comma-free** (the doc strip's regex stops at a comma → `satisfies OptTable`, not
`satisfies Record<string, Opt>`). Pre-empted and verified against both strippers.
