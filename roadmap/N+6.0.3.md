# Session N+6.0.3 · POC pipeline rework · per-component files + set-policy + TokenPath union

**Status**: closed (2026-05-28)
**Type**: bridge (POC · RN consumer contract · pipeline-side rework)

## Outcome

The pipeline ships three TS surfaces for the RN consumer instead of
one. `build/tokens.ts` keeps only **runtime sets** (chrome + accent
today — the context-dependent vocabulary the classify-by-cascade
emitter discovers from `[data-*]` blocks); per-component numerics
move out of the emitter into `build/components/<name>.ts` (today:
`button.ts`); the discriminated union of every runtime-set leaf
lives at `build/token-paths.ts` and is consumed by every per-
component file via `import type { TokenPath }`. The pre-N+6.0.3
hardcoded `BUTTON_BASE` constants block in
`build/parsers/semantic.js` — which held `minHeight: 56` /
`paddingX: 16` long after the [`N+6.0`](./N+6.0.md) primitive
rename moved CSS to `--nuri-px-{60,18}` — is **structurally killed**:
`button.ts` now reads from the live CSS source on every build, so
the same drift class can no longer accumulate.

A **set-policy registry** at `build/parsers/semantic.js` (`SET_POLICY`)
is the single declarative extension point. Every set carries three
flags: `cascadeVarying` (mechanically derived by the classifier),
`runtime` (appears in tokens.ts + TokenPath union), `pipelineInline`
(references resolve to literal values at build). An **auto-rule**
forces cascade-varying sets to `runtime: true / pipelineInline: false`
(their value depends on consumer context, so no terminal literal
exists to inline). Context-invariant sets are operator-pickable
between `(runtime, !pipelineInline)` and `(!runtime, pipelineInline)`;
orphans (neither flag) and auto-rule violations throw at the
classifier. Today's initial registry locks the 6 primitive sets as
`pipelineInline` (colour · px · radius · type · font · duration) and
relies on the auto-rule for the 2 semantic sets (chrome · accent).
Future cascade dimensions auto-promote at the next build with no
policy edit.

The new public-emit contract lands as
[**decision 34**](../decisionlog.md#34-per-component-files--tokenpath-union--set-policy--pipeline-emit-shape--n603)
appended after
[decision 33](../decisionlog.md#33-semantic-token-docs--format-b-verbose-dual-mode-for-context-dependent-tokens--n601).
The classifier internals
([decision 28](../decisionlog.md#28-emitter-shape-derives-from-cascade-structure-not-from-a-hardcoded-list--n55))
stay intact — decision 34 documents the orchestrator-level emit
contract layered ON TOP of decision 28's classifier. No procedural
enforcement cascade this session (decision 34 is surface-localised
to `build/parsers/*` + component CSS; apply the [N+6.0.1.1
pattern](./N+6.0.1.1.md) at a follow-up `.1` session if/when a new
component CSS surfaces the need).

A ~10-line `resolveToken(tokens, path)` **sketch** lives in
`docs/migration-tests/button-matrix/index.tsx` to demonstrate the
consumer-side dereference. The production implementation is the
consuming app's responsibility (Unistyles theme function · custom
Context selector); the Nuri spec describes the contract, not the
runtime. The migration pair typechecks against the new shape
(`button` + `TokenPath` + the existing `chrome` + `accent` runtime
namespaces) — `npx tsc -p docs/migration-tests/button-matrix/tsconfig.json`
exits 0.

No CSS edits this session
([`styles/*`](../styles), [`lib/components/button/button.css`](../lib/components/button/button.css)
stay untouched per the anti-goal — the POC validates the new

audit). No new tokens, no new components, no new pages. The
`button.css` consumes `--nuri-px-60` / `--nuri-px-18`, so the
emit reads `minHeight: 60` / `paddingX: 18` — the drift kill is

## Ship list

1. ✓ **R1** · **SET_POLICY mechanism**. [`build/parsers/semantic.js`](../build/parsers/semantic.js)
   gains an inline `SET_POLICY` constant + a `resolveSetPolicy(setKey,
   cascadeVarying, policy?)` central enforcer + a `primitiveSetFor(cssVar)`
   lookup. `classifyAll` extended to attach `.setKey + .policy` to
   each classified group, throwing on the three named failure modes
   (orphan · auto-rule violation · missing entry). Lives inline next
   to `GROUP_NAMES` per the implementer pick — one file fewer, same
   config-near-code pattern.
2. ✓ **R2** · **`tokens.ts` emitter rewrite**. `emitTokensTs` filters
   classified groups by `policy.runtime` before emit (today: chrome
   + accent both qualify under the auto-rule). The pre-N+6.0.3
   `BUTTON_BASE` constants block + `fmtButtonBase` helper inside
   `build/parsers/semantic.js` are **deleted**. Header rewritten to
   drop the F-FONT-1 caveat and point at the new per-component path
   + TokenPath union.
3. ✓ **R3** · **per-component emitter**. New [`build/parsers/components.js`](../build/parsers/components.js)
   exposes `readComponentTokens(css, prefix)`, `resolveComponentValue(cssVar,
   value, ctx)`, `emitComponentTs(componentName, decls, ctx)`, and
   `emitTokenPathsTs(classifiedGroups)`. Walks the `@layer tokens`
   block of a single component CSS, dispatches each declaration per
   `SET_POLICY` (literal numeric via primitive-chain walk · TokenPath
   string for runtime references · pure literal pass-through). Type
   inference for the terminal primitive var name drives formatting
   (dimension → number after stripping `px`/converting `rem×16` ·
   `fontWeight` → quoted string · etc.).
4. ✓ **R4** · **`build/components/button.ts` emitted**. Matches the
   brief's expected shape character-for-character: 7 literal fields

   `accent.*` · `softBg/softBgPressed/softFg` → `chrome.*`). The
   `BUTTON_BASE.minHeight = 56` / `paddingX = 16` drift is killed:
   the emit always reads `--nuri-px-{60,18}` from the live CSS.
5. ✓ **R5** · **`build/token-paths.ts` emitted**. Discriminated string
   union over every runtime-set leaf; derived from the same
   `classifyAll` pass that emits tokens.ts. 18 union members today

## Why N+6.0.3 not N+6.1

POC validates the SHAPE before [N+6.1](./index.md#whats-next--session-n61--semantic-sizing--spacing--button-refactor)
introduces new tokens (semantic spacing + sizing) against it.
Bundling means the audit can't disambiguate "is the shape right"
from "are the new tokens right". Sequencing keeps each session's
audit focused.

After N+6.0.3 closes, N+6.1's brief naturally consumes the new
shape: `semantic.space` + `semantic.size` join `SET_POLICY` with
operator-locked `runtime: true / pipelineInline: false`, the new
tokens flow into `tokens.ts` as additional namespaced exports,
`button.css` refactors to reference them (`padding: var(--nuri-space-md)`
etc.), and the per-component emitter re-emits `button.ts` with
TokenPath strings where there were literals before (`paddingX` flips
from `18` to `'space.md' as const satisfies TokenPath`).

X.Y.Z numbering: N+6.0.3 is the third derivative of N+6.0's
primitive direct-pixel migration thread. N+6.0.1 locked the CSS-side
Format B convention; N+6.0.1.1 propagated it to the spec-authoring
skill surfaces; N+6.0.2 closed the loop on the docs-page surface;
N+6.0.3 reworks the pipeline emit shape so [N+6.1](./index.md#whats-next--session-n61--semantic-sizing--spacing--button-refactor)
has somewhere to land. Four derivatives, four distinct audit
surfaces, one decision number added (34 · the public-emit
contract); no amendments to existing decisions.
