## Outcome

Shipped the **first two List-family primitives** — `<nuri-separator>`
and `<nuri-icon-avatar>` — as standalone components the future List /
ListItem will compose, without building List/ListItem itself.

**Separator** ([`lib/components/separator/`](../lib/components/separator/))
is a prop-free `<nuri-separator>`: a generic, author-placed **1px
hairline** (`background: var(--nuri-border-subtle)` · `block-size: 1px` ·
`inline-size: 100%`) painted **directly on the host** (no
`display:contents` wrapper — the host *is* the line), with
`role="separator"` + `aria-orientation="horizontal"` and no
radius/margin/variant/inset/thickness. It **closes the long-deferred
Stack-`divider` open question by reframing**: a divider is just a
separator the author drops between rows — not a Stack prop, not a
`<nuri-divider>` component
([decision 49](../decisionlog.md#49-separator--standalone-generic-1px-display-primitive--author-placed--horizontal-only--n69)).

**IconAvatar** ([`lib/components/icon-avatar/`](../lib/components/icon-avatar/))
is `<nuri-icon-avatar name [variant] [accent] [fill]>` — the **static
decorative twin of IconButton** (an icon centred on a coloured circle ·
`size-lg` 48px · `radius-full` · the same geometry as IconButton) and
the **second direct `<nuri-icon>`
consumer**, now allowed because N+6.8 closed F-ICON-RN-1 and the glyph
path works both sides. It consumes the **same** semantic surface
vocabulary IconButton uses — solid→`accent-solid`/`on-solid` ·
soft→`bg-strong`/`text-primary` · ghost→transparent/`text-primary` —
plus an avatar-only `subtle`→transparent/`border-strong` (like ghost,
but the lowest-emphasis glyph · no IconButton counterpart) —
**directly** in `@layer rules` (the Tabs/Box attribute-dispatch
precedent), with **zero interactivity**: no `disabled`/`onPress`/`label`,
host `aria-hidden="true"`
([decision 50](../decisionlog.md#50-iconavatar--static-decorative-twin-of-iconbutton--composes-icon-directly--skip-emit--avatar-name-reserved--n69)).

Both components have an **empty `@layer tokens`** block → the pipeline's
skip-emit path detects 0 declarations and writes **no**
`build/components/{separator,icon-avatar}.ts` (decision 37 pattern · no
duplicate of `icon-button.ts`). **Zero new tokens.** The **Avatar** name
stays reserved for a future polymorphic primitive.

## Decisions locked

- **[Decision 49](../decisionlog.md#49-separator--standalone-generic-1px-display-primitive--author-placed--horizontal-only--n69) ·
  Separator · standalone generic 1px display primitive · author-placed ·
  horizontal-only.** (a) A **standalone element**, not a Stack `divider`
  prop — keeps Stack pure (no child-wrapping JS / RN render-map), makes
  the rule a visible inspectable DOM node, and serves non-Stack contexts
  (any author-placed hairline). (b) **Prop-free + horizontal-only** —
  ship exactly the 1px hairline current consumers need (P11); a vertical
  variant waits for a real row-layout consumer. (c) **Skip-emit, zero
  new tokens** — consumes `--nuri-border-subtle` + a 1px literal
  directly; no `--nuri-separator-*` surface to alias. Anti-scope: no
  orientation/vertical, no thickness/variant/inset, not a Stack prop, no
  `<nuri-divider>` name.

- **[Decision 50](../decisionlog.md#50-iconavatar--static-decorative-twin-of-iconbutton--composes-icon-directly--skip-emit--avatar-name-reserved--n69) ·
  IconAvatar · static decorative twin of IconButton · composes Icon
  directly.** (a) **Decorative, not interactive** — IconButton minus the
  button: no `disabled`/`onPress`/`label`, host `aria-hidden="true"`
  (the glyph is decoration beside real text, the row owns the semantics).
  (b) **Same semantic surface, consumed directly** in `@layer rules` —
  not a re-aliased component-token set; reusing IconButton's exact
  variant→surface mapping prevents drift and proves "same resolveToken
  surface, two components". (c) **Single-size-locked + skip-emit** —
  IconAvatar is IconButton's exact static twin, so it mirrors that
  geometry leaf-for-leaf: a `size-lg` (48px) circle holding a
  `<nuri-icon size="md">` (28px) glyph (P11 · no new token · reuses
  IconButton's leaves); empty `@layer tokens` → no
  per-component file. Anti-scope: no size prop, no interactivity, no
  label, no component-token emit, the Avatar name reserved. Second direct
  `<nuri-icon>` consumer (allowed post-F-ICON-RN-1 closure · N+6.8).

## Why Separator is a standalone element, not a Stack `divider` prop

The external-project Stack spec carried a `divider: boolean` that wraps a
thin rule between children. Reframing it as a standalone
`<nuri-separator>` keeps Stack **pure** — no child-wrapping JS on web, no
RN `render`-map that interleaves separators between mapped children — and
makes the rule a **real inspectable DOM node** the author places
explicitly, which also serves non-Stack contexts (a hairline under a
heading, between two cards). The `divider` prop is retired and the
`<nuri-divider>` name dropped; Separator subsumes both.

## Why IconAvatar consumes the semantic surface directly (no component-token emit)

IconButton already proved the variant→surface mapping
(solid/soft/ghost → accent-solid/bg-strong/transparent). IconAvatar is
the **same surface, no interaction** — re-aliasing those values into a
fresh `--nuri-icon-avatar-*` component-token set would duplicate
`icon-button.ts` and create a drift seam (two places to keep the variant
matrix in sync). Consuming the semantic tokens **directly** in
`@layer rules` (the Tabs/Box attribute-dispatch precedent) keeps exactly
one authored copy of the mapping, and the empty `@layer tokens` makes the
component skip-emit. The RN side reuses the literal `iconButtonBg` /
`iconButtonFg` helpers (with `pressed=false`) for the same reason.

## Why single-size-locked (no size prop)

IconAvatar is IconButton's **exact static twin**, so it mirrors that
geometry leaf-for-leaf rather than inventing its own: the same `size-lg`
(48px) container and the same `<nuri-icon size="md">` (28px) glyph
IconButton uses. Reusing IconButton's leaves means **no new token** (P11 ·
ship what's consumed) and a single locked size. A size scale (sm/md/lg)
is deferred to the roadmap until a real consumer needs more than one
avatar size.

## Frictions

- **F-DECORATIVE-1 (new · documented, not a blocker)** · the web/RN
  a11y-hiding idioms differ: web hides a decorative subtree with a single
  host `aria-hidden="true"`, RN needs **both**
  `accessibilityElementsHidden` (iOS) and
  `importantForAccessibility="no-hide-descendants"` (Android). Captured
  on the IconAvatar page's Behavioural-delta section; not a renderer gap,
  just a per-platform attribute pair.
- **F-ICON-RN-1 stays CLOSED** · IconAvatar is the first *new* Icon
  consumer after N+6.8's closure and inherits the working glyph path
  (composes `<Icon size="md">`), exercising the renderer beyond
  IconButton exactly as N+6.8's "remaining open thread" anticipated.
- No new RN-runtime friction minted — the proof stays type-only against
  the same shims.

## Why N+6.9 ships only two building blocks (not List/ListItem)

The List family is the next real-component step, but List/ListItem need
their constituent parts to exist and be documented first. Separator and
IconAvatar are the two leaf primitives a transaction/activity row
composes (the hairline between rows, the leading glyph on a row); minting
them as standalone, independently-documented components keeps each shape
small and lets the ListItem session focus purely on the
row-composition mechanism rather than re-deriving sub-parts. Separator
also retires a long-open question (Stack `divider`) as a side effect.
