## The smell this fixes

The accent semantic layer was **role-major** — `accent[role][accentName][theme]` with the accent
names (`neutral` / `lilac`) baked into the type (`type AccentLeaf = { neutral; lilac }`). Adding an
accent (slice 2) meant **editing all six role entries + widening the type** — the wrong unit of
change. Reshaped to **accent-major**: each accent is **one object**, each role either a flat `string`
ref (theme-INVARIANT · the P4-frozen brand fill) or a `{ light, dark }` pair (theme-ADAPTING ·
`dark.ref ≠ light.ref`). The names are **out of the type** (`Record<string, Record<string, AccentRole>>`),
so slice 2 is "add one object," not six edits + a type change.

## Commit 2 — the chrome unwrap (consistency · operator addition)

Now that accent holds bare ref strings, `chrome` is unwrapped the same way so the rule is
uniform across the file: **a bare `string` is a reference; `{ value }` is a literal.** After
this, no SoT data wraps a ref in `{ ref }` — chrome + accent are bare strings, the ramps
(`neutralScales` / `lilac` / the alpha overlays) keep their `{ value }` literals.

- **`colours.ts`** — chrome leaves `{ light: { ref: 'neutral.1.light' }, … }` → `{ light:
  'neutral.1.light', … }`. Refs verbatim; the pair structure kept (chrome is theme-only ·
  every role is a light/dark pair · no flat-collapse — flat was an accent-INVARIANCE concept,
  it doesn't apply to chrome). A shared `type RefPair = { light: string; dark: string }` is
  introduced and reused by both chrome (`Record<string, RefPair>`) and `AccentRole` (`string |
  RefPair`). `ColorLeaf` / `ThemedLeaf` stay for the ramps (still `{ value }` literals); the
  now-unused `{ ref }` arm of `ColorLeaf` is noted as vestigial (a possible later micro-prune).
- **`semantic-css.js`** — `chromeDecls` reads the bare string and wraps it `{ ref }` so
  `refToVar` is unchanged (the same path `accentDecls` uses).
- **`colour-semantic.test.js`** — `sotRefFor` chrome leg: `chrome[k][theme].ref` → `chrome[k][theme]`.
- **`foundations-ir.js`** — the `@nuri/doc` Chrome row: `def.light.ref` → `def.light`.

**Chrome reader-sweep:** the same 3 SoT-shape readers as accent (`chromeDecls` · `sotRefFor` ·
`foundations-ir.js` Chrome row). All other `chrome.*` references read the RESOLVED contract
(the `'chrome.bgStrong'` token-PATH strings in `build/palette.ts` · `theme.ts` · the RN resolve
tests · `docs.js` · `axis-ir.js`) — unaffected. No 4th reader.
