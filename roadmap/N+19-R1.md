## The flow (what "finding the flow" surfaced)
- The descriptor's `palette.variant:'solid'` resolves through `build/palette.ts` to the SAME TokenPaths
  the hand-written `build/components/button.ts` emits. palette.ts and button.ts are independently
  emitted from one CSS SoT, so factory==hand-written is a real **cross-consistency** proof, not a
  tautology.
- The merged-NS model is clean: per part, base ⊕ each selected axis patch; disjoint namespaces never
  collide; `interactive` on `base.root` + per-variant `palette` compose into the §11 per-variant
  pressed-bg compounds with no per-component logic.

  recipe with **no structural friction** — a later Unistyles adoption is a swap, not a rewrite.

## Findings (surfaced, not fixed — Guard F · candidates for the first versioned bump)
1. **No transversal interaction emit.** `pressScale`/`disabledOpacity` are embedded per-component
   (`build/components/{button,icon-button}.ts` = 0.97/0.4), but the model (resolver-model §1/§7/§11)
   treats interaction as a transversal baseline. The factory CARRIES the baseline in `theme.ts`,
   **pinned to the contract embeds** (`button.pressScale`/`disabledOpacity` · asserted → can't drift).
   A transversal `build/interaction.ts` (or an interaction block in tokens) would let every consumer
   read one source.
2. **`subtle` fg-only.** resolver-model §11's sketch wrote `surface.subtle = {bg:'transparent', fg:…}`;
   the FROZEN `build/palette.ts` makes `subtle` **fg-only** (no bg/pressed). The factory honours the
   frozen mapping (absent bg → no fill). A one-literal sketch/contract gap — a **doc reconciliation**
   (§11 text), not a code change.
