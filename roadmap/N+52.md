## What flipped (the chain, end to end)

| layer | before (CSS-SoT) | after (TS-SoT · inline) |
|---|---|---|
| the 6 type composites | `--nuri-type-md-size: var(--nuri-font-size-17)` etc. hand-authored | the `type` table in [`typography.ts`](../packages/spec/pipeline/typography.ts) (`md: { fontSize: 17, lineHeight: 1.29, letterSpacing: -0.02, weight: 'regular' }`) → emitted |
| size | `var(--nuri-font-size-17)` (a ref into the font primitive) | `1.0625rem` INLINE (px÷16 · the current spelling · rendered value identical) |
| weight | `var(--nuri-font-weight-regular)` (a ref) | `400` INLINE (the name resolved against the primitive) |
| lineHeight / tracking | `1.29` · `-0.02em` (already inline · no ref) | the same, re-emitted from the SoT (`xl` normalized `1.20`→`1.2`) |

**Why inline, not `{ref}`:** there are only six steps and the value of the table is seeing fontSize+lineHeight+letterSpacing+weight together in one place; the indirection into the font primitives does not pay. De-referencing also means the `--nuri-font-size-*` / `--nuri-font-weight-*` primitives go back to being a foundational hand-CSS layer (`shell.css`'s concern) — **the fake type↔shell coupling dissolves, it is not documented as a half-flip.**

`build/tokens.ts` (the RN reader · re-sourced onto the SoT) and every other `build/*` artifact are **byte-identical** — the resolved values don't change. `styles/typography.css` (the web reader · `[data-type-style]`) is untouched — it consumes the generated vars.

## The mechanism — in-place de-referenced rewrite (the dimension-css.js posture)

The emit is postcss-surgical (mirrors `dimension-css.js`): parse the CSS, set each `--nuri-type-*` declaration's value from the SoT, restringify; postcss preserves raws so all non-type content passes through verbatim. Unlike the dimension flip (a pure passthrough · byte-identical) this DE-REFERENCES size and weight to inline, so the `--nuri-type-*` block changes spelling (var→inline). The weight name (`regular`) resolves to its literal (`400`) against the `--nuri-font-weight-*` primitives read from the same file (`readFontWeights`) — the primitive stays the source of truth for the weight *value*. The flip is genuine — the build *drives* those values (a hand-edit is overwritten on the next `npm run build`), and the harness fails loudly if the CSS and the SoT disagree.

## The 30/57 finding (de-referencing orphaned two font-size primitives)

De-referencing `--nuri-type-*-size` to inline rem removed the only consumers of `--nuri-font-size-30` and `--nuri-font-size-57` — the `xl` / `3xl` steps. `shell.css` consumes `--nuri-font-size-{13,15,17,22}` but NOT 30/57 (verified). So those two ramp steps became orphans and would fail the "every primitive is consumed or reserved" guardrail. They are now **RESERVED** (P11 · the full-ramp pattern · like the unused neutral Radix steps), with a justification pointing at Phase 4·3, where the font-size ramp's membership is re-decided (they may then be removed or TS-authored). The operator's "the font primitives go back to being shell.css's stuff" is true for 13/15/17/22; 30/57 were type-only and are now reserved-orphans, not shell consumers.

## Judgment calls

- **The gate is computed-equivalent, not byte-identical** (the §77/N+45 posture). De-referencing necessarily changes the `--nuri-type-*` block's spelling (var→inline) and normalizes `xl`'s `1.20`→`1.2` (the SoT authors the number `1.2` · value-identical · flagged at the checkpoint, operator-accepted). The load-bearing byte-identity gate is `build/tokens.ts` + the RN snapshots (the resolved values), which hold.
- **The SoT regenerates all 4 leaves, not just size+weight.** Making the SoT the genuine single source for the whole block (a build-driven flip · the N+31 precedent) is why a SoT edit to lineHeight/tracking now updates the CSS too — no half-measure where the CSS line-height could silently diverge from the RN reader. The cost is the one cosmetic `1.20`→`1.2`.
- **Weight stays a semantic name in the SoT, a literal in the CSS.** `weight: 'regular'` reads best in the table; the emit resolves it to `400` against the primitive (which stays defined for `shell.css`). `--nuri-font-weight-semibold` (the emphasis override) stays referenced directly — emphasis unchanged.
- **30/57 reserved, not removed.** Removing them is a font-primitive decision (Phase 4·3); reserving with a clear justification is the minimal, honest holding pattern.
