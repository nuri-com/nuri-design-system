# Session N+6.0.4 · Pipeline sources vs build outputs physically separated · `pipeline/` source, `build/` generated-only

**Status**: closed (2026-05-28)
**Type**: bridge (structural cleanup · pipeline-side rework)

## Outcome

`build/` is now **output-only**. The 5 pipeline source files moved
out of `build/` into a sibling `pipeline/` tree: the orchestrator at
[`pipeline/tokens-parser.js`](../pipeline/tokens-parser.js), its
parser slices at
[`pipeline/parsers/{primitive,semantic,components}.js`](../pipeline/parsers),
and the test runner at
[`pipeline/tokens-parser.test.js`](../pipeline/tokens-parser.test.js).
The 4 generated files stay at the same paths under `build/`
([`build/tokens.json`](../build/tokens.json),
[`build/tokens.ts`](../build/tokens.ts),
[`build/components/button.ts`](../build/components/button.ts),
[`build/token-paths.ts`](../build/token-paths.ts)) so no downstream
consumer's import path moves — the migration pair at
[`docs/migration-tests/button-matrix/index.tsx`](../docs/migration-tests/button-matrix/index.tsx)
imports `'../../../build/tokens'`, `'../../../build/components/button'`,
and `'../../../build/token-paths'` unchanged.

The invariant is now structural: anything under `build/` is
generated by `pipeline/tokens-parser.js` and never hand-edited;
anything under `pipeline/` is hand-maintained source and never
machine-written. The "is this file source or output?" cognitive
tax that grew with each emit surface added (N+6.0.3 doubled the
file count in `build/`) is removed once.

[**Decision 35**](../decisionlog.md#35-pipeline-sources-vs-build-outputs-physically-separated--pipeline-source-build-generated-only--n604)
locks the separation and resolves the long-standing "`build/`
mixes pipeline sources and outputs" Open question that has been
sitting in [`roadmap/index.md`](./index.md) since N+5. Future
hardening (a pre-commit hook or CI check enforcing the invariant
mechanically; `.gitignore` for `build/*` once a stable output
platform locks) is documented out-of-scope inside decision 35;
this session ships only the directory layout itself.

[Decision 26](../decisionlog.md#26-ds-surfaces-vs-docs-chrome-are-physically-separated--n35)
gets a one-sentence forward-pointer to decision 35 (the
physical-separation-by-lifecycle precedent now extends to the
pipeline). Decisions 28 + 34 stay verbatim — their cited source
paths shift from `build/parsers/*` + `build/tokens-parser.js` to
`pipeline/parsers/*` + `pipeline/tokens-parser.js` as factual
drift correction, not amendment.

The pipeline behaviour is **zero-diff**. Output files post-session
are byte-identical to pre-session **except** for the source-path
strings in their generated-header comments
(`build/tokens-parser.js` → `pipeline/tokens-parser.js`).
[`build/tokens.json`](../build/tokens.json) is fully byte-identical
(no source-path string in its body). The three TS outputs each
shift their `Emitter` header line:
[`build/tokens.ts`](../build/tokens.ts) at lines 5 + 24 (the
`Emitter` line + the `pass --neutral=<scale> to …` line);
[`build/components/button.ts`](../build/components/button.ts) at
line 5 (the `Emitter` line);
[`build/token-paths.ts`](../build/token-paths.ts) at line 5 (the
`Emitter` line; the `Source · build/tokens.ts` line above it is
an output-to-output reference and stays unchanged). The
pre-session outputs were saved to `/tmp/nuri-pre-session-outputs/`
before the move, then diffed against the post-session re-emit —
the diff is confined to those four expected source-path lines.

`npm test` ships at **17/17**. `npm run build` emits the same
four files at the same output paths.
`npx tsc -p docs/migration-tests/button-matrix/tsconfig.json`
exits 0.

## Why N+6.0.4 not N+6.1

Different domain · different audit surface. [N+6.1](./index.md#whats-next--session-n61--semantic-sizing--spacing--button-refactor)
introduces NEW semantic spacing + sizing token families + their
foundation pages + the `button.css` refactor + emitter extension
to consume the new `SET_POLICY` slots — feature work in the
"new tokens land" mode. N+6.0.4 is pure structural cleanup in
the "physical separation" mode. Bundling means the audit can't
disambiguate "did the move break something" from "did the new
tokens land correctly".

Sequencing benefit: [N+6.1](./index.md#whats-next--session-n61--semantic-sizing--spacing--button-refactor)'s
agent inherits the post-move source layout. New parser code
lands in `pipeline/parsers/*`; new outputs land in `build/*`.
Without this session, N+6.1 perpetuates the mixed state and the
Open question stays open another cycle.

X.Y.Z numbering: N+6.0.4 is the fourth derivative of N+6.0's
primitive direct-pixel migration thread. [N+6.0.1](./N+6.0.1.md)
locked the CSS-side Format B convention;
[N+6.0.1.1](./N+6.0.1.1.md) propagated it to spec-authoring
skills; [N+6.0.2](./N+6.0.2.md) closed the docs-page surface;
[N+6.0.3](./N+6.0.3.md) reworked the emitter contract; N+6.0.4
separates source from output. Five derivatives, each one
structural, all converging on a clean pre-N+6.1 baseline.
