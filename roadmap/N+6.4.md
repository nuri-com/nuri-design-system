# Session N+6.4 · IconButton · Ghost variant · Button 3-size matrix · Behavioural-delta template

**Status**: closed (2026-05-29)
**Type**: main sequence (the first real Icon consumer · validates
the N+6.3 atom at the consumer level and unblocks the downstream
icon-bearing components — SegmentedControl / ListItem / TabBar)

## Outcome

Four cohesive deliverables land in one arc, each reinforcing the
others:

1. **IconButton** ([`lib/components/icon-button/`](../lib/components/icon-button/))
   ships as `<nuri-icon-button name variant accent label disabled>`
   — the **first real consumer of [Icon](../decisionlog.md#38-icon-component--phosphor-source--nuri-icon-name-nuri-facade--2-size--fill--registry-based-js-dispatch--n63)**,
   answering the N+6.3 "first consumer forces the question" deferral.
   A fixed 48×48px circle wrapping a single `md` `<nuri-icon>`,
   single-size-locked under
   [decision 40](../decisionlog.md#40-iconbutton-is-single-size-locked--md48px--n64).

2. **Ghost variant** joins `solid`/`soft` as a chrome-less tertiary
   on **both** Button and IconButton — a cross-component decision
   ([decision 39](../decisionlog.md#39-ghost-variant-joins-solidsoft-as-a-cross-component-chrome-less-tertiary--n64)):
   transparent until pressed, never bordered, never accent-tinted.

3. **Button three-size matrix** (`lg` · `md` · `sm`) with an
   **asymmetric** type/radius coupling and the default shifting from
   implicit-largest to explicit-`md`
   ([decision 41](../decisionlog.md#41-button-three-size-matrix--asymmetric-typeradius-coupling--default-shifts-to-md--n64)).

4. **Behavioural-delta** template section — a fifth component-page
   section keyed by friction code, retroactive to Button and forward
   to IconButton
   ([amendment 24.1](../decisionlog.md#241-amendment--n64--behavioural-delta-section)).

IconButton is the **n=2 confirmation point** for web↔RN prop parity
(RISKS R1): the second component (after Button) where identical
props meet per-component behavioural budgets, which is exactly why
the Behavioural-delta section lands this session rather than in the
abstract.

## API · operator-locked at session open

```
<nuri-icon-button
  name     (required)   icon registry key · kebab-case (→ <nuri-icon name>)
  variant  solid | soft | ghost     default "soft"
  accent   <accent key>             Tier-2 self-scope (mirrored to inner button)
  label    <string>                 overrides the auto-derived aria-label
  disabled boolean
>
                         NO size prop — locked to md=48px (decision 40)
```

`aria-label` is **auto-derived from `name`** (`gear` → "gear",
`arrows-down-up` → "arrows down up") unless `label` overrides it; the
inner `<nuri-icon>` is `aria-hidden` (`F-ARIA-LABEL-1`).

Button's matrix (decision 41), for reference:

| size | min-height | padding-x | font-size | radius |
|------|-----------|-----------|-----------|--------|
| `lg` | 60px (`size.xl`) | 24px (`space.xl`) | 17px (`type-md`) | 12px (`radius.md`) |
| `md` *(default)* | 48px (`size.lg`) | 18px (`space.lg`) | 17px (`type-md`) | 6px (`radius.sm`) |
| `sm` | 36px (`size.md`) | 12px (`space.md`) | 15px (`type-sm`) | 6px (`radius.sm`) |

Type breaks at the `md`/`sm` boundary; radius breaks at the
`lg`/`md` boundary — the asymmetry is the point.

## Decisions locked

- **[Decision 39](../decisionlog.md#39-ghost-variant-joins-solidsoft-as-a-cross-component-chrome-less-tertiary--n64) ·
  Ghost variant, cross-component.** `transparent` → `bg-subtle` on
  `:active`; fg `text-primary` (never accent); no border any state.
  Defined once per component (`--nuri-button-ghost-*` /
  `--nuri-icon-button-ghost-*`) with a word-for-word identical
  contract. Anti-scope: no accent variation, no border (an
  `outline` variant is a separate future Open question).

- **[Decision 40](../decisionlog.md#40-iconbutton-is-single-size-locked--md48px--n64) ·
  IconButton single-size-locked · md=48px.** No `size` prop. 48px =
  the iOS/Android comfortable touch target (`F-TOUCH-TARGET-1`).
  Deliberate asymmetry with Button's matrix — size count follows
  demonstrated density evidence, not symmetry. The inner glyph is
  locked to `<nuri-icon size="md">`. First real Icon consumer.

- **[Decision 41](../decisionlog.md#41-button-three-size-matrix--asymmetric-typeradius-coupling--default-shifts-to-md--n64) ·
  Button three-size matrix · asymmetric coupling · default → md.**
  Type tracks the primary/dense split (lg+md share `type-md`; sm
  drops to `type-sm`); radius tracks the hero/standard split (lg gets
  `radius.md`; md+sm share `radius.sm`). Default shifts to `md`
  explicitly — **no backward-compat shim, no autofix sweep** that
  freezes the old largest look.

- **[Amendment 24.1](../decisionlog.md#241-amendment--n64--behavioural-delta-section) ·
  Behavioural-delta section.** A fifth component-page section keyed
  by friction code (`F-PRESSED-1`/`F-FOCUS-1`/`F-DISABLED-1` +
  component-specific codes), stating web behaviour, RN behaviour, and
  the delta the migration agent must honour. Retroactive to Button,
  forward to IconButton; **not** backfilled onto Stack/Box/Icon
  (empty delta there).

## F-ICON-RN-1 · still OPEN (operator-deferred · debt documented)

The Icon RN renderer was **operator-deferred** this session. The
intent was for IconButton — the first real consumer — to force the
RN-side `react-native-svg` path-per-weight renderer. The operator
chose to keep N+6.4 web-spec-only and carry `F-ICON-RN-1` forward
rather than ship a partial RN renderer.

**No partial RN renderer shipped.** The migration test models
IconButton as a type-only interface + a `View` stub that explicitly
references `F-ICON-RN-1`; it does **not** silently fake a glyph. The
debt is surfaced in three places (RISKS.md F-ICON-RN-1, the
migration-test stub comment, and IconButton's Roadmap section) so it
cannot be lost. This is the one OPEN item leaving the session.

## Frictions surfaced

- **Inner `<nuri-icon>` upgraded name-less → 144× `[NuriIcon]
  unknown name "null"`.** First build of `icon-button.js` created
  the inner `<nuri-icon size="md">` and appended the subtree to the
  document *before* `#sync` set its `name`. When the deferred
  `icon.js` module later defined `<nuri-icon>`, the inner elements
  upgraded name-less and each warned. Final DOM was correct (the
  warning fired, then `#sync` set the real name), so it was a
  console-noise bug, not a render bug — caught only in browser
  verification, not by tests. Fixed by **seeding
  `icon.setAttribute('name', this.getAttribute('name') || '')`
  before the subtree enters the document**, so the first upgrade
  resolves a real registry key. Verified zero warnings on a clean
  load. Lesson: a wrapper that builds child custom elements must set
  their required attributes *before* DOM insertion, since deferred
  upgrade order is not under the wrapper's control.

- **Docs Tokens dictionary typed `--nuri-icon-button-size` as
  `unknown`.** `lib/docs/tokens.js`'s `TYPE_PREFIXES` had matchers
  for `-font-size$`, `-(min-|max-)?(height|width)$`, etc., but no
  bare `-size$` — IconButton's diameter token is the first bare
  `-size` component token. It fell through to `unknown` and logged a
  `parseSemantics` warn. Fixed by adding a `-size$` → `dimension`
  matcher *after* `-font-size$` (so font-size precedence is
  preserved; both map to dimension anyway). Verified the rendered
  dictionary row now shows `dimension`.

- **Generated export name was an invalid JS identifier.** The first
  pipeline run emitted `export const icon-button = {` (hyphen
  illegal in a JS identifier). Fixed with the `exportNameFor`
  kebab→camelCase helper → `export const iconButton`.

- **Test count drifted to 18 (violated "NO new tests").** An
  initial standalone `test('per-component emit · icon-button.ts…')`
  pushed the count to 18. Caught via `grep -c "^test("`; the
  IconButton assertions were merged **into** test 16 inside a nested
  block (shadowing the re-declared `decls`/`ctx`/`groups` consts).
  Back to 17/17.

## Why IconButton now (sequence position)

N+6.3 shipped Icon precisely to unblock icon-bearing components.
IconButton is the **smallest, most foundational** of those (one
glyph, one job), which makes it the right first consumer: it
validates the Icon atom composes inside an interactive control
*before* the more complex multi-icon components (SegmentedControl /
ListItem / TabBar) depend on that composition. Landing ghost and the
Button size matrix in the same arc is deliberate — ghost is a
cross-component variant that wants its second host (IconButton) to
prove the "defined once per component, identical contract" claim,
and the Behavioural-delta section wants its n=2 component to confirm
the template generalises past Button.
