## The emit — the inverse-spelling of `applyFields`

| | RN (the existing consumer) | web (this session) |
|---|---|---|
| reads | `STACK_FIELDS` / `BOX_FIELDS` ([resolve-map.ts](../packages/rn/factory/resolve-map.ts)) | the **same** table (cross-package · type-stripped · the spike shim) |
| emits | `applyFields` → `ViewStyle[prop] = value` ([resolve.ts](../packages/rn/factory/resolve.ts)) | `.nuri-<ns>[data-<kebab key>="<v>"] { <web prop>: <web value>; }` |
| spelling | RN-spelled props (`flexDirection`, `paddingHorizontal`, `width`) | the **web spelling layer** (logical props · per-target) |

The Field table carries `{ via, property-CONCEPT, value-SOURCE }`; the per-target EMIT supplies the property SPELLING — exactly the S1 neutrality choice, now exercised by a second consumer.

## The web spelling layer — the spike's payload (the concrete L3-flip TODO)

"One table → web CSS" works, but the Field table (designed RN-first) is **insufficient alone**. The web emit needs a per-target supplement — each gap is a [`cascade.md`](../docs/cascade.md)-named item, now made concrete:

1. **`LOGICAL_OVERRIDES`** — the RN-physical → web-logical prop remap is **broader than the doc's lone `paddingHorizontal→padding-inline` example**: sizing (`width→inline-size`, `height→block-size`, `minHeight→min-block-size`) AND every padding edge go logical (9 remaps). The rest is mechanical camelCase→kebab.
2. **value vocab** — `size`/`radius` **DERIVE** from the token scale (`Object.keys` of the scale · the SizeLeaf model · adding a token grows the CSS, no emitter edit); `space` is the **curated `SpaceLeaf` subset** (`xs…xl`, not the full 8-leaf scale — the cascade.md "SpaceLeaf hardcoded · a double declaration to remove"; today an erased TS type, so the spike restates it as `SPACE_LEAF`); `direction` is `literal` vocab (also erased).
3. **`EXPAND_WEB`** — the `expand` arm's web declarations: RN's `{flexGrow:1,flexShrink:0}` ≠ the hand CSS `flex: 1 0 auto`, and `grow-shrink` uses the LOGICAL `min-inline-size:0` (not RN's physical `minWidth`). Not mechanically derivable → per-target.

The OTHER arms need no supplement — `keyword` (the ALIGN/JUSTIFY map keys+values) and `flag` (on/off) ride the table itself. So the supplement is minimal, and every gap is a known flip TODO, not a surprise.

## Judgment calls

- **Table homing = in-place** (the sub-decision · operator-recommended). The table stays in `@nuri/rn`; the emitter reads it cross-package + type-strips it (node 20 can't `import` a `.ts` — the same constraint that drives the descriptor browser-ESM twins · here a `data:`-URL import of the stripped source, which has only `import type` deps so it is self-contained). This is the spike's TEMPORARY shim — cascade.md: "the axis SoT belongs in `@nuri/spec`"; the L3 flip relocates the table (the decision-68 `rn → spec` DAG) and the shim becomes a plain import.
- **typography deferred to L3.1b** (the sub-decision). typography is **not a Field-table namespace** — `resolve.ts` handles it bespoke as a type-STEP ref (`node.typeKey`, not a `ViewStyle` prop · it is absent from `STACK_FIELDS`/`BOX_FIELDS`). Forcing it into the generic table is the kitchen-sink the anti-goals warn against; the ship list named box + stack (the clearly-tabular two).
- **The shell is the emitter's, not the table's.** The element wrapper (`display:contents`), the `:not(:defined)` skeleton, the variant-agnostic base, and box's `data-center` auto-margin are non-field structural boilerplate — mirrored from the hand `<ns>.css` as per-namespace constants. They are not field mappings (the thing the table de-duplicates); at the L3 flip the hand CSS retires and the emitter is the sole source (the B1 discipline).
- **Order-insensitive structural compare** (Guard A) + **order-irrelevance proof** (Guard D) — the generated file emits in TABLE order, the hand file in its own grouping; the rule-order difference is cascade-irrelevant *for the field rules* because each dispatched property is owned by one data-attr (mutually-exclusive values within an attr). **Caveat: Guard D's soundness has a gap — see below.**

## L3c handoff / known limitations (carry-forward · LOG-only · do NOT fix in this spike · P11)

**Guard D soundness gap — shorthand / logical-longhand families.** `css-preview.test.js` Guard D proves "each dispatched property is owned by one `data-` attribute ⇒ field-rule order cannot matter" by comparing **property strings**. That treats `padding`, `padding-inline`, `padding-inline-start`, … as **disjoint** — but they **overlap at the computed-longhand level**: the `padding` shorthand and the logical longhands all resolve onto overlapping physical sides (both `padding` *and* `padding-inline-start` set `padding-left`). When **≥2 box padding attrs co-match one element** — a SUPPORTED case: [`box.css`](../packages/spec/lib/components/box/box.css) documents precedence **edge > axis > uniform** (`data-padding` + `data-padding-start` together) — the computed value is decided by **source order at equal specificity** (all dispatch rules are `0,2,0`). **Neither harness exercises co-occurrence** (every curated cell sets exactly one attr).

Parity holds **today only because** the generated `BOX_FIELDS` order *coincidentally* preserves the hand's uniform→axis→edge order (so the edge longhand wins by being emitted later). A future `BOX_FIELDS` reorder that breaks precedence would keep **Guards A + D green, undetected**.

This is **latent while the hand CSS is the oracle** (the reversible spike · Guard A would catch a divergence from hand). But **at L3c the hand oracle retires** and the node gate becomes the **sole structural guard** — so **close it before/at the flip**. Options (operator-surfaced):
- **(a)** add a **computed-style co-occurrence cell** to the browser harness (`data-padding` + `data-padding-start` on one node → assert `padding-left` = edge value, `padding-right` = uniform value);
- **(b)** **expand** the shorthand + logical props to their **physical longhands** before Guard D's disjointness check (so the collision is visible to the node gate);
- **(c)** assert the generated padding-family **rule order matches a canonical precedence order** (uniform → axis → edge).
