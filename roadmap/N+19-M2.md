## The four RN-toolchain integration decisions (the M2 crux)

`@nuri/spec` ships RAW `.ts` and now resolves UNDER `node_modules` via the workspace symlink, and the RN runtime (react/react-native) is version-split across the workspaces. Each broke a default; each fix is **factory/app-LOCAL** so `@nuri/spec`'s resolution and the root's type-only pins stay untouched (65.7's "let them coexist"):

1. **jest `transformIgnorePatterns`** — jest-expo excludes `node_modules` (RN allowlist); `@nuri/spec` was appended to the negative-lookahead so its raw `.ts` (the frozen contract the smoke imports) gets transformed. `roots` stays scoped to `factory/`.
2. **Single React + single React Native for jest** (`moduleNameMapper`) — the install nests the factory's `react@19.1.0` + `react-native@0.81.5` under the package while the root carries `@nuri/spec`'s **type-only** `react@19.2.6` + `react-native@0.80.3` (for the button-matrix migration tsc). Consequences: `react-test-renderer` (peer `^19.1.0`) hoists to the root and binds the root's 19.2.6 → `useContext` reads null; and jest-expo (hoisted) binds the root's RN 0.80.3 → its 0.81-shaped native mock fails (`__fbBatchedBridgeConfig is not set`). Fix: `moduleNameMapper` redirects every `react`/`react-native` specifier (incl. the ones inside react-test-renderer + the jest-expo setup) to the factory's own copies via `require.resolve`. A **global dedupe override was rejected** — the migration tsc REQUIRES the root's RN 0.80.3 (RN 0.81 dropped APIs the mirror uses, e.g. `SafeAreaView`). `modulePathIgnorePatterns` also drops the sibling `expo-demo` (a duplicate `react-native@0.81.5` that collides in the haste map).
3. **Metro monorepo resolution** (`metro.config.js`, NEW) — `watchFolders` = repo root + `nodeModulesPaths` = [app, root] (the symlinked `@nuri/*` live above the app); package-exports (on by default in Expo 54) resolves `@nuri/spec`'s subpaths; babel-preset-expo transforms the raw `.ts`. Plus a `resolveRequest` that redirects `react`/`react-dom` to the app's single copy — else the symlinked factory's nested `react@19.1.0` is a SECOND instance in the web bundle → the same hooks-dispatcher mismatch → blank `#root`. (Confirmed: the fix dropped the bundle from 276 → 259 modules.)
4. **TS `moduleResolution` + `@types`** — `expo/tsconfig.base` already sets `bundler` + `customConditions:["react-native"]` (so the plain-string exports targets resolve, `.ts` and all); no override needed. The monorepo's split/hoisted `@types` (root's stale `@types/react-native@0.72` + a nested/root `@types/react`) made tsc's automatic ancestor-`@types` inclusion miss `@types/jest`, so an explicit `types: ["jest","react","react-test-renderer"]` pins the wanted globals and excludes the stale ones (RN types arrive via the `react-native` package import, not `@types`).

**Plus dependency reconciliation**: `typescript` standardized on the root's `^6.0.3` across the new workspaces (dropped expodsdemo's 5.9 · Expo's "expected ~5.9" advisory is benign — babel does the transform; tsc 6 only type-checks). `expo` is pinned `^54.0.0` in the factory even though it isn't imported at runtime — babel-preset-expo's `peerOptional expo@"*"` otherwise floats it to the latest major (56), whose winter runtime crashes jest-expo's RN transform.
