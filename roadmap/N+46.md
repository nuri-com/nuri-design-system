## Why this session

The typography axis page on `main` was still the A4b page: a `## Wrapper` table dumping the web CSS of the
`nuri-typography` `muted`/`align` element. But [§76](../decisionlog.md) reclassified the axis as `size`, and
[§77](../decisionlog.md) (N+45) de-fused it into orthogonal `size`+`emphasis` with a clean Web↔RN realization
— so the page documented the wrong thing (a web-only wrapper) as "the typography axis". This session re-points
it to the REAL axis and, doing so, **spikes + locks the grammar** every axis page will share. The grammar is
the deliverable: the typography page is the proof, the other four axes are the fan-out.

## The grammar — LOCKED (operator-confirmed at the rendered checkpoint)

`| Input | Web | RN | Value |` — the two explicit sub-choices locked:

- **Web | RN as two columns** (not a single "Realization" column) — generalizes box/stack's
  `| Input | CSS | RN | Value |` by renaming **`CSS`→`Web`**; the per-target spelling stays explicit. The
  fan-out applies that rename to the other four axis pages.
- **The composite REFERENCED** (not inlined) — `Value` = `type` scale (size) / semibold (emphasis); the
  resolved per-step composite is the Foundations (A4c) scale page, not duplicated here.

The page now states the orthogonality + both-targets realization in the lead, renders **Size as 6 agnostic
rows** and **Emphasis as the single boolean row** (6×1, not the old 12 fused `mdEm` keys), and demotes the
wrapper to a web-only section whose missing RN column is itself the honest signal. This cures the "CSS guide"
critique: the agnostic axis is up front, the web-CSS dump is the labeled tail.

## Three authorial calls (operator-approved)
