Default

API

A content-pivot compound (decision 64 · amendment 46.4). <nuri-topbar> is the shell; <nuri-topbar-content> is the named layout pivot that wraps the title / centre content. Everything you drop before the pivot is leading, everything after it is trailing — plain positional siblings, no wrapper element. The pivot's flex: 1 absorbs the slack and pushes any trailing to the row end by construction, so an empty side simply contributes nothing (no phantom gap). The structural center boolean centres the content; the optional inset / inset-start / inset-end override the edge padding (default lg · decision 46.1). Edge padding is never auto-resolved from child type — per-shape defaults live in recipes.

<nuri-topbar> · shell

Prop Type Default Description
center boolean false Centres the content within the pivot — the Cancel / Edit / Save action bar or a segmented switch. The pivot still absorbs the slack (flex: 1) but now centres its own content; with symmetric side controls (e.g. equal flanking icon buttons) the content sits optically centred in the bar. Reflected as data-center on the host.
inset · inset-start · inset-end "xs" | "sm" | "lg" lg Overrides the edge padding. The default is lg on both edges; inset is the symmetric shorthand and inset-start / inset-end set one edge and win over it. Reflected as data-inset-start / data-inset-end; the value pick lives in CSS (decision 46.1). Never auto-resolved from child type — per-shape defaults (a control edge that hugs at sm, a tight segmented gutter at xs) move to recipes. Asymmetric insets on a center bar shift the optical centre — keep them symmetric there.

<nuri-topbar-content> · content pivot

Prop Type Default Description
none — — No props — the named layout pivot (flex: 1) that wraps the centre content. Its position is the API: siblings before it are leading, siblings after it are trailing. A bare-text title reuses Typography's lg-em utility (the single text-style owner · decision 64 · 53); a non-text centre (a segmented control) passes through untyped. Omit a side entirely for an empty edge — no phantom gap.

Anatomy & parts

Topbar is a content-pivot shell. The <nuri-topbar-content> pivot (flex: 1) wraps the centre content; leading / trailing are plain positional siblings around it — anything before the pivot is leading, anything after it is trailing. No reparenting, no Shadow DOM, no <slot>: the row stays in document order and CSS flexes it (decision 64 · amendment 46.4). The pivot's flex: 1 pushes trailing to the row end by construction.

Live demos

The structural range: a left-aligned title with a double trailing affordance, a filled close button (the IconButton fill passthrough · decision 40.1), a back-chevron leading row, a centred <nuri-tabs> switch, and the center action bar. The pivot absorbs the slack while as many positional icon buttons as needed stack after it.

Theming · chrome surface

The shell paints --nuri-bg-canvas with --nuri-text-primary — both chrome (theme-only) tokens. Toggling theme repaints the whole bar with no extra rules; the accent surfaces only through the composed controls (e.g. a solid Button in the centre bar), never the shell itself.

Token mapping

CSS property → DTCG → CSS var → reference. Topbar has no @layer tokens block per decision 46 — every value dereferences a semantic token directly in @layer rules through the host element selector and data-* attribute dispatch (e.g. nuri-topbar[data-inset-start="sm"] { --_inset-start: var(--nuri-space-sm); }). — means a CSS literal, not a token.

  • planned · evidence-gated
    Icon RN renderer (F-ICON-RN-1)

    Topbar composes IconButton rather than <nuri-icon> directly, so it does NOT add a new direct Icon consumer — the RN glyph-rendering debt stays a single funnel. The renderer (react-native-svg SvgXml over a typed build/icons.ts emit) lands at the first direct <nuri-icon> consumer outside IconButton, or the first real RN build. See RISKS.
