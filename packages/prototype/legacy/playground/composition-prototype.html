Composition-model prototype · B1.5

Validates decision 65.3 (docs/composition-model.md §6–9): a recipe is 100 % a composition of the five curated primitive namespaces — stack · box · typography · palette · interactive — with zero raw style. Each recipe below is rebuilt purely from the web primitives (nuri-stack / nuri-box / nuri-typography / nuri-icon), placed to reproduce its anatomy, and shown beside the live component for parity. Where a primitive lacks a prop the gap is reproduced inline and flagged LOGGED — those are exactly the extensions B2 will ship.

composed rebuilt from primitive namespaces
LOGGED an inline gap = a missing primitive prop (see the report)

Composition notes. (1) On the web each primitive is a display:contents custom-element wrapper around one painting node, so two primitives cannot share an element and a wrapper cannot be inline-augmented. To validate the model (namespaces merged on one node — what the RN factory emits as a single <View style>) the composed painting nodes apply the primitives' own class + data-* vocabulary directly (e.g. class="nuri-box nuri-stack"); the namespaces are disjoint (§6) so the rule-sets co-exist with no collision. Text/glyph leaves use the public <nuri-typography> / <nuri-icon> elements. (2) Box carries no colour — under §6 disjointness all colour belongs to palette, which has no web primitive yet, so every palette role (bg / fg / pressed) is applied inline as a LOGGED gap (never via box.background, a decision-42 prop that would collide with palette · report §4.3). Foreground flows by scope where the role fg = the ambient text-primary (F-BOX-FG-1). (3) Recipe roots are plain flex nodes (no inline-flex) — content-width follows from the flex parent, because RN is flex-only with no inline/block (report §4.5).
